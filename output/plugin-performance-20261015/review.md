# 插件性能与代码精简记录

本轮围绕插件发现、入口加载、项目和任务上下文、桌面执行准备审查。未提交、未替换已安装的正式客户端；验收使用此工作树构建的 Electron 客户端与用户资料的隔离副本。

## 已修复

- **读取互相阻塞**：独立读取最多并发 4 个；写入保持独占，排队写入阻挡后来的读取插队。逻辑取消不释放仍在执行的物理请求；已取消的读取只占自身槽位，不阻塞其余 3 个读槽。旧页面迟到结果不能覆盖当前页面。
- **无关模块导致重复加载**：生成、查询、历史查询 journal 按当前 family 过滤通知；任务收据仅在合法且关联当前模块时刷新。保留旧包未决记录的恢复路径。
- **可选缓存拖住在线加载**：缓存读取超过 200ms 退回原认证网络请求；迟到缓存不导入，取消不发起新的在线请求。
- **缓存淘汰大额复制**：用时间索引及 key cursor 淘汰，避免每次写入读取整批入口字节。v1 缓存迁移保留数据，修复事务取消挂起和迟到连接泄漏。
- **无插件时启动失败**：私有 v3 配置在没有执行 owner 时保留元数据和插件发现，执行类服务不获得权限。复制 DTO 不能冒充私有文件签发身份。
- **多模型准备失败**：同一插件允许多个模型执行目标；逐项验证身份、配置和工作区，采用 Native 验证的默认目标。
- **旧批准累积后的准备失败**：合法配置新增映射从约 63KB 增至约 67KB，超过旧聚合 64KiB 限额。Native 聚合改为已有审批文件的 128KiB 上限；公开 UI 仍为 64KiB，子配置、深度、节点及权限限制保留，不删除历史批准。
- **启用其他插件后读不到旧任务**：按私有 Native 执行发布中已准备的插件选择原读取服务。未准备的插件沿用原有 paid 历史授权；同插件旧任务继续由 Native 检查，拒绝后不切换服务。读取适配器使用不可变自身方法描述符，兼容应用层捕获方式及原服务私有字段。
- **切换项目后显示另一项目的旧恢复记录**：50.2.0 的 account/module 级恢复上下文可触发 `applyRecovery`，覆盖明确项目页的需求、概念和任务，并取消正在读取的新项目；页面仍处于 ready，原 effect 不再纠正。50.2.1 在恢复前绑定页面项目，对四条恢复路径按项目投影，拒绝迟到的跨项目 adoption，显示其他项目待处理记录的返回入口。普通首页保留原恢复；全局 journal、原请求正文、幂等键及写互锁不清除。未确认的原项目保存仍阻止切换后的写入；终态后新生成使用新的 Thread。
