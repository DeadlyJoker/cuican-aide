## 两个入口使用同一条制作流程

插件首页输入想法后，形成同一项目的制作方案，再交给原 Agent 会话执行；用户也可以从原对话创建或继续项目。两处使用同一个项目、采用版本、执行记录和任务状态，不增加第二套聊天存储或工作空间绑定。

项目内的每个页面都支持查看成果、手动编辑、让 Agent 处理选中范围、查看候选并采用。Agent 处理的成果能在页面继续编辑，页面采用的结果能被 Agent 读取。切换入口或关闭页面不重新提交生成。

页面操作统一遵守以下行为：

1. 输入故事或导入内容，确认项目与制作范围。仅讨论想法时不启动媒体生成。
2. 大纲、剧本、角色和美术成果保存为可检查版本；用户采用后成为下游来源。
3. 按已采用的剧本和资产制作结构化分镜。单集和局部制作使用同样的依赖检查。
4. 为选中对象准备画面描述与参考素材，选择实际可用的工作流，再执行生成。
5. 结果进入对应对象的候选区；查看、比较、采用、锁定和再次生成分别是明确动作。
6. 上游被重新采用时标出受影响对象；既有任务和旧成果仍保留原输入。未知结果先查原任务，不自动再提交。

Krea2 T01/T04 保留在同一个短剧插件，分别用于文本概念探索和角色三视图。T10 使用已采用角色参考，D18 使用场景和两个有顺序的角色参考；D18 的画面探索不能代替结构化分镜。视频、配音、剪辑按既有八阶段方案继续扩展，入口是否可执行取决于真实能力，不由参考截图上的按钮推定。

## 当前实现与改造顺序

已有真实项目、文字成果、角色/美术资产、原会话关联及媒体输入控制器。当前持久化页面将这些能力集中在少量阶段中；公开参考则按项目首页和具体创作对象组织。因此需要调整插件内部的页面组织，并复用已有控制器，不创建第二份预览数据作为正式项目源。

实施按以下顺序进行，每一步都保留原任务与版本行为：

1. 登录后核对真实工作台：记录首页提交、项目切换、剧本/角色/美术/分镜编辑、生成与历史等关键路径；暂不触发付费生成。
2. 先对齐插件首页和项目内部框架：创意输入、最近项目、项目导航、阶段目录和可变宽度；接入真实项目读取与创建。
3. 将现有剧本、角色、美术、候选和历史操作放入对应页面；沿用已有保存、采用、锁定与恢复控制器。
4. 完成原 Agent 对话与页面操作接力，随后接通分镜和媒体任务。页面显示真实阶段状态，未接通能力给出具体缺失条件。
5. 对照参考逐项验收外观、导航、编辑、生成和恢复，同时回归 CrewON 原页面、侧栏、账户、设置及会话绑定。

验收分别记录“外观对齐”“交互已验证”“业务已接通”。静态截图只能证明外观；可点按钮不能证明生成已成功；隔离页面验收不能代替用户桌面 App 的正式验证。

当前待补证据是登录后的 ReelBench 页面与操作。未取得这些证据前，不承诺完整复刻所有交互，也不按猜测批量替换现有页面。
