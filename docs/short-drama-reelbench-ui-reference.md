## CrewON 页面与交互决定

外层左右栏、账户、设置、工作空间和会话继续使用原实现。插件只占用协议允许的内容区域；不接管宿主导航，不覆盖全局 CSS，不复制 ReelBench 的黑金视觉、账户或购买流程。积分仍后置。

主题框架的可变范围限定如下：宿主下发明暗模式及字体、颜色、间距等主题变量；插件只在自己的 owner 上应用，并响应宿主更新。插件可定义内容区内的项目导航、编辑区和业务弹窗，响应式断点以模块实际宽度为准。弹窗遮罩、滚动与层级也必须限制在模块内，不调用全局顶层模态 API，不对宿主 body 设置 inert，不向全局 CSS 或主题状态写入。卸载只清理插件拥有的 DOM、监听及状态。这里是当前受信任模块的实现约束，不把 CSS 作用域宣称为不可信代码的安全沙箱。

插件内部采用两层组织：

1. **项目首页**：创意输入、创建/导入入口、最近项目、搜索与归档。继续项目直接回到其真实成果和状态。
2. **项目工作区**：项目标题与返回入口、成果导航、可收起的分集/对象目录、主编辑区。按需显示详情和任务记录；窄窗口收起插件目录，避免多层固定侧栏挤压主内容。宿主侧栏打开时，插件按剩余宽度布局，不使用遮罩覆盖主区。

项目成果导航为概览/需求、大纲、剧本、角色、美术、分镜、视频/声音、成片、素材与变更；实际页面按可用能力逐步开放。页面不是硬性执行顺序：例如更换角色图可以回到角色页，并明确看到受影响的分镜。

每个成果页保持相同操作语义：查看当前采用内容 → 手动编辑或交给 Agent → 保存候选/输入 → 在明确范围内执行 → 预览结果 → 采用/锁定 → 查看历史。提交前说明目标对象、数量和执行终点；发生未知回执时查询原任务，不因刷新或切页重新提交。

Agent 入口沿用原对话页，带入当前项目、选中对象及采用版本。例如用户可以要求“根据这版剧本准备第二集镜头描述，先不要生成图片”，随后在分镜页手动调整，再让原 Agent 继续。页面与对话使用同一项目、版本和 Run，不另建聊天存储或第二套工作空间绑定。

Krea2 T01/T04/T10 和 FLUX2 D18 留在同一个短剧插件中，按概念探索、角色设定/多视图、参考驱动的画面生成进行选择。D18 画面生成不能代替结构化分镜；视频、配音和剪辑各自有真实工作流、依赖及产物。

## 实施与验收顺序

1. 登录后页面核对已完成上述范围；据此修正页面组织和交互清单，视觉固定为 CrewON 风格。
2. 先完成插件项目首页和项目内部导航，复用真实项目读取、创建、搜索与归档。不得把模拟项目数据作为正式源。
3. 将已有剧本、角色、美术、候选与历史控制器放入对应页面，保持保存、采用、锁定和恢复行为。
4. 完成原 Agent 与手动页面接力的桌面验收，并逐项连接结构化分镜、画面/视频/声音任务和成片。
5. 回归宿主左右栏、账户/设置、工作空间绑定与桌面一致性；分别验收窄宽布局、操作路径、真实任务与恢复。

当前仍存在原桌面包接线与后续制作阶段的实施缺口。UI 可点、包测试通过或参考站存在某个按钮，都不能替代 CrewON 的真实执行验收。参考站创建方案、批量生成、失败重试、撤销与跨项目导入的最终结果尚未测试；本次没有为观察而改动用户在参考站的项目。
