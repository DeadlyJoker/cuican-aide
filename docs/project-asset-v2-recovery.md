# V2 素材操作恢复

2026-10-07，接续 [V2 插件调用](./project-asset-v2-plugin-ui.md)。此增量把六类素材写入接入持久化恢复：内容保存、内容改选、锁定、概念参考保存、参考改选、已保存生成图采用。恢复用于插件手动操作，不创建 Run、任务或积分消费。正式 Control / Worker 注册、插件页面客户端和已安装 App 升级仍待完成。

## 插件协议

插件的 `main.content` 模块同时声明 `crewon.project-assets` API 2 和 `crewon.project-asset-recovery` API 2。只有已配置恢复服务的实际 V2 owner 才能处理恢复请求；描述符声明恢复但宿主未配置时拒绝操作。旧 V1 恢复日志、动作和回执保持原协议。

| 动作                                             | 输入                              | 行为                                                               |
| ------------------------------------------------ | --------------------------------- | ------------------------------------------------------------------ |
| `crewon.project-asset-recovery.v2.getPending`    | `{}`                              | 查找当前用户、安装版本及模块范围内未确认的操作，项目来自保存的请求 |
| `crewon.project-asset-recovery.v2.cancelPending` | `intentId`、`expectedRevision: 1` | 取消尚未提交的操作；若写入已经提交则返回原成功结果                 |
| `crewon.project-asset-recovery.v2.acknowledge`   | `intentId`、`expectedRevision: 2` | 确认已成功或已取消的操作，释放该范围的待确认位置                   |

首次写入前保存完整的 V2 请求及原幂等键，状态为 `pending`、版本 1。业务结果提交后状态为 `accepted`、版本 2；取消后为 `cancelled`、版本 2。确认后保留版本 3 的记录，同键重试不会再新建操作。界面重试应直接重发保存的请求；修改参数时必须使用新幂等键，不能把旧请求变成另一项操作。

确认结果只包含资产标识、资产与内容或参考版本、结果摘要。公开响应不返回安装凭据、供应商配置、文件路径或运行时权限。写请求沿用素材协议的 24 KiB 上限；恢复响应上限 60 KiB。

## 数据一致性

`project_asset_versioned_intents` 使用原父 Store 的 SQLite 连接或 PostgreSQL 连接池。迁移明确要求原素材、媒体结果与采用回执表已可用。它与 V1 日志分别存储，不迁移或改写旧日志。

业务结果、原不可变回执和恢复状态在同一事务中提交。恢复状态的成功证明来自实际回执，不能由页面的“成功”消息决定。所有原素材写入、采用写入及回执重放都会检查已记录的 V2 操作；已经取消的请求无法绕开 UI 再写入。

锁顺序为原业务回执、恢复范围、原项目。取消和写入争用同一回执锁：先提交的操作决定结果。取消成功后迟到的写入被拒绝；业务先提交时取消返回成功回执，不改变已完成的素材。确认不会删除记录，也不使取消失效。

原始调用注册、安装与包摘要、模块、授权及生命周期仍需有效。恢复读取先找到记录，再对记录所属项目检查读取权限；取消和确认检查该项目的写权限，不能借当前页面所在项目的权限读取其他项目。提交后的权限变化不改变已提交结果，读取仍检查返回前权限。

## 验证和边界

证据位于 `output/extensions/checks/asset-v2-recovery-20261007/`。集成测试使用真实 `PluginUiApplicationService`、原安装处理器产生的 T10 历史、原素材及结果存储、SQLite 和 PostgreSQL。UI 包读取器、策略决定、供应商响应及故障注入是具名测试端口，没有实际调用 ComfyUI。

覆盖六类写入的恢复与确认、回复丢失、重新挂载及重新打开 Store 连接、待处理请求阻止第二个写入、取消后的永久拒绝、取消与在途写入竞争、事务回滚、返回前撤权和提交后撤权。另有公开协议边界、V1/V2 宿主可用性及原恢复日志的兼容回归。

最终验证：集成测试 34 项、兼容回归 51 项全部通过，两轮有重叠，合计 73 个不同用例，无失败或跳过。Contracts、Application、Store、PluginHost、ControlAPI、RuntimeWorker 类型检查，以及边界、格式和 7 个桌面运行时构建通过。SDK、原冻结插件包和用户 App 校验保持原样；临时 PostgreSQL 已停止并删除。

此增量不提供原生 App 重启的完整验收，也不等同于页面可用。下一步把这些 owner 注册到正式 Control / Worker，再升级短剧插件内的客户端、采用入口与恢复提示；随后接通同项目 Agent 执行、混合工作流和分镜、视频、音频、导出。宿主主题、侧栏、账户设置及会话绑定不属于插件可变范围。
