## 保存、准备与执行的关系

```mermaid
flowchart LR
  A[Agent准备内容或用户编辑] --> B[确认并保存输入修订]
  B --> C[逐角色准备原素材]
  C --> D[当前字节与来源核验]
  D --> E[原Run事务准入：宿主内部已验证]
  E --> F[实际生成与结果候选：待接线]
  F --> G[采用或锁定：待接线]
```

保存输入只固定已确认的提示词、工作流、业务项、真实采用参考和目标配置，不读取图片、不上传、不创建Run。用户可以先保存再执行；Agent也须先保存可回看的输入，不能在媒体提交时临时改写提示词或替换角色。

输入保存的是原准备请求关联，不是假造的上传回执。准备服务取得真实加密源归档、SQL准备journal及当前供应商字节观察后，才返回各角色的实际准备状态。准备成功仍不授予生成Run；下一项在原Turn/Run事务中固定实际准备记录和输入摘要并再次核验。

| 工作流                                 | 业务用途                   | 固定的输入                                          | 当前输出边界                              |
| -------------------------------------- | -------------------------- | --------------------------------------------------- | ----------------------------------------- |
| T10 `krea2-reference-four-view`        | 已选角色参考派生           | 同项目真实角色、确切设定/参考修订、确认提示词       | 节点129的图像；不把一张四视图算成四份文件 |
| D18 `flux2-three-reference-storyboard` | 有剧本来源的双人物画面探索 | 采用剧本及分集、真实场景、顺序角色一/二、确认提示词 | 节点17的图像；不代替结构化镜头表或视频    |

D18必须有两个不同的角色档案和不同的原生成结果位置。素材准备后再核对实际图片字节：不同结果身份却返回同一角色图片，也不能报告可用。没有第二角色时保留业务成果，等待合适工作流；不能复制文件凑输入。场景与角色的叙事和视觉质量仍由用户或后续真实多模态评价判断，结构检查不冒充视觉一致性评审。

## 版本和准备身份

新增独立 `crewon.project-media-input.v1` 记录。固定实际调用者/项目、宿主生成的媒体输入ID、递增输入修订、业务项、需求摘要、可选剧本摘要、工作流摘要、确认提示词、有序参考来源摘要、原Run/operation/结果位置、来源配置摘要、目标完整安装/选择/配置和保存时间。完整记录不超过96KiB，提示词不超过8192 UTF-8字节。

业务项和工作流ID在一个输入ID内保持，内容修订追加保存，head采用CAS增加一个版本。请求键绑定完整调用者和项目；同键改变请求报冲突，同键重试返回原修订。两个实际父存储并发保存原请求时只产生一个输入、修订和回执。旧修订可读，不被新提示词覆盖。

每项源冻结键由真实调用者、业务查询和完整来源快照确定；目标准备键另包含真实目标快照。只改变提示词不会重新上传相同素材，明确保存另一输入但引用同一原来源/目标也可复用原准备。更换源修订、实际安装选择或目标配置产生不同准备身份；任何已有发送状态都不回到首次上传。

当前服务从实际调用者捕获身份；未来两个入口须通过共同的宿主持久执行意图协调同一原身份、输入和任务。不能让UI/Agent任意填actor，也不能用两端各自的随机任务键冒充跨入口去重。当前材料去重不代替尚待实现的媒体生成意图和阶段计划。

## 当前使用与历史读取

历史读取只核验当前读取权限及项目归属，可以查看已保存输入。新保存和当前使用另核验项目active、当前需求、采用剧本及其原需求/大纲来源、分集身份、每项当前采用参考与设定，以及真实目标安装/选择/配置。

参考来源沿原解析器核验原生成Run、准入、资金记录、operation、实际结果验证器和历史配置，不能用调用者自报摘要代替。工作流审查清单固定实际包、版本、publisher、manifest、implementation与图摘要；不从baseUrl推测包支持某项能力。生产清单须由后续实际宿主部署组合提供，本项检查使用具名清单夹具。

查询当前使用同时给出明确输入修订和预期最新head。执行过程中head改变，逐素材准备在下一项前停止。重新选择新修订可复用已完成的原材料；明确选择旧修订也必须提交当前head并通过当前来源核验，不能默默执行过期快照。已受理Run后续仍属于原输入，不得改绑到新修订，这是下一项的Run关联契约。

上游或安装变化不删除历史输入及已发出准备记录；当前使用失败。资格、来源和版本错误不能降格为供应商网络错误或被当作准备成功。

## 双库保存与独立资格

独立显式迁移建立输入head、不可变修订、回执及schema marker四张表。原资产schema是前置条件；构造不迁移，缺表/缺marker/DDL或触发器改变时拒绝，不修复部分历史。修订、回执及marker禁止SQL更新/删除，head只允许身份保持且revision加一，外键固定真实修订及项目归属。

`ProjectMediaInputApplicationService`组合原来源/目标服务；`SqliteProjectMediaInputStore`与`PostgresProjectMediaInputStore`由真实父资产存储创建，沿同一个数据库核验全部依赖。新增 `projectMediaInput:read/write/qualify` 独立用途，无默认allow。写回执重放也核对写权限，历史读取不授予当前使用。

事务只做SQL、外部资格检查及同步active fence，不借父pool执行第二次来源查询，不执行文件、DNS或HTTP。SQLite的异步检查在BEGIN之前完成，锁内同步；Postgres使用同一个父连接和原项目锁，maxPoolSize=1可运行。各SQL步骤前后检查owner/profile活动，写入中资格失效回滚全部新增行。JSON通过描述符捕获，拒绝getter、Proxy、额外路径、非JSON及过量内容，不运行toJSON或调用者回调。

原文字计划、资产操作、准备和网络授权均不能替代媒体输入资格；媒体输入资格也不能替代源读取/冻结、目标读取、上传、查询或Run准入。

## 多素材准备与恢复

`ProjectMediaMaterialPreparer`只绑定真实双库类和原 `ProjectMaterialPreparer` 方法，忽略实例覆盖，拒绝假DTO和Proxy依赖。按保存的角色顺序逐项调用[真实准备服务](./project-material-preparer-protocol.md)，每项前后及返回前重核当前输入/来源/目标。整个操作有90秒上限，各原材料操作继续使用原30秒上限。

prepare允许沿原材料的独立权限准备尚未发送项；observe仅查询已有原项，缺少准备记录时拒绝，不冻结源、不创建记录或上传。三项可以分别处于verified、pending或rejected；某项响应丢失时保留原unknown，其他独立项可准备，整体不能报告verified。再次prepare也沿原journal，已发送项不重传。

关闭并重新打开原父存储和加密归档后，observe查询每项原目标路径，核对PNG、实际字节、尺寸和当前资格。过去verified只是历史；当前目标变化或不可读不能沿旧观察执行。下一项生成Run必须再观察所有材料，并在自身准入事务内核验真实输入、准备身份和当前依赖。
