# 架构精简推进记录

目标：按 ChatGPT 对比审计的顺序减少重复装配和执行编排，保留身份、安全、持久化及恢复语义。基础分支为 `codex/runtime-concurrency-result-streaming`；并行调度基础提交为 `24d7a6343100bc98f53594765fec923a4bf53271`。

## 推进顺序与验收

1. 收窄包入口、分离生产与测试依赖图、退出失效的前端旧连接装配。保持旧包入口兼容；类型检查、既有行为测试、演示模式与组件视觉覆盖均需保留。
2. 建立有界且一致的会话读取模型，集中前端流式收敛。验证刷新、切换、断线恢复、最终结果及重复事件。
3. 将 Team / Workflow 推进权迁至持久化后端。验证关闭窗口继续运行、多窗口不重复推进、重启不重放副作用以及旧记录兼容。
4. 合并重复生命周期管理，按资源范围隔离本地工具。保持权限撤销、取消传播、任务等待及共享目录写入约束。
5. 引入自主子 Agent：父子关系、等待释放执行槽、取消传播、上下文和权限边界，以及数量、深度、时间和 token 预算。

各阶段以行为验证为完成依据；当前仅完成第一阶段的一部分，不代表整套改造完成。

## 下一批的明确边界

`App.tsx` 以 `enabled: false` 调用旧 `useAppConnectionEffects`；该 Hook 除了连接装配还承担演示数据本地化和演示 Inspector 同步。应先保留并分离演示职责，再移除旧连接装配，不能直接删掉整个 Hook。保留终端、宿主工具和权限链路，按真实调用者逐个核实旧协调器。
