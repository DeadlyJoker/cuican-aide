# 架构精简推进记录

目标：按 ChatGPT 对比审计的顺序减少重复装配和执行编排，保留身份、安全、持久化及恢复语义。基础分支为 `codex/runtime-concurrency-result-streaming`；并行调度基础提交为 `24d7a6343100bc98f53594765fec923a4bf53271`。

## 推进顺序与验收

1. 收窄包入口、分离生产与测试依赖图、退出失效的前端旧连接装配。保持旧包入口兼容；类型检查、既有行为测试、演示模式与组件视觉覆盖均需保留。
2. 建立有界且一致的会话读取模型，集中前端流式收敛。验证刷新、切换、断线恢复、最终结果及重复事件。
3. 将 Team / Workflow 推进权迁至持久化后端。验证关闭窗口继续运行、多窗口不重复推进、重启不重放副作用以及旧记录兼容。
4. 合并重复生命周期管理，按资源范围隔离本地工具。保持权限撤销、取消传播、任务等待及共享目录写入约束。
5. 引入自主子 Agent：父子关系、等待释放执行槽、取消传播、上下文和权限边界，以及数量、深度、时间和 token 预算。

各阶段以行为验证为完成依据；当前仅完成第一阶段的一部分，不代表整套改造完成。

## 下一批的明确边界

`App.tsx` 以 `enabled: false` 调用旧 `useAppConnectionEffects`；该 Hook 除了连接装配还承担演示数据本地化和演示 Inspector 同步。应先保留并分离演示职责，再移除旧连接装配，不能直接删掉整个 Hook。保留终端、宿主工具和权限链路，按真实调用者逐个核实旧协调器。

## 第二批：退出生产 App 的旧连接装配

将 `useAppConnectionEffects` 的演示本地化和 Inspector 同步迁至独立的 `useAppDemoEffects`，移除禁用的客户端连接、重连及其唯一消费者通知协调器的 App 装配。旧客户端、事件协调器及相关能力模块保留，尚未将所有旧链路声明为可删除。Shell 从原本挂载后被改为断开的状态，调整为直接以断开状态初始化；Control 的连接权威不变。

## 第三批：生产类型图与跨应用沙箱依赖

两个服务新增 `typecheck:production` 与 `tsconfig.production.json`，从检查根目录排除测试、辅助和 fixture。原 `typecheck`、默认 tsconfig 和 CI 命令保持完整覆盖；新入口用于局部生产改动的快速验证，不替代最终完整检查。Test Contracts 增加解析真实 TypeScript 依赖图的检查：生产代码不能通过传递导入重新带入测试或其他应用，同时验证完整检查仍保留测试根。

初次解析发现 Worker 确实生产依赖 Control 的 PIM 沙箱实现。将实现逐字节迁入已有 Device Dispatch 包，通过显式 `pim-sandbox-client` 子入口共享；Control 保留旧路径兼容重导出，Worker 生产与对应测试改用公开子入口。实现、错误类、串行队列和网络协议不变。准确更新包依赖与单文件架构许可，没有开放渲染端能力。

改造前完整类型图：Control 2420 个仓库源码文件，含 424 个测试相关文件及 294 个其他应用文件；Worker 2497 个，含 467 个测试相关文件及 307 个其他应用文件。新增生产图检查实际验证两者没有测试相关文件和其他应用依赖。Control 生产图含 1554 个仓库源码文件，Worker 为 1666 个（包含各自所需的共享实现）。这些统计排除 node_modules，与 TypeScript 全部 Files 指标的口径不同。

本次生产类型检查分别耗时 27.51 秒与 26.74 秒（同时运行时样本），不据此推断相对完整检查的性能比例。沙箱及新类型图测试通过；PIM 有一项平台相关清理测试按既有条件跳过，不能视为通过。

同时运行架构扫描发现 5 类基础失败：未登记的 plugin-tools 包、部分宿主能力边未登记及开发代理文件位于 Renderer 源目录。已用 HEAD `650c8391d` 的独立源代码副本重跑，复现相同 5 类失败；两边扫描提取的 45 条导入违规完全一致，本批没有新增违规。保持失败断言，没有通过扩大整个包的权限来使检查变绿；这些历史边界欠账仍需独立处理。
