另一个独立问题是终态处理等待完整会话回读：正式正文、工具历史、计划及额外快照串联在结束路径上。回读超时后再进入同步重试，页面继续显示执行中。可信执行终态、正式消息同步和可选详情恢复原先没有明确分开。

## 修复边界

- 发送处理先创建有界本地用户消息，再等待网络；正式确认后去重替换。提交失败保留明确失败状态和草稿恢复，不伪造 Run 或正式消息标识。
- 新会话返回时先绑定本地提交，再发布会话选择，避免已切换到新会话而本地消息仍属于草稿的空窗。临时消息由实际 Transcript 的可见 Run row 认领，不能因为全局 Thread 缓存已有 user item 就提前清除；正式消息完成渲染后才确认移除。
- 仅有正式消息标识或空正文仍不能接替本地消息，纯图片输入也需要有可见内容。团队进度通过本地 submission ID 与同一次提交交接，避免准备阶段显示两个用户气泡；该标识不进入 HTTP、模型请求或持久化。
- 供应商文字缓冲保留原字节阈值并增加 50 毫秒刷新窗口；UI 每 32 毫秒显示整批已收到文本，去掉固定逐字播放造成的人工延迟。
- Control SSE 在写入背压时等待 `drain`，关闭或取消后释放监听器，保留身份校验及事件顺序。
- 资源目录读取由当前账号和组件生命周期持有。相同账号仅共享进行中的读取，最后一个订阅者离开会真正取消；账号换代立即取消并拒绝旧结果。完成后不保留目录缓存。
- 目录的 2 个物理读取槽、单项 10 秒和整组 45 秒期限用于保护连接预算；取消、请求去重和所有权修复才是消除重复挂起请求的关键，不通过限制会话并行掩盖问题。
- 可信 Run 终态立即更新对应轮次并释放实时 reader；正式消息同步独立恢复，只重试读取、不重启模型执行。正式正文通过 Thread 身份、版本及输出标识校验；工具和计划详情不再阻塞正文。
- 正式消息尚未同步时，编辑重放保持关闭；允许继续发送，但已收到的上一轮回复必须按 Run 保留。晚到结果只更新对应旧轮次，不能覆盖后继运行。
- 模型 HTTP 在正式终态通过身份、正文和用量校验后，先检查同一次读取中已经收到的尾帧，再结束读取；仍拒绝终态后的违规帧。未收到终态、无效终态和完整文字不能冒充成功。正常 EOF 保留连接，未关闭的尾流主动取消；底层取消 Promise 不完成或拒绝也不能阻塞已验证的结束事件。

可信终态后的 HTTP 生命周期缺陷用保持连接开放的真实本地 HTTP 和 Kernel 集成确定复现：旧实现已经产生 completed，却随后因尾流 idle 超时重试模型。新实现证明仅发起一次模型请求。这是另一个独立本地缺陷；本轮真实外部缺终态的请求没有触发它，不能用这项修复宣称网关问题已解决。`httpTiming.streamEndMs` 的字段及持久化形状保持兼容，其含义是客户端拥有的读取结束，包括正常 EOF 或可信终态后的主动关闭，不再必然表示远端 EOF。

发现并修正两个确定的客户端缺陷：

- 账号恢复的 5 秒计时器在请求尚未失败时就发布 `unavailable=true`。已删除该误判；正在等待的请求显示恢复中，真实错误或原有 10 秒请求截止后才显示自动重连。仍保留实际取消、单一实体请求所有权、账号换代隔离及未验证期间的访问门禁。
