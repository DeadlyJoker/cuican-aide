# 桌面账号恢复

用户要求保留原登录态，不能因网络问题自动进入未登录状态。

正式桌面 0.1.50 冷启动后出现「账号服务暂时不可用」，随后进入本机管理。现场账号配置接口返回 200，但耗时约 6.6 秒，超过前端启动等待的 5 秒。原实现丢弃了超过等待时间才返回的账号校验结果；刷新凭据时任意 HTTP 错误还会清空凭据。

修复保留启动等待上限，但接收原账号稍后完成的有效校验；重试、切换账号和退出会撤销旧请求的界面消费者。已有账号恢复期间不自动进入本机管理；确实失效的凭据仍撤销并回到登录页。429 和 5xx 保留凭据供原鉴权接口重试，不授予离线账号权限，不使用缓存身份替代服务端校验。所有主题 CSS 和 Native Main 保持不变。

0.1.50 已部署混合 v1/v2 大纲只读修复。原小说项目读取与最新第 6 版大纲读取返回 200，但旧会话关联仍返回 403 `project_conversation_authority_changed`。必须通过原插件更新关联保留工作空间与历史，不能绕过权限或直接改数据库。

检查涵盖慢请求、旧请求晚返回、账号切换、凭据临时刷新失败与真实失效。源码相关 83 项、干净打包工作树相关 89 项检查通过；UI/Native lint、边界和仓库格式检查通过。

正式 `/Applications/CrewON.app` 已更新至 0.1.51，签名校验通过。实际冷启动自动恢复原 `admin / 管理员` 账号，原会话、工作空间与所选模型保留，没有输入密码、退出账号或改写凭据。四份主题 CSS 与原 Native Main 字节一致。实际桌面截图、签名及完整数据库备份位于打包工作树 `output/extensions/desktop51-delivery/`；恢复截图为 `account-restored.png`。原 0.1.50 保留作回退；原未知 Comfy 请求未再次提交。短剧会话关联问题继续单独处理。
