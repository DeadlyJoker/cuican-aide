# 短剧共享资产与 Agent 资产阶段协议

日期：2026-10-06。Short19 增量提供角色、场景、道具的设定版本及图片参考版本。仍交付一个 `crewon.short-drama` 包；原工作空间、账户、导航和全局样式不变。完整制作流程见[协同设计](./short-drama-agent-workflow-design.md)，验收范围见[实施进度](./incremental-extension-progress.md)。

## 共享成果

资产有稳定 ID、类型和 head 修订；设定候选与图片参考有各自不可变修订和选用指针。保存候选不自动选用，锁定挡住选用替换，仍允许探索新候选。Agent 和手动页读写同一个资产服务。

设定保存名称、文字设定、画面描述，以及实际需求修订和可选确切剧本来源。正文 JSON 最多8 KiB，名称最多160个 Unicode scalar，画面描述最多2,000 UTF-8字节。需求或已选剧本改变、剧本对大纲的依赖过期，都显示实际来源过期；不能用最新来源冒充旧候选的来源。

参考候选仅提交同项目概念图 ID 和选用修订。服务器解析真实选择、原 Run、operation、冻结配置和经过验证的图像结果；客户端不能提交这些字段充当证明。摘要是元数据摘要，不是图片字节摘要；缺少实际图像验证器时不能保存图片参考。

## 独立服务

以下为独立可选服务，不扩张 SDK0.1.0 或原四阶段协议。声明服务不构成授权，Main/Production 必须批准实际安装包、模块来源和真实当前调用者。

| 服务                              | 用途                           | 调用范围                                              |
| --------------------------------- | ------------------------------ | ----------------------------------------------------- |
| `crewon.project-assets@1`         | 六项读取、五项保存/选择/锁定   | 实际模块 invocation 与项目 PDP                        |
| `crewon.project-asset-recovery@1` | 读取未核对记录、确认核对       | 主体、配置档、完整安装、模块及原项目 PDP              |
| `crewon.project-asset-stages@1`   | 启动独立资产阶段               | 实际项目会话、Thread、安装、执行 Agent 和 package pin |
| `crewon.project-asset-context@1`  | 读取冻结资产范围               | 原 Worker 的真实 Run/claim 和独立准入 marker          |
| `crewon.project-asset-tools@1`    | 分页元数据、分段正文、保存候选 | 同一真实阶段资格及当前项目 PDP                        |

模块 UI 输入24 KiB、响应整份60 KiB，列表最多16项。Node 整份 `resultJson` wrapper 最多8,192字节，列表最多4条元数据，正文按有界 Unicode 分段读取。公开协议与 codec 固定 SHA，随独立包发布，不导入宿主私有源码。

## 原 Agent 对话

原 Composer 增加资产阶段及角色/场景/道具选择，仅当服务器确认实际绑定具备独立执行能力时开放。可仅依据需求执行，也可指定已选分集剧本；界面和服务器核验确切来源。普通聊天及原讨论/需求/大纲/剧本四阶段保持原协议。

`GET /api/v1/threads/:threadId/project-asset-stage` 只检查当前可提交性，不创建 Run 或准备供应商任务。`POST` 同路径携带项目、实际 Thread/绑定修订、资产种类、需求修订、可选剧本、原用户消息和幂等键，沿原 Turn/Run、资金准入、outbox、Worker 和 Node 执行。独立 marker 为 `crewon.project-asset-stage-run-admission.v1`，不伪装成旧 discussion。

候选与工具回执持久提交；丢回复后以原 Run、原键和冻结来源恢复。已受理任务的 UI 恢复只读取和采用原记录，不重复 POST。曾出现未知结果后，后来的来源/绑定409不能证明旧请求未提交，不能自动换键新建任务。关闭 owner 时等待实际在途工作退出。

新资产报价使用独立具名端口，旧报价不获得新能力。沿原本地执行准入或实际配置的新报价执行；两者均不存在则拒绝，不虚构价格。积分产品按用户要求后置。

## 手动工作台与冷恢复

“角色与场景”页在原插件内容区增加三类表单、候选列表、明确选用/锁定、剧本来源和图片参考。进入新阶段才读取数据，旧项目浏览不额外调用新服务。服务缺失只挡新能力，基础聊天和原阶段保持原行为。

五项手动写入先保存独立 journal 原请求，同一次业务 COMMIT 保存确认回执。连接恢复只读；重开后可在项目列表检查原记录，打开实际原项目核对正文、来源与历史回执。pending 仅以原正文/版本/键重试；accepted/refused 核对后确认。未读到记录或来源恢复失败时挡住新写入，不用最新 head 推断成功。ACK 有原键墓碑，丢回复可安全读取和重放。

19.0.1 在当前实例实际写请求收到成功回执后，自动核对原 action/body/key 与 accepted 记录，读回确切不可变内容/参考，再 ACK 并确认槽已为空。正常保存、采用、锁定不再要求额外点击恢复按钮；自动核对回执不等于采用创作候选。读回或核对失败保留“已保存”，阻止新的写入，不重复业务请求。冷启动、重新连接和打开旧记录继续只读。补丁仅改插件 UI 与测试，SDK、宿主服务及公开请求形状不变；原19.0.0包保留，旧安装身份的记录不能由新包身份借用。

## 20.0.1 的设定到概念输入探索

资产页可明确将**已选用**设定的画面描述复制到新的概念输入草稿。来源仍有效且与当前已保存需求一致时开放；存在未保存的设定、概念草稿或原在途操作时不覆盖或替换。锁定只保护已选版本，不阻止建立新的概念候选。当前打开的未采用候选不会替代已选设定作为复制内容。

复制仅改变本次插件挂载的草稿，不写资产、不创建Run、不提交供应商请求，也不自动选用结果。检查、编辑及明确保存后，沿原概念元数据和T01/T04生成/选图链执行，再由用户在资产页明确保存为参考候选及选用。概念页的“起始描述复制自”仅为本地输入校对标记，不是持久资产来源或执行授权；重新读取原概念修订不会编造这个标记。正式参考仍由原服务校验真实结果与确切资产设定版本。

这一补丁不新增服务、HTTP或持久字段，冻结SDK、业务工具和原工作流请求形状不变。Agent资产阶段产出的已采用设定可沿同一页面继续手动探索；资产到媒体的自动计划、T10/D18真实素材准备仍继续实施。

## 后续媒体边界

已有 T01/T04 概念生图与选图链仍可复用。资产管理不代表人物一致性生成已接通；T10 需要真实参考输入文件，D18 需要场景和两个角色参考，二者还需批准的素材准备及按工作流读取结果。裸 ComfyUI `output` 文件名或 `/view` 地址不足以构成图像输入；官方核心 `LoadImage` 的 `[output]` 注解为同服务复用提供待验证路径，D18 自定义节点尚未验证该行为。[官方路径解析](https://github.com/Comfy-Org/ComfyUI/blob/v0.38.0/folder_paths.py#L229-L243) 实际接入需核验来源、目标配置、节点支持及素材可读性；需要上传时保存真实字节与传输回执。分镜、视频、声音、时间线与合成分别扩展成果和阶段协议，真实工作流验收后开放。
