# 项目参考素材的源字节冻结

2026-10-06。继续[八阶段与双入口方案](./short-drama-stage-execution-contract.md)，已把真实采用参考的受控读取接到宿主内不可变源素材归档。此次不新增插件包、页面、HTTP入口、SDK服务或任务工具；供应商目标副本、媒体输入、Run准入和Agent媒体计划继续实施。

## 源素材如何固定

`ProjectReferenceMaterialFreezer` 只接调用者、项目/资产/预期head/采用设定/参考修订和原请求键。捕获原来源服务及真实读取类的方法，不接受调用者的URL、文件名、摘要、字节或实例覆盖方法作为来源。

先沿原项目服务核验当前权限与采用来源，再核对独立的源归档资格，读取原请求的归档。已有完整归档时验证原请求、来源、字节摘要和PNG规格，复核当前来源与资格后复用原记录；不再次读取可能变化的供应商文件。

首次归档沿[受控读取](./project-reference-material-read-protocol.md)取得真实PNG字节和观察记录。读取类原观察方法保持原返回形状，新增的字节方法仅供宿主内部使用；GET前后的网络资格及来源检查保持。归档服务再核验来源、归档资格、字节摘要、尺寸，把确切字节交给可信存储，写后重新读回核对，最后复核当前项目/来源与资格才返回。

`readFrozenReference` 是宿主内部的只读字节取得方法。它沿当前项目和归档资格检查，只读原请求的完整归档；缺失、损坏、过期或权限撤销时失败，不修复文件、不重新GET或创建任务。其字节不会直接公开给插件或Agent。

源归档资格为独立 `ProjectReferenceMaterialFreezeAuthorizationPort`，没有默认allow或生产测试策略。资源绑定确切archiveId、materialId、业务查询、参考/结果/原Run绑定、包及配置摘要。宿主组合层仍须为实际安装、配置、批准及该用途提供可信授权；已有项目阅读、旧JSON网络批准或纯DTO均不能授予它。

## 原键、并发与恢复

归档身份由版本、archiveId、实际调用者、项目及原请求键确定。请求摘要还冻结完整查询。相同项目原键改资产或修订时冲突，不能变成另一个隐式请求；不同tenant、space、principal、actor、project或archive分开。

手动与Agent后续应从同一个持久业务意图取得原请求及调用者身份，而不是各自随机生成键。当前源归档已支持两个入口提交同一原请求时共享不可变记录；这不代替尚待接入的全阶段计划/执行意图协调。首次并发可能各做一次只读GET，独占发布只有一个赢家；来源与字节相同则复用赢家的原观察时间，字节不同则冲突，绝不覆盖赢家。

来源或权限在归档写完后改变时，服务拒绝返回当前成果。已写入的加密源归档保留原版本，不能假装发生了跨数据库/文件系统原子回滚。后续读取继续重核实际来源和资格。下游执行仍须在自身事务内做当前版本与准入检查；一次归档成功不承诺未来任意时刻都可执行。

## 不可变加密存储

`@crewon/artifacts` 增加独立 `FilesystemProjectMaterialArchive` 与新格式 `crewon.project-reference-frozen-material.v1`。原键记录为 `CRWPMI01`，源字节文件为 `CRWPMV01`。旧Artifact v0仍只接受text/plain工具输出，原Run保留规则、数据库和blob格式均不扩张。源归档使用单独配置的宿主目录与密钥，不冒充工具输出，不伪造tool call身份。

先持久保存规范化、最多32KiB的原键记录，固定首次来源与字节摘要；源字节文件再保存同一记录及最多16MiB的确切字节。记录保留真实采用/设定/原结果/原Run/包/配置身份、原output引用、PNG摘要/尺寸和观察时间。AES-256-GCM对全部内容认证加密，附加认证数据绑定archiveId、materialId、keyId及记录/字节类型。目录为0700，文件为0600；只使用散列身份命名，不把业务ID或供应商路径拼成磁盘路径。关闭实例清除其密钥副本。

两个文件分别写入唯一、独占的临时文件，完整写与fsync后用排他的hard link发布，再删除本次临时文件并fsync目录。已有最终文件永不覆盖；返回前解密读回、核对原键记录、字节文件的同一记录与实际字节。原键记录存在而字节缺失时，读取及归档服务的重试明确失败，不重新GET可变供应商内容。可信宿主存储的显式恢复只能用与原记录完全一致的确切字节补齐；不能换摘要、换来源或修复损坏的已有文件。进程在发布前退出可能留下本命名空间的加密临时文件，不把它当作完整回执；后续维护须按归属处理，不能扫描清理用户其他目录。

读取在分配buffer前核验文件类型、长度、权限和inode；拒绝symlink、非普通文件、过大密文、替换目录及GCM认证失败。存储层是机械字节归档，不授予项目权限，也不解释PNG；归档服务通过原读取及受限PNG检查核验内容。归档记录是内部数据，不能由自报字段获得执行资格。

这是宿主源字节归档，还没有配置到正式App。宿主后续组合须绑定确切存储位置、密钥来源、容量与项目保留/引用规则。多实例需要共同可读、受控的归档后端；同名archiveId不能证明另一实例具有字节。若整个归档及原键记录一并丢失，存储本身无法区分历史请求和首次请求，后续持久媒体意图必须将已登记但归档丢失识别为不可用，不能建立新素材冒充恢复。不能沿旧工具输出的到期删除规则删掉仍被项目采用的参考素材。

已用用户提供的SSH只读核验当前 `/root/ComfyUI/server.py`，文件SHA-256为 `2040372807f2e97f705c3ff6c8613b1517322eea1dcbf666de2320203df69931`。当前 `image_upload` 支持input/temp/output类型；普通 `/upload/image` 分支按收到的文件字节保存，非overwrite情形可能比较原文件或选择带编号的文件名。该源码与[上游实现](https://github.com/comfyanonymous/ComfyUI/blob/master/server.py)提供下一步适配依据，不是目标上传或生成验收。本轮没有上传、改服务文件或启动复制任务。

目标适配须固定原传输归属路径，拒绝服务端擅自换名/换路径，将源与目标分别保存。发送后GET核验目标字节、尺寸及可读性；即使上传回执返回asset hash，也不能代替宿主计算的字节摘要。T10/D18目前同包适配器只接明确output引用；不得为方便而偷偷把input文件标成output，或复用原可变文件名当作新目标。

只有目标准备完成，才保存工作流媒体输入、关联原执行意图并沿原Run准入执行。服务器分别核验每个真实角色/场景参考及顺序。D18仍要求一个场景和两个有顺序的角色；不能补一个虚构角色满足槽位。后续Agent资产/分镜步骤与手动执行沿同一媒体输入和任务命令，既有文字计划和原前端保持。
