# AI 短剧 Agent 大纲读取连接

2026-10-09。读取修复已安装到正式桌面 0.1.45、短剧 45.0.0；实际外部模型读取仍未通过。

## 实际问题

在正式桌面更新原会话关联后，历史和工作空间保留，原主页对话框可继续执行。用户验收项目的大纲已经手动保存为候选 v6，但实际模型调用 `foundation_proposals` 和 `foundation_proposal`，将改编方案 v1 当作大纲版本；第二次明确要求读取大纲时，模型以 Foundation 工具范围为由拒绝。两次实际执行均完成，但均未核实 v6，没有写入或生成。

源码检查确认：原讨论阶段已经允许 `outline_read`、`content_read` 和 `text_history`。Foundation 范围独立约束方案工具，并不取代原项目讨论的只读范围。另一个问题是原 Node 文本读取器只识别旧大纲内容格式，不能读取新结构化修订。

## 本次修复

- Worker 使用原数据库和项目授权服务，给原 Node 大纲读取、分页内容及历史工具接入混合 v1/v2 的只读服务。
- 保留原工具名、请求和响应外壳，每页最多 1024 个 Unicode 字符，仍经过原 8 KiB 响应检查；完整结构化内容的内部规范序列化与原摘要一致。
- 历史旧大纲、剧本及旧宿主缺少新读取服务的行为保持兼容。已采用版本的 Foundation 来源变化时明确拒绝把它描述为当前版本，历史正文仍可读取。
- 旧大纲保存工具不能用 v1 内容替换当前结构化大纲；已提交旧请求仍能沿原收据重放。结构化 Agent 写入没有因此获得权限。
- 修正插件指引与固定版本的 shuohao 方法指导：从大纲头取得实际候选版本，再分页读取正文；改编方案与大纲分别读取，不能混淆版本。
