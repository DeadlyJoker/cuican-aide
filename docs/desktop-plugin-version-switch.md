# 桌面插件版本切换

2026-10-07，实际 Short26 → Short31 升级验收发现：设置页直接以启用状态切换版本，而原生业务执行要求先停用并配置已选择的候选版本。拒绝被误报成普通版本冲突，刷新不能解决。

修复保留原生执行的准备与权限校验：桌面管理版本页面先明确停用旧版，再由用户选择新版。新版保持停用，完成原有业务配置后才能启用。Web 和旧版桌面桥接沿用原有版本选择行为。

Main 允许选择尚未配置的停用版本，但先后读取原有业务激活状态，确认它没有启用；提交后再次核对实际选择。旧版本运行时不会用自己的配置激活新摘要。未停用、并发激活、选择变化和运行时撤销均不返回成功。原请求的幂等键和未知结果恢复机制保持原样。

设置页新增流程快照及行为验证，Main 测试使用真实类型客户端、原生运行时所有权和具名 HTTP 响应夹具。此类测试不代替打包 App 的实际升级验收。

原始复现与正常退出备份：`output/extensions/checks/native-short31-20261007/`。正式安装的 App、用户数据和冻结插件包未修改。候选版后续实际验收仍需完成升级配置、项目读取、重启恢复及真实 ComfyUI 闭环。
