# 业务插件的可变范围

日期：2026-10-03。范围：CrewON 增量业务扩展，依据用户“插件只是多一个功能模块，保持现有能力与页面”“样式完全一致”及“插件一定可插拔，能够独立开发并安装”的要求。本页约束模块的可变范围；独立包协议、SDK、安装和可信 Node/UI 加载基础见[可安装插件实施方案](./installable-plugin-protocol-plan.md)，完整生产插件产品尚未交付。

结论：业务插件提供自己的能力、数据和内容页面，宿主决定它能注册在哪里、使用哪些服务。插件可以拥有完整的短剧、采购或专业分析操作界面；安装业务插件不会替换 CrewON 首页、侧栏、主题、现有团队或普通聊天。

## 对照 DeepSeek Harness

DSH 将工具、模型、会话和 Agent 循环也作为可替换插件，通过 profile 与 bundle 组合应用。它的“全部可替换”是完整应用的组合能力。CrewON 当前采用保留已有架构的增量接入，不把业务插件安装解释为选择另一个平台实现。[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)。

可直接借鉴的是显式服务依赖、类型化事件和可清理的注册生命周期。业务依赖某项能力时调用契约，不导入另一个插件的内部实现；停用时移除其入口、订阅和新操作资格。[Cordis 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-primer.md)。

DSH Web Client 由宿主持有权威状态，客户端模型维护投影，UI 通过 Slots 组合；展示组件只接收所需数据和回调。自定义设置页也从页面所有者取得表单状态和带预期版本的修改方法。[Web Client 分层](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-client.md)、[设置页贡献点](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-settings-card.md)。

下表是针对 CrewON 的设计决定，不是 DSH 所有插件的限制，也不要求复制 Cordis 或新增运行时。

## 谁可以改变什么

| 范围     | 业务插件可定义                                                | 宿主持有的边界                                             |
| -------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| 入口     | 模块名称、图标、简介、注册的业务动作                          | 导航位置、排序、可见性和激活条件；保留原入口               |
| 页面     | 自己内容区域内的列表、表单、编辑器、阶段和结果视图            | 全局 shell、首页、侧栏、账号、主题、公共组件和交互规范     |
| 业务     | 输入输出契约、专业规则、提示词、Agent/团队模板、Workflow 模板 | 已发布执行版本、授权、审批、模型路由、工具执行及有界上下文 |
| 外部能力 | 提交/查询适配器、服务参数、可核验的状态转换                   | 凭据引用、调用门禁、幂等回执、任务关联、恢复和撤销         |
| 数据     | 本业务的项目、修订、素材关系、版本化增量迁移                  | 租户/空间/本人隔离、存储端口、事务协调、审计和历史保留     |
| 积分     | 具名服务端价格规则提供者和报价版本，须符合已确定产品规则      | 当前付款人、独立积分池、余额、冻结/结算/释放及任务原子准入 |
| 其他插件 | 声明依赖，调用其公开能力                                      | 不直接修改其数据库、配置、内部组件或覆盖其注册             |

模块内的布局可以根据业务不同而变化。例如分镜编辑器不必长得像聊天记录；字体、配色、按钮、圆角、焦点、弹窗和响应式仍采用宿主规范。模块样式限定在自己的根节点下，不修改 `body`、`:root`、全局 shell 或其他模块，不创建覆盖整个 App 的固定定位容器。

宿主样式以插件改造前发布基线 `776484c57` 为准：窗口框架、品牌、原导航、左右栏按钮、字体和颜色保持原实现。左栏展开占布局宽度，主内容动态缩放、不被覆盖；右侧工作台继续原开关与宽度调整。新增模块入口及模块内部内容是贡献范围，不授权重排或换肤原宿主。可信 UI 必须遵守这项协作约束；若要技术上隔离任意第三方 DOM/CSS，需要独立实现隔离模式，不能将当前可信加载器称为沙箱。

企业可配置服务绑定、术语、知识源和业务模板。换全局品牌、主题或平台提供者属于应用组合配置，需要单独的明确架构范围，不能夹带在一个短剧或采购业务插件中。现有团队业务继续保留；企业用户、组织和租户身份不属于 Agent 团队插件。

## 注册与调用方式

现有实现仍随宿主构建，这是调用试点，不是最终安装方式。按用户最新要求，后续实现必须从独立插件包加载，在公开贡献点注册；开发新插件不修改宿主业务源码、不重编译宿主。前端只收到当前可见的模块声明及当前账号可读的业务投影；宿主解析入口、维护路由和激活状态，提供必要的窄动作回调。组件不取得整个 App 状态、原始凭据、数据库连接或任意 HTTP/执行权限。

现在的业务 Manifest 已有严格版本契约。增加包描述、UI 贡献或新的调用能力时，需要明确其兼容格式及行为测试；当前预览用可信组件组合验证边界，不把一个 React 插槽当作完成的插件加载、授权或隔离系统。可信自研模块和隔离的第三方界面分别加载，不能把任意远程代码直接装进宿主 React 树。

用户表单与 Agent 通过同一业务用例提交，使用原 Run/Tool/SSE 路径。插件描述业务方法和准备参数，宿主解析当前身份、检查权限及额度、锁定版本并保存回执。新增项目生成关联仍必须进入原任务与积分冻结事务；不能先生成再补关联，也不能由页面自算付款人或直接修改余额。

插件停用后撤下新业务入口、移除其订阅，阻止新的提交；当前任务按已有撤销和恢复契约处理。历史输入、结果和积分记录保留，缺少专用界面时由宿主提供基础记录展示。停用、卸载与删除用户数据是不同操作。

## 短剧首版的具体边界

- 现有 CrewON 首页、任务、助理、智能体、日程、团队、知识库及账号入口保留。
- 新增“AI 短剧”模块入口，点击后只切换主内容区；项目选择、需求修订、概念图版本及生成服务设置都在该模块内。
- 短剧模块复用宿主样式与控件，取消此前预览自造的侧栏、工作空间切换、账号区和橄榄色主题。
- Krea2 的真实生成由现有 ComfyUI 适配器处理。尚未接通的视频、配音与成片不提供可收费的提交操作。
- 所有用户可使用短剧能力，数据及消耗按本人独立积分隔离；价格、计费单位和失败结算仍以用户确定的规则为准。

项目与不可变需求/描述修订的内部基础，以及 SQLite/PostgreSQL 存储，不等于正式项目页面已经接通。当前交互预览仍明确使用演示数据，不保存真实项目、不发起生成、不实际扣费。

## 验收边界

新插件接入时，原导航与首页仍可用，已有团队和聊天路径保持行为；样式只影响模块自己的内容区域。启用后出现模块入口，退出模块回到原页面；停用后移除其贡献，其他模块不受影响。输入、版本、权限、积分、重连和恢复仍由原宿主用例核验。新模块使用真实业务路径后，再补端到端保存、生成、查询及选用验收，不能用页面演示替代。
