# AI 短剧插件：本地内容与共享 Agent

## 目标与边界

复用 CrewON 的 Agent、会话、模型、权限、工具调度和恢复机制。插件提供短剧阶段提示、少量业务工具和项目页面，不创建第二套任务引擎或聊天目录。

采用 `ai-short-drama-production` 的制作协议：brief、script、bible、shots、assets、generation、qc、release。阶段是依赖提示，不是必须逐次审批的固定流水线；在已有授权内连续推进，返修只处理受影响的产物。生成完成、质量验收和用户采用分别记录。

## 数据归属

- 项目工作空间中的文件是内容的唯一权威来源。需求、剧本、设定、分镜、提示词、审阅意见以 Markdown/JSON 保存，媒体保留原始文件。
- 数据库保存任务运行状态、外部生成 ID、幂等提交信息、文件相对路径与摘要索引。索引可从文件重建，不再承担正文版本库。
- 每份文本内容保留不可变 revision 文件；读取最新版本从 revision 文件序列确定。无需跨 SQLite 与文件系统维护一个“当前正文”事务。
- 修改要求 expectedRevision；并发编辑返回冲突，不能覆盖另一方内容。相同内容的重试复用当前版本。写入中断留下的临时文件不算有效版本。
- 既有 SQL 正文保持只读迁移源。迁移须逐项目导出、核对摘要、切换存储模式；未切换项目继续使用旧入口。禁止静默双写或自动删除历史。

## 工具与交互

Agent 使用宿主现有工作空间授权。项目工具只需要列目录、限量读取、保存修订、打开页面与提交/查询生成；不为每种资产再建一套 CRUD 服务。文件路径由受信项目根目录和相对路径组合，不接受任意绝对路径。

阶段提示每次只注入当前阶段、必要约束、产物路径及版本，内容按需读取。不能把整项目正文塞入系统提示。用户材料属于数据，不提升为指令。

右侧项目页面提供概要、正文/资产、生成与审阅视图，直接读取相同文件。保存复用同一版本冲突逻辑。Agent 打开页面只导航到项目与文档，不代表生成、采用或发布。文件提交成功后通知页面刷新；刷新失败保留文件与未同步提示，不能回滚已保存内容。

会话继续使用工作空间目录；插件可以显示项目内会话过滤结果，但不得重新实现卡片式聊天系统。打开文档不切换当前会话或清空输入草稿。窄窗口页面以可收起面板呈现，保留主输入框的可读宽度。

## 开发顺序与验收

1. 本地不可变文本修订存储：真实文件读写、重启读取、幂等重试、并发冲突、路径隔离和中断文件处理。
2. 接入受信工作空间宿主，再贯通 Agent 工具与页面同读同写；没有授权的项目不能创建存储。
3. 逐项目迁移旧 SQL 内容，校验内容摘要；切换后 SQL 正文不可再写。
4. 对接既有页面导航/刷新，验证 Agent 保存后页面变化、页面修改后 Agent 读到新版本。
5. 保留外部生成提交幂等与未知结果恢复，验证断线只查询原任务，不重复扣费或生成。

本轮接通不可变文本修订、Native 授权、Agent 读写工具及右侧“本地文件”页。旧项目页面继续保留既有数据和操作，逐项目正文迁移与媒体资产文件化仍需后续实施。

## 接入进展

Native 根据当前会话的持久项目绑定校验安装包、项目、工作空间及读写权限，再取得原目录。Agent 工具复用既有 Thread 工作空间路由。UI 请求只含会话、项目、安装包身份与文档 ID，每次访问重新检查授权。文件监视器只在完整修订落盘后通知页面，干净视图自动刷新，有草稿时保留草稿并报告版本变化。

同一父目录中的项目文件按租户、空间与项目身份生成稳定分区，保存在 `projects/<scope>/documents/`。Control 通过已授权会话返回分区身份，Worker 从持久阶段任务记录核对同一身份，渲染器不能指定文件路径或分区。普通工作空间工具保留原目录行为。已有平铺 `documents/` 文件继续保留，项目分区不会自动认领来源不明的旧文件。

已覆盖真实 SQLite、Native HTTP 授权、工具批准、共享读取、变更通知、并发冲突和撤权拒绝。2026-11-03 真实桌面回归中，“本地文件验收三”先由页面写入 `script` 第 1 版，再由 Agent 读取并经批准保存第 2 版，页面自动同步。共用同一目录的“桌面项目隔离B”由 Agent 读取返回 `document: null`，再由页面保存自己的第 1 版，返回项目 A 后内容保持独立。项目分区文件与原平铺历史修订均保留。

旧版可空工作空间模式的新项目会话会捕获用户已选择的目录，并在重试时保留该绑定。已有空绑定继续显示选择目录提示。新版独立项目模式使用原 Native 项目目录分配器。

工作空间的“移出列表”持久隐藏目录项，并保留原路径与会话绑定。再次选择同一目录恢复原 ID。Control 拒绝把新会话绑定到已移出的目录，已有会话仍可读取自己的原目录。折叠在侧栏按空间分别控制。

插件侧栏和主空间目录共用 `CommandWorkspaceDirectoryGroup`，会话共用 `CommandSidebarThreadList`。插件只通过原 SDK 服务提供项目、会话和操作，继续使用原安装租约与工具权限边界。目录先分页读取项目，展开单个项目后读取其会话。原自绘侧栏的需求版本、连接状态、重复标题和进入对话卡片已从目录中移除。

宿主目录的首次读取等待挂载发布授权完成，发布前撤权会取消读取。目录通过原侧栏按钮显式折叠。会话恢复已在 `0d073c3dc` 中移除的历史分页及文件汇总工具栏，仅在工具历史不完整时显示重读提示。

桌面构建已验证插件目录首次打开无需手动刷新，目录折叠入口可用，主会话与插件会话均不显示旧工具栏，重启后项目文件保持可读。“重录”的已确认方案与版本历史入口仍可访问。定向验证包括 207 项 UI/宿主回归、12 项真实文件与 HTTP/运行器检查，以及插件 Worker 启动失败后普通会话完成的进程级回归。

本轮远端检查没有新提交。`d11b` 的录制能力和 `e73a` 的 Team 工作树仍含未提交改动，三方预检在主窗口、运行器和会话层出现冲突，未纳入本轮改动。

## 制作页面的伸缩边界

制作页保持在宿主工作台中，使用同一侧栏拖拽与铺满能力。拖拽解除原 840px 上限，根据中间 Agent 对话区的实际左边界计算剩余宽度，独立预留 560px，左侧目录和导航栏不计入该宽度。达到阈值后扩展至目录右缘，目录继续可见并可操作，退出后恢复侧栏宽度。目录仅响应用户的显式折叠操作。文件工具与插件共用该行为，伸缩不会重新挂载插件或更换会话。

插件页面按容器实际宽度组织剧本、资产和分镜。窄栏压缩目录与工具栏，中等宽度显示目录和正文，宽幅增加资产网格列数。页面复用宿主主题变量，布局规则限制在插件容器内。

本轮宿主伸缩改动通过 111 项定向回归、类型检查和桌面构建。真实桌面已检查拖拽触发扩展、扩展时保留目录并切换项目、主动折叠后用原按钮重新展开、退出扩展后恢复侧栏。插件内部三组制作页及 Skill/知识库整合仍按前述改造顺序实施。
