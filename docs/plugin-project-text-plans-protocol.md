# 项目文字执行计划协议

日期：2026-10-06。Short17 增量提供独立 `crewon.project-text-plans@1`，公开入口为 `@crewon/contracts/project-text-plans`。与 Short16 的项目对话、阶段 Run 和共享文字成果服务配合，支持需求→大纲→指定分集剧本的持久执行。宿主基础界面及 SDK0.1.0 不变；角色资产、分镜、视频、声音和成片仍按[协同设计](./short-drama-agent-workflow-design.md)分阶段接入。

## 用户操作与执行边界

用户在原短剧模块选择实际项目对话、起点、终点、分集范围和创作要求，明确开始计划。默认 `manual`：需求追加当前需求修订，大纲和剧本先保存候选；用户在现有文字页采用、按需锁定，然后明确继续。`whenUnchanged` 是独立的用户选择，允许符合来源及选用检查的步骤采用自身成果并推进。安装、信任插件、模型建议或读取计划均不产生这项委托。

同一主体、配置档、项目和对话只能有一条未结束计划，paused 也占用此范围。执行最多16集、18个固定步骤，并发1，每一步最多一个业务保存结果。既有大纲、指定独立剧本可以作为起点，不伪造未完成的前置成果。计划有明确终点，不能变成无限 Agent 循环或任意 DAG。

Short17 的开始和扩大剩余执行范围使用真实 UI invocation 签发的独立事务资格。原普通未关联对话的一句想法创建项目、从原消息建立计划建议及确认，属于下一项入口接线；当前模型工具不能借 UI 资格批准自己，也不能从参数提供 actor、安装身份或委托。

## 公共动作

所有动作严格使用 `crewon.project-text-plans.v1.*`。写入携带原 `idempotencyKey`；除开始外，还携带当前 `expectedRevision`。

| 方法              | 输入与作用                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `start`           | 项目、真实 Thread、预期关联/需求修订、要求、起止阶段、分集范围和选用规则；保存有界委托和步骤 |
| `get`             | 项目、planId；读取当前头、定义及步骤，或 null                                                |
| `list`            | 项目、afterPlanId、limit；按稳定 ID 分页，limit 1–16                                         |
| `pause`           | 停止派发下一步骤，已准入任务保持原身份                                                       |
| `resume`          | 用户明确确认当前来源与剩余范围，重新授权后续派发                                             |
| `revoke`          | 停止后续执行，保留已开始任务及成果                                                           |
| `reviseRemaining` | 用户明确修改剩余要求、终点、分集和选用规则；新定义不能向前扩展已完成范围                     |
| `continue`        | manual 模式下校验本步骤确切成果已经采用，再允许下一步骤                                      |

阶段只有 `brief / outline / script`。执行到 brief 时 episodes 为 null；生成新大纲使用 `newOutline` 和1–16集；从剧本开始使用 `selectedOutline` 或 `independentScripts`，携带确切既有 episodeIds。指令最多4096 UTF-8字节，输入及列表最多24 KiB，详情最多60 KiB；控制字符、孤立代理项、未知字段和不一致范围均拒绝。

公共详情包含计划头和当前定义、固定步骤、来源修订、实际 Run/阶段摘要、业务成果引用、选用事实和终态观察。不返回私有授权、完整安装资料、工具回执、内部 planDigest 或原幂等键。正文仍通过已有文字服务读取。

## 沿用原执行与恢复链

组合必须显式配置计划服务，且精确出版 tuple 同时属于项目 UI、文字 UI 和项目对话服务。旧配置不打开计划表，也不获得计划动作。Native 在当前 Main 准备的完整来源和真实请求 owner 上派生委托调用；Remote 没有明确提供此能力时，保存可观察的 `authorization_unavailable` 暂停，拒绝执行，不伪造本机身份。

原 Control 的有界扫描与实际 outbox 消费者负责进度；原 TaskCore 创建真实 Turn、Run、队列和阶段准入。原 Worker 读取固定计划范围，原安装 Node 插件通过当前 Worker 命令执行项目工具。没有新增运行时、插件计时器或网页隐藏执行循环。

步骤领取、Run 与计划关联在父 Store 同一个提交连接保存；真实业务 Tool 保存候选与步骤成果引用同事务提交。自动选用和推进也同事务完成，只允许本步骤确切结果，不能改选“最新候选”。原 Run 必须真实结束且具有合格业务结果才可推进；无结果、失败或取消时暂停，已有候选保留。

SQLite/PostgreSQL 提交中核主体、当前安装/配置/target、真实委托、阶段与分集、来源摘要、锁定、工具租约及结果。独立 Run 标记防止计划表丢失后降级为旧无范围执行。后续定义不会重写已准入 Run、输入、来源或成果。

## 并发编辑与暂停

需求、大纲来源、选用指针、锁定、关联或配置变化时，不覆盖手动成果，不派发下一任务。具有合法当前元数据 owner 时写入对应暂停；安装或关联完全撤回、无法再取得合法当前 owner 时，拒绝新派发和选用，不承诺能够凭存储中的旧 actor 继续修改暂停状态。

manual 的采用和继续是两个动作，避免页面采用后立即启动未经确认的后续步骤。用户已采用并锁定本步骤的确切成果可以明确继续；锁定其他成果或来源变化仍拒绝。自动选用要求原基线、当前来源、head/选用指针和未锁定事实完全一致。

## 回执与页面恢复

同键重放返回原操作的固定回执视图；当前计划详情可能已经更新。页面确认旧回执时清除未知请求，但保留已经读到的更高 revision。列表或详情迟到不能回退头；已知头比读到的详情更新时，不显示旧详情作为可写 CAS。

确定的未提交来源、关联、修订或剩余范围冲突释放本次请求，须刷新并重新明确操作；不能自动改变原输入或重发。其他未知响应在同一挂载保留原请求和原键，只有“重试原计划操作”再次发送它。表单默认值跟随真正未完成步骤，已手动编辑的字段保留；这种默认更新不改变保留的未知请求。

冷挂载只读取服务端计划，不新建任务或重放写入。Short17 尚未增加独立的本地计划 intent journal；服务端幂等与已持久计划的冷恢复，不等同未确认本地写入可以任意跨 App 重启恢复。

## 构建和验收范围

示例自持无 import 的 portable 协议与严格 codec ESM，构建固定摘要，仓外用冻结 SDK0.1.0 tarball 严格编译 UI/Node 并打包。旧包、Krea 工作流、宿主全局 CSS、原导航及账户入口保持原样。

命名公共 DTO 的真实 Chrome 页面验证只证明发行包交互和布局；真实 Main 准备、Control/Worker/Node、双库提交、实际用户模型与媒体分别验收。命名模型 transport 没有模型网络请求，不能作为供应商创作或完整短剧已完成的证明。当前验收和剩余阶段见[实施进度](./incremental-extension-progress.md)。
