# 结构化改编大纲 v2

依据[产品拆解](./reelbench-product-replication-analysis.md)的小说改编概览、大纲和资产关联，以及 [shuohao-skills 固定版本](https://github.com/eternityspring/shuohao-skills/tree/ef4ac0c313c7eeb1f918db5f0f0eb319745900bc/skills/novel-outline)。这是 P2 的数据与校验实现；原有持久化服务、Agent 工具和插件页面尚未接入该新格式。不能将本记录当作完整产品验收。

## 已实现内容

`@crewon/domain` 提供 `parseProjectOutlineDocument`、`evaluateProjectOutlineQuality` 和 `projectOutlineAssetRequirements`。格式显式使用 `crewon.project-outline-document.v2`，不会扩展或误用旧四字段大纲。

| 内容           | 独立字段与关系                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 故事概览       | 标题、一句话故事、整体梗概、来源名称与语言。来源名称是标签，不能充当原文来源证明。                                                            |
| 改编规格       | 集数、单集分钟数、题材、忠实/抽核/借壳策略、必留偏好和明确的质量阈值。创建页仍保留既有可选字段；进入专业大纲执行阶段后才能检查所需规格。      |
| 改编取舍       | 内核；保留、砍掉、合并分别记录对象和原因；保留项可含原文引句；风险分别记录问题及处理计划；砍线和合人补注独立保存。                            |
| 人物和场景     | 人物稳定 ID、定位、轻重档、弧光及来源记录；场景稳定 ID、主场景标记及复用计划。不是最终角色画像或场景美术文档。                                |
| 叙事道具和爽点 | 道具戏剧功能及爽点引用；爽点轻重、铺垫、兑现和分集引用。道具尺度、状态和经手人留给美术文档，不塞进大纲。                                      |
| 分集           | 稳定 `episodeId`、当前展示编号 `ep`、标题、梗概、钩子、悬念、人物/场景/道具引用、同框拆解和制作预警。改名或重排不会把引用转成标题或数组下标。 |
| 资产需求清单   | 从实际分集引用计算人物、场景和道具的使用集。返回真实实体 ID 和稳定分集 ID，不让模型手写数量；它是制作需求，不是假装已生成的图像资产。         |

新文档至多120集、240 KiB，并沿用有界 JSON 遍历、严格字段及 Unicode 检查。旧格式仍至多16集、16 KiB；两格式相互拒绝，旧调用不会丢掉新字段后冒充完整读取。输入会复制并深度冻结，保留原文、空格和换行。未知字段、重复身份和重复引用会拒绝；可编辑的空正文及暂时无效的业务引用交给实际质量门报告，避免把“格式合法”当作“创作完成”。

## 实际 Skill 校验

固定上游 `ef4ac0c313c7eeb1f918db5f0f0eb319745900bc` 的纯函数 `gateReport` 和 `validateOutline` 已保留原字节片段，并保留 Apache-2.0 许可、NOTICE 与来源摘要。没有引入另一运行时、CLI 或文件访问；服务和授权依然由 CrewON 负责。

14项门包括三档人物数量、主场景数量、叙事道具数量、一次性场景复用、爽点间隔、首集钩子、大爆点时机、分集三栏、多人同框拆解、风险预警、引用完整和叙述体检查。`skeleton`、`beats`、`full` 分别运行上游相应阶段校验。未到执行阶段的门显示跳过；未提供道具表时明确跳过道具上限，并明确说明道具引用未检查，人物、场景和爽点引用仍检查。

上游校验使用临时分集序号视图；业务文档仍保留稳定 ID，不改写存储身份。报告含实际问题和固定 Skill 来源。纯校验器不能访问原小说，报告明确 `sourceEvidenceVerification: not-checked`；引句与实际原文的核对必须由持久化服务结合已确认 Foundation 来源完成。通过本校验不表示已保存、已采用、已出图或已验证原文。

## 接线顺序与兼容边界

1. 新持久化修订复用原 `projectId`、大纲 `artifactId`、候选历史和采用指针；使用独立版本标记及 Foundation/原文/确认方案的确切版本，不建立第二套项目身份。
2. 沿原 SQLite/Postgres 事务核对实际项目、当前规格、来源及确认方案，保留原 CAS、幂等回执和冷恢复。新候选的保存不能覆盖已采用成果；只有完整校验及真实来源检查通过，才能明确采用。
3. 新 HTTP/UI/Node 服务使用显式新协议。旧 v1 服务维持原形状和预算；遇到新修订须返回协议升级原因，不能将其裁成旧梗概或误写为旧格式。
4. 产物页分别显示改编取舍、人物/场景、爽点、分集和资产需求。手动修改与主页 Agent 共用同一业务记录。原主页对话框及宿主主题保持不变。
5. 长大纲的 Agent 保存沿实际批次追加，单批至多10集；读取按正文和对象分页，不把全大纲、全书或质量报告常驻注入模型。章节原文仍走既有 Foundation 有界读取。

这些接线尚未计为完成。33项领域检查通过，无跳过，包括24项新格式检查及9项既有文本行为检查；覆盖严格格式、14个实际失败门、阶段跳过、旧文本格式限制、120集、稳定引用和派生资产清单。领域类型检查、架构边界和仓库格式检查通过，记录位于 `output/extensions/checks/structured-outline-v2/`。用户桌面、真实 Agent 写入及双库接线需要后续独立证明。
