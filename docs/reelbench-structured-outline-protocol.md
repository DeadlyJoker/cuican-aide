# 结构化改编大纲 v2

依据[产品拆解](./reelbench-product-replication-analysis.md)的小说改编概览、大纲和资产关联，以及 [shuohao-skills 固定版本](https://github.com/eternityspring/shuohao-skills/tree/ef4ac0c313c7eeb1f918db5f0f0eb319745900bc/skills/novel-outline)。当前已实现数据、校验、双库持久化、有界 Application 修改和新的只读 UI 协议，插件42增加对应产物页。公开写入、Agent新格式执行及用户桌面的42版本仍未完成，不能将本记录当作完整产品验收。

## 已实现内容

`@crewon/domain` 提供 `parseProjectOutlineDocument`、`evaluateProjectOutlineQuality` 和 `projectOutlineAssetRequirements`。格式显式使用 `crewon.project-outline-document.v2`，不会扩展或误用旧四字段大纲。

| 内容           | 独立字段与关系                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 故事概览       | 标题、一句话故事、整体梗概、来源名称与语言。来源名称是标签，不能充当原文来源证明。                                                            |
| 改编规格       | 集数、单集分钟数、题材、忠实/抽核/借壳策略、必留偏好和明确的质量阈值。创建页仍保留既有可选字段；进入专业大纲执行阶段后才能检查所需规格。      |
| 改编取舍       | 内核；保留、砍掉、合并分别记录对象和原因；保留项可含原文引句；风险分别记录问题及处理计划；砍线和合人补注独立保存。                            |
| 人物和场景     | 人物稳定 ID、定位、轻重档、弧光及来源记录；场景稳定 ID、主场景标记及复用计划。不是最终角色画像或场景美术文档。                                |
| 叙事道具和爽点 | 道具戏剧功能及爽点引用；爽点轻重、铺垫、兑现和分集引用。道具尺度、状态和经手人留给美术文档，不塞进大纲。                                      |
| 分集           | 稳定 `episodeId`、当前展示编号 `ep`、标题、梗概、钩子、悬念、人物/场景/道具引用、同框拆解和制作预警。改名或重排不会把引用转成标题或数组下标。 |
| 资产需求清单   | 从实际分集引用计算人物、场景和道具的使用集。返回真实实体 ID 和稳定分集 ID，不让模型手写数量；它是制作需求，不是假装已生成的图像资产。         |

新文档至多120集、240 KiB，并沿用有界 JSON 遍历、严格字段及 Unicode 检查。旧格式仍至多16集、16 KiB；两格式相互拒绝，旧调用不会丢掉新字段后冒充完整读取。输入会复制并深度冻结，保留原文、空格和换行。未知字段、重复身份和重复引用会拒绝；可编辑的空正文及暂时无效的业务引用交给实际质量门报告，避免把“格式合法”当作“创作完成”。

## 实际 Skill 校验

固定上游 `ef4ac0c313c7eeb1f918db5f0f0eb319745900bc` 的纯函数 `gateReport` 和 `validateOutline` 已保留原字节片段，并保留 Apache-2.0 许可、NOTICE 与来源摘要。没有引入另一运行时、CLI 或文件访问；服务和授权依然由 CrewON 负责。

14项门包括三档人物数量、主场景数量、叙事道具数量、一次性场景复用、爽点间隔、首集钩子、大爆点时机、分集三栏、多人同框拆解、风险预警、引用完整和叙述体检查。`skeleton`、`beats`、`full` 分别运行上游相应阶段校验。未到执行阶段的门显示跳过；未提供道具表时明确跳过道具上限，并明确说明道具引用未检查，人物、场景和爽点引用仍检查。

上游校验使用临时分集序号视图；业务文档仍保留稳定 ID，不改写存储身份。报告含实际问题和固定 Skill 来源。纯校验器不能访问原小说，报告明确 `sourceEvidenceVerification: not-checked`；引句与实际原文的核对必须由持久化服务结合已确认 Foundation 来源完成。通过本校验不表示已保存、已采用、已出图或已验证原文。

## 已接入原有版本库

`ProjectStructuredOutlineStore` 由原 `SqliteProjectTextStore` / `PostgresProjectTextStore` 实现，借用原父级连接、连接池和生命周期。没有新迁移、项目身份、采用指针或第二套版本表；新修订标记为 `crewon.project-text-revision.v2`，仍写入原大纲槽、不可变历史及幂等回执。候选追加保留原采用项和锁定状态；同一键重试及关闭后重开返回原结果。

新修订绑定真实 Foundation 版本、规格版本及摘要、原文版本及摘要、已确认方案版本及摘要。提交在实际 SQLite 写事务或 PostgreSQL 原项目锁下重新读取这些记录，核对集数、题材、单集时长和改编策略，并在 COMMIT 前重新核对来源状态。缺少专业执行规格、确认方案或版本已变更时拒绝提交。

完整采用会重新执行 Skill 校验，并在同一事务中遍历真实原文片段，核对连续序号、Unicode 标量偏移、逐段摘要、完整原文摘要及所有提供的保留/删减/合并引句。引句可跨片段匹配；正文使用流式哈希及小边界窗口，PostgreSQL 每页至多32段，不将整本书注入模型。未通过完整校验的草稿仍可保存，但不能采用。

旧读写协议、64 KiB 标准化预算及旧内容限制保持不变。旧服务读取新修订，或者试图在已有新候选后保存/采用旧格式时，返回明确的 `project_text_protocol_upgrade_required` 冲突。原有锁定命令可以继续使用；新读取支持混合历史，不将新字段裁掉后冒充完整结果。原 v1 UI/Run/计划授权不能直接批准新形状，目前尚未注册任何新公开写入口。

相关检查为105项通过，无跳过：双库及兼容流程56项（其中18项为新存储行为）、领域与原 Application 流程49项。Domain、Application 和 Store 类型检查通过。日志位于 `output/extensions/checks/structured-outline-store-v2/`。这些检查使用隔离真实数据库及明确夹具，不代表已在用户资料中保存，或已通过真实 Agent、HTTP/UI 与桌面验收。

## Application 与新只读协议

`ProjectStructuredOutlineApplicationService` 使用原项目、Foundation、大纲槽和回执。候选修改显式区分初始化、概览、改编取舍和各实体集合；单次至多10个对象、48 KiB变更，以确切基础版本及摘要追加。120集实际双库检查通过小批次形成同一完整文档，质量与实际原文核对后采用；锁定、并发版本和关闭重开后的同键回放保留。旧 UI/Run/计划提交资格仍被拒绝，不把旧批准当作新协议批准。

`crewon.project-outlines` API2目前仅有 `getOutline`、`getSection` 和 `listRevisions`，无公开写动作。请求24 KiB，响应60 KiB；概览返回版本、统计及校验摘要，正文按确切项目/产物/修订/摘要读取整项，每页至多10项。长正文不会静默截断；返回明确的下一页位置。服务通过原私有 UI 调用注册、原安装与发布身份、当前认证请求和业务权限，读取前后均检查存活和授权；没有生成、积分、Run或写回执。

插件42的小说大纲页直接呈现已采用版本的分集、人物、场景、道具、爽点及改编依据，质量和历史按需展开；候选历史只查看，不改变采用项。旧宿主回退原文字页，真实传输错误显示重试。所有主题和布局限于插件，原 Agent 对话框未新增或替换。

独立插件402项检查通过，包括新增阅读控制器、实际文字快照、分页与晚到请求处理。产物标签支持方向键、Home和End；键盘交互仍需真实桌面验收。Application新流程6项SQLite/PostgreSQL检查通过；原生导入与执行声明修复6项通过。新读协议的实际安装、正式HTTP及SQLite/PostgreSQL集成检查2项通过，覆盖120集完整正文分页和原权限撤回。以上夹具和服务检查不等于新版已安装、真实 Agent 已写入新格式，或完整产品验收通过。

## 后续接线顺序与兼容边界

1. 安装已通过原安装/正式HTTP双库检查的宿主及插件；以实际安装为验收对象。
2. 新公开写协议核对原 UI 意图或 Run/Tool 的新版本资格，保留现有保存回执、断线恢复和未知结果处理；增加手动修改及主页 Agent 批次写入。
3. 新大纲与后续角色/美术、剧本和分镜共享稳定实体身份及明确的上游版本。长文读取分页，不把全大纲、全书或质量报告常驻注入模型，单个模型注入片段不超过10K tokens。

此前33项领域检查记录位于 `output/extensions/checks/structured-outline-v2/`；49项包括这些用例及原 Application 行为，不能重复相加。用户桌面的新格式、真实 Agent 写入及新公开写协议仍需要独立证明。
