# 短剧阶段执行与双入口协作

2026-10-06。本文把[完整协同设计](./short-drama-agent-workflow-design.md)细化为可实施的阶段契约。一个 `crewon.short-drama` 插件包含这些阶段及多个工作流；原 Agent 对话和手动工作台调用同一项目服务。以下为目标设计，已交付范围另见[实施进度](./incremental-extension-progress.md)。原宿主样式、侧栏、账户、设置及工作空间绑定保持。

参考 [shuohao-skills](https://github.com/eternityspring/shuohao-skills) 的角色、美术、剧本、分镜分工、参考锚点与确定性检查；参考 [Reelbench](https://reelbench.79px.com/) 的项目资产、引用及任务记录组织。CrewON 的执行、权限和恢复继续沿现有宿主，参考网站的部署方式及供应商限制不成为我们的通用规则。

## 一项成果如何产生

[跨阶段自动执行规格](./short-drama-orchestration-spec.md)进一步定义两个入口如何领取同一业务步骤、采用检查点、部分失败、依赖变更及冷恢复。它是实施规格，不代表已发布新的媒体或计划协议。

[媒体原Run事务准入](./project-media-generation-run-protocol.md)已固定真实确认输入、逐素材准备事件和业务执行意图；该宿主内部底座继续接Worker、Main及两个产品入口，尚不代表阶段媒体生成已可用。

同一业务项依次经历“明确目标 → AI/用户准备内容 → 校验 → 保存候选 → 采用 → 执行下游”。每一步都有独立含义：

1. **明确目标**：保存项目、阶段、业务项范围、终点、允许工作流、候选数量、选用规则和锁定项。“帮我想想”只产出建议；“先做三集大纲与第一集剧本”可以执行该明确范围。
2. **准备内容**：用户编辑，或 Agent 根据当前采用版本生成内容。文本创作不必经过 ComfyUI；AI 输出必须符合该阶段的结构，仍作为候选保存。
3. **校验与采用**：程序检查结构、引用、覆盖和技术规格。用户或已明确授权的自动选用规则采用确切候选。创作质量可由用户确认；未接入多模态评价时不虚构画面/声音评分。
4. **执行媒体**：读取真实采用素材，保存确认后的提示词、参数、工作流及源修订；准备素材后提交原任务。手动执行不在后台再改写提示词；Agent 自动执行也必须先保存可回看的输入。
5. **观察与选用**：受理、正在生成、结果可读和采用分别显示。读取供应商结果后保存候选，采用才影响下游。结果未知只核验原任务，不能自动重新提交。

这些是共同业务步骤，不要求每个阶段都调用一次文本 AI 加一次媒体 API。阶段可先编辑结构；只有能力、必需输入和执行资格全部满足，才开放实际执行。

## 阶段契约

| 阶段           | 必需输入                                         | AI 与工作流配合                                                                    | 持久产物和完成依据                                                       |
| -------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 创作需求       | 用户想法、原文或已有资料；指定制作范围           | Agent提炼故事目标与约束，有界提取资料，核对缺口                                    | 需求修订、制作范围和计划；假设明确，执行范围可回看                       |
| 大纲与分集     | 采用的需求、集数或分集范围                       | AI产出人物关系与情节，检查器核对分集覆盖、转折和必要设定                           | 大纲/分集候选及采用指针；全部请求的分集有合格成果                        |
| 分集剧本       | 需求，采用的大纲或明确导入的剧本起点             | AI写场次、动作、台词，工作流提取对白并检查引用与时长                               | 分集剧本修订及台词来源；完成以采用的剧本为依据，导入不伪造大纲           |
| 角色与美术资产 | 需求，可选剧本来源；稳定角色/场景/道具身份       | AI整理设定与画面描述；T01/T04做文本形象探索，T10从确切参考派生；检查来源与技术规格 | 设定、参考候选、采用锚点及锁定；探索不替换锚点，四视图不冒充四份文件     |
| 分镜           | 采用剧本、所需确切资产设定与参考                 | AI把场次拆成镜头，程序核对剧情/对白覆盖及资产引用，按实际供应商约束拆生成分段      | 镜头表、生成分段、对白位置与资产版本；分镜不擅自改剧情，改动形成上游候选 |
| 关键帧与视频   | 采用分镜、确认提示词、所需参考或首尾帧、真实服务 | AI准备描述；图像/视频API生成，检查器确认实际输出、尺寸、时长与关联                 | 每镜/每段的输入、原任务和媒体候选；图像成功不表示视频完成                |
| 配音与声音     | 采用台词、角色音色配置、分镜声音意图             | AI准备语气/声音需求，TTS及音乐/音效API生成，工作流读取时长并对齐对白               | 音轨、台词修订与对齐数据；对白或音色改变使对应音轨过期                   |
| 剪辑与交付     | 采用的视频/音轨、字幕来源及时间线                | AI建议节奏；确定性时间线操作、外部合成和技术检查产生结果                           | 时间线修订、成片与交付报告；可读成片及必要技术检查通过才算完成           |

新增结构化分镜的稳定身份至少覆盖分集、场次、镜头和生成分段；镜头与供应商请求不能混成一个 ID。每镜保存构图、动作、运镜、时长、对白引用和资产引用；每段保存实际工作流所需的镜头范围、参考顺序及输出规格。这是待实现契约，不暗加到现有文字 v1 请求。

工作流目录以实际输入契约匹配用途。D18当前需要一个场景和两个有顺序的角色，适用于满足这些条件的镜头关键帧；一个人物的镜头不能靠捏造第二角色或复制文件冒充满足条件。缺少合适适配器时保留分镜，显示缺失能力，继续可独立执行的其他项。视频、声音、合成也分别验证真实API，不能因为ComfyUI中存在一个名称就开放按钮。

## 用户和 Agent 如何接力

示例指令：“做三集雨夜悬疑，完成大纲和第一集剧本，探索女主形象，先不做视频。”

Agent在原对话整理并保存需求，建立有界计划。大纲与剧本沿实际采用规则推进，资产阶段提取女主设定，生成获准数量的形象候选。用户打开工作台改第一集台词并采用，又选中一张女主图并锁定。返回原对话说“继续做第一集分镜”，Agent重新读取当前剧本、确切参考与锁定项，保存新的分镜计划；不能沿旧聊天文本覆盖用户刚采用的内容。

工作台始终可以独立编辑、AI补全、探索候选、采用/锁定和执行本步，也可以明确推进到某阶段。对话卡片显示实际成果和待处理项，点击进入原项目的相应项；主聊天不堆积全部工作流图、长剧本和轮询信息。页面用已有组件与主题，仅插件内容区新增项目操作。

计划逐项保存输入版本和执行关联。手动执行与Agent计划领取同一持久步骤/执行意图，服务器协调并发；两个入口各生成随机请求键不能保证去重。用户明确“再做一个候选”才产生新的意图。用户手动采用会暂停依赖旧输入的未执行步骤，随后可以按新修订继续；已受理结果仍属于旧输入，不会覆盖新指针。

锁定限制替换采用版本，仍允许探索候选。修改正式输入后沿真实依赖列出受影响项：改台词影响相关配音、字幕与包含对白的镜头；换人物参考影响引用它的关键帧和视频；改某镜头时长影响相应生成分段与时间线。未采用草稿不让正式下游过期。旧成果保留，可查看和明确复用，不能无提示当作当前成果。

Agent按项目/阶段/业务项分页读取当前版本和检查结果，单片段不超过10K tokens。文本修复、候选数和并发有界；暂停挡住新的任务和自动采用，已提交媒体继续观察原任务。关闭工作台、聊天重连或App重启后从持久计划恢复。

## 当前接线顺序

现有文字计划、资产档案和原会话关联继续复用。T10/D18同包适配器已完成示例素材的真实外部生成；正式项目参考到媒体执行仍需接线。

宿主内部已实现“解析已采用参考”、受控字节读取与[源字节冻结](./project-reference-material-freeze-protocol.md)：两个入口未来只给业务身份和确切修订，服务核验真实项目、采用指针、原结果及历史配置，独立检查读取/归档资格并固定真实字节。来源DTO、读取观察和源归档均不授予任务执行，也没有新增公开插件服务、UI或生成按钮。

[供应商副本与持久准备](./project-material-preparer-protocol.md)、[确认媒体输入与逐角色准备](./project-media-input-protocol.md)已完成宿主内部组合和双库验证。保存确认输入不触发上传；准备状态与原生成Run分开。D18当前记录是带采用剧本来源的双人物画面探索，结构化镜头表及每镜生成关联仍须实施。

随后依次接持久媒体输入和实际准备记录的原Run准入、手动T10/D18项目生成、对应Agent资产/分镜步骤，再接实际视频、声音和成片。每一步保留源码检查、正式App操作和真实供应商验收各自的范围；当前不能宣称八阶段已自动打通。
