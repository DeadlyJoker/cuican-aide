## 已实现的传输规则

`renderComfyMaterialUpload`是宿主纯适配器。输入为确切源归档记录和字节、宿主分配的UUIDv4准备身份，以及已规范化的目标HTTPS根地址。它重算归档记录摘要、源字节摘要、长度和受限PNG尺寸；不接受调用者指定的目标文件名、子目录、URL或覆盖选项。记录和适配DTO不能获得项目访问、目标网络或发送资格。

每次准备固定到`output/crewon-materials/<preparationId>/material-<byte-sha256>.png`，上传到明确的`POST /upload/image`，multipart内固定`type=output`、独立subfolder和`overwrite=false`。同一准备产生相同正文、目标路径与请求摘要；新的准备使用新的目录。检测正文中的multipart边界冲突并拒绝，不能将input引用伪装成output引用。源归档与供应商副本分别保存，供应商副本不是源归档。

原通用JSON请求/响应上限仍为1MiB，已有GET图片模式仍只读。新`imageUpload`模式只允许明确的POST路由、无query/hash和受限multipart Content-Type；源图片最多16MiB，完整上传正文最多16MiB+64KiB，回执最多64KiB。TLS、证书/主机名、真实远端地址、固定DNS结果及不跟随重定向规则保持。低层模式本身不检查项目授权；组合调用必须先沿原生产公网HTTPS网络策略批准确切目标，不能直接把自报IP作为批准。

上传采用原生TypedArray内部长度和set复制，分配前限制实际字节数，不调用调用者覆盖的length、byteLength、byteOffset、buffer或迭代器。发送前捕获独立正文，调用者随后修改原数组不改变实际发送的字节。该复制仍不能替代持久请求摘要和实际发送前的资格核验。

回执必须是200、受限UTF-8 JSON，name/subfolder/type与原计划完全相同。服务可能在冲突时改名，改名回执拒绝；不能跟随回执中的URL或asset对象。服务自报asset hash不作为素材证明。随后只GET原计划的`/view`路径，不带preview或channel参数，核验实际PNG字节摘要、长度、尺寸及Content-Length。文件名与上传回执正确也不能代替字节核验。

目标可读性是核验时刻的观察。外部服务文件仍可能被其他操作改动，不能宣称供应商具备不可变存储保证；媒体执行前仍须核验原路径及原字节。

## 持久目标准备与服务组合

目标准备使用独立于源冻结、媒体输入保存和生成Run的原请求键。禁止借用源生成Run、伪造Run或把上传包装成数据库事务。手动入口和Agent步骤最终调用同一个准备业务服务，不接收供应商路径或任意HTTP正文。

准备记录冻结实际调用者/项目、已采用资产及设定/参考修订、源归档身份和记录/字节摘要、真实目标安装包及选择、实际配置修订/摘要和规范化服务地址、原准备键、目标路径、multipart请求摘要。服务器从实际项目与安装/config记录解析它们；字段自报或适配器DTO不能成为准入证明。每个D18素材有各自的来源和准备记录，再按scene、characterOne、characterTwo的明确角色排列，不能用一个共同origin代替逐项证明。

以下状态规则已由独立journal和双库检查实现；取得claimed仍须通过真正的源归档、目标字节及独立网络资格。内部服务组合已实现；实际Main批准与公开入口尚未接线：

| 状态           | 允许动作                                       | 恢复规则                                           |
| -------------- | ---------------------------------------------- | -------------------------------------------------- |
| reserved       | 当前源/目标资格重核后，以CAS取得唯一发送权     | 原键返回同一记录；输入变化冲突，不换路径           |
| dispatching    | 唯一获准调用者发送一次，其他调用者只查询原路径 | 进程重启或回执丢失不重新POST                       |
| unknownOutcome | 保留原键、摘要、路径及未知原因，核验原目标     | 查询404、DNS失败或不可读不证明从未上传，不自动重发 |
| verified       | 仅在实际目标字节匹配且当前资格仍有效时记录证明 | 再用前核验；外部目标变化不重新上传冒充恢复         |
| rejected       | 保存确定的业务拒绝或不匹配原因                 | 同原请求保留原结果，新尝试须明确新请求             |

实际项目/采用来源、独立素材准备PDP、目标安装及配置须在保留请求前、发送前、读取后和最终保存时重核。发送后的撤权/来源变化可以阻止返回可用素材，但不能抹掉已经dispatching的原记录。数据库事务内使用同一父连接复核来源和实际安装资格；事务不跨越DNS、文件或HTTP await。已登记的源归档丢失/损坏必须不可用，不能重新GET源或生成新准备替代旧请求。具体验证覆盖SQLite/Postgres、两实例CAS、失去回执、冷恢复、撤权、上游变化及归档丢失后，再开放业务入口。

prepared证明经过上述服务后才可加入版本化媒体输入，原Run准入事务再次冻结确切输入与依赖；执行沿原TaskCore/Worker与原operation恢复。当前旧概念生图、文字计划和原资产文字阶段不因为有这个适配器而获得上传或媒体执行权限。
