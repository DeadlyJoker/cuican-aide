# 已保存媒体结果的素材采用前校验

2026-10-07。接续[插件内保存产出](./plugin-media-output-workbench.md)。本增量实现原候选到角色参考图的来源协议与采用前校验，供后续实际采用事务复用。实际采用、页面按钮、Agent 采用工具和下游图片读取尚未接通。

## 来源与兼容性

旧 `ProjectAssetImageSource` 指向概念图选择，保存其概念版本、选择版本和原操作结果。T10 的媒体候选来自另一种原 Run/operation，不能填入这些字段来伪装成概念图。

新增独立的 `crewon.project-asset-media-image-source.v1` 元数据格式，明确 `kind: media-result`。其中固定原候选 ID/摘要、输出序号、生成输入与执行身份、原操作/配置/包摘要，以及生成时使用的角色内容和参考图版本。它不包含供应商 URL、文件名、图片字节、归档位置或凭据，也不授予读取图片或写入的权限。

旧概念图来源、引用记录、接口、数据库结构和摘要均保持原格式。新类型目前只用于采用准备结果；没有把它写入现有 v1 引用表或投射到旧插件协议。实际采用需要明确版本的引用格式、事务提交与下游解析一起接通，不能只增加一个选择指针。

## 校验路径

`ProjectAssetMediaReferenceApplicationService` 捕获原项目与素材 Application 方法，复用原读权限检查。在取得 Store 准备结果后再次检查项目、素材、版本及结果权限，拒绝迟到的指针变化和撤权。元数据不能绕过素材读权限；该服务尚未注册为 UI 或 Agent 服务。

SQLite/PostgreSQL 的 `qualifyAssetReference` 借用原父连接，在同一个项目锁和事务内完成以下核对：

1. 当前项目有效、角色属于当前用户，未锁定，当前素材和已采用内容版本与请求一致。
2. 角色的需求及剧本依赖仍有效。
3. 原候选确已保存，其 ID、摘要和原输出位置与请求一致。
4. 原 Run、准入、配置、生成输入、素材准备、operation 及输出历史仍能相互验证。
5. 原生成输入针对该角色，且内容版本/摘要仍与准备采用的角色一致；生成时使用的原参考图仍能按历史版本验证。

仅支持将 T10 `krea2-reference-four-view` 的角色结果准备为角色参考。D18 的分镜探索结果必须进入后续分镜对象，当前会拒绝将它冒充角色参考图；场景、道具及其他工作流同样不能借此入口混用。

后续输入提示词变化不会重写旧候选的来源。用户明确选择旧结果时，只要原角色内容及依赖仍有效，就可以取得其原来源准备结果。修改角色内容、改变需求、锁定角色或项目归档会拒绝采用准备。

准备结果是一次读取快照。后续采用必须在实际写入连接上重新执行版本、权限和来源核验，不得把这个返回对象当作可转交的提交授权。
