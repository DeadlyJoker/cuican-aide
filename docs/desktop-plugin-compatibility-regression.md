# 桌面插件兼容回归

2026-10-07，接续 [Short31 图片采纳与复用](./short-drama-media-adoption-ui.md)。本次修复宿主自动化对当前会话协议的兼容问题，并继续排查原生验收失败。短剧插件包和宿主页面样式不变。

## 会话与自动化

实际 `ControlApiClient.getThread` 会把旧会话缺省的 `workspaceId` 规范为 `null`，也会保留已绑定会话的工作空间 ID。自动化模块仍按旧字段集合做严格校验，因此合法会话也会在创建和立即执行之前被拒绝。

校验现在接受当前字段，并复用公开的工作空间 ID 解析器。仍拒绝路径、非法 ID、额外所有权字段和不匹配的会话游标；失败时不提交自动化、不接续 Run。创建请求仍使用原会话 ID 和版本，不自行改变工作空间归属。

Office 历史会话查找的测试改为核对客户端规范后的对象，保留稀疏分页、Unicode 搜索和 14 页遍历，并覆盖未声明、明确未绑定和已绑定三种响应。

## 原生进程验收

旧 Comfy 原生进程夹具从默认 Agent 复制工具目录，但只提供 Comfy 运行时。默认 Agent 增加工作空间工具后，这种配置在实际 Worker 中被正确拒绝，错误为 `agent_version_tool_runtime_unavailable`。补充原 MCP 路径仍缺少本地工作空间命令，不能完整匹配。

夹具现在明确编译只需要 Comfy 的插件 Agent，沿用默认模型和执行参数。原默认 Agent 完整保留，额外断言普通聊天请求仍携带全部原工具，插件请求不继承这些工具。源码模式通过真实 Release / Worker / Control 进程完成任务、SSE 续读、默认聊天及零外部生成记录检查；模型服务为本地具名替身。这是旧扩展进程兼容证据，不是 Short31 安装包或在线出图验收。

打包模式仍失败：当前默认运行时总是准备工作空间工具，旧恢复捕获器明确返回 `runtime_bootstrap_tooling_unsupported`，与旧测试要求生成恢复胶囊不符。保留失败与原恢复断言，不放宽恢复门槛。后续需要明确旧恢复场景与当前可安装插件恢复路径的覆盖范围，并完成 Short31 原生 App 验收。
