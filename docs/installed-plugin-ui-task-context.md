# 已安装插件页面的任务上下文

原 `App` 将当前 Control 客户端、原 `ControlThreadRuntime` 和当前任务选择交给通用模块宿主。原首页、用户栏、设置分类、两侧栏和全局样式继续由宿主管理。独立包不接收客户端、账号、profile、执行目标、报价或凭据；没有插件名称或动作名称专用的宿主分支。

只有声明 `crewon.tasks@1` 或 `crewon.tasks@2` 的包才显示通用任务控件。已有任务的版本来自实际 `GET /threads/:id`，不能从页面的 Turn 数量推导。没有当前任务时，打开模块不创建会话或 Run；用户点击“创建任务”才通过原 Control API 创建一个临时目标会话。这一步不改变原 App 的任务选择，插件草稿因此继续保留。创建结果未知时保存相同请求和幂等键，再次点击仅重试该请求。

`crewon.plugin-ui-props.v1` 的 `data` 继续是有界业务 JSON，增加以下可选投影；SDK 和公开 HTTP DTO 没有升级。

| 字段                                 | 来源与含义                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `locale`                             | 宿主当前语言，保持已有字段                                                                       |
| `threadId`、`expectedThreadRevision` | 当前宿主会话或用户显式创建的目标，会话版本必须从认证 Control 读取                                |
| `taskContextReady`                   | 当前元数据是否可用于一个新意图；只影响页面交互，不授予任务权限                                   |
| `tasks`                              | 至多八个经过原任务读取接口校验的公开 `ExtensionTaskView`                                         |
| `sourceRunId`、`operationId`         | 用户明确选择的原外部操作，必须仍在已读任务中；不默认选择第一项，也不使用查询任务 ID 代替生成来源 |

投影最多 48 KiB，不附加历史文本、身份、内部绑定或媒体字节。超限时只省略末尾图片和操作并设置 `truncated`，保留实际任务标识。元数据暂时不可读时，同一所有者保留已核验的会话、结果和查询来源，并设置 `taskContextReady=false`。插件应阻止新意图，同时保留未知结果的原请求供直接重试。真正切换会话、包或账号时撤回旧作用域。

Web 与 Native 使用同一回执观察器。观察器只接受当前客户端实际动作响应中的完整六字段任务回执；该回执仍是恢复提示，模块所有者必须通过原 `getExtensionTask` 核对插件、会话和配置修订，随后调用原 `adoptExtensionTask`。原 Run、转录、SSE 和重连路径继续负责任务执行与恢复，没有另起 Agent 或平行任务引擎。点击“打开任务”才进入原会话。

离开页面立即撤下插件及其动作，但已发送的动作 HTTP 在自身五秒期限内继续读取受理结果。同账号的真实晚到 COMMIT 保留在有界恢复缓存中；最多每插件八项、每账号三十二项。账号变更同步撤回并清缓存，不把旧账号的响应展示给新账号。当前 B 页面可读取有权限的旧 A 历史，只有完整当前包 pin 匹配时才按当前模块接回回执；实际查询仍由服务端重读原 A 的持久绑定。

HTTP 逻辑取消不代表物理请求已经结束。任务元数据和创建请求按实际客户端共享单个物理请求池，最多十六个有界等待者；动作观察器最多保留十六个物理请求。期限或撤回不会提前释放实际槽。开发模式的 StrictMode 临时重挂不关闭仍属同一会话的恢复所有者，真实卸载和账号变更仍撤权。

排队也不等于已发送：创建会话及确认读取在实际槽交接后、发送前再次核验当前所有者。排队期间退出页面或切换账号不会让旧请求随后开始；已经发送的请求仍沿用原 body/key 和未知结果恢复规则。

Krea2 包使用以上投影，确认受理后等待实际会话版本更新，再以新键发起下一意图；未知结果锁定描述与原请求，不能换键重发。重复查询持续引用原生成操作，不再次预留生图积分或 POST 生成。结果仅显示原公开任务状态及 HTTPS 引用，不自动下载图片。

该页面接线不提供默认资金、价格或生产身份；新生成仍需要原安装、配置、发布、启用和真实报价准入。组件及具名 HTTP 测试不等于完整正式 App 的生成验收，双库安装式 UI/Worker 集成也不等于用户当前 ComfyUI 在线可用。完整 App/Main/packaged App、正式收费查询进程和在线服务验证仍需分别完成。

实际包的组件接线专项使用 Node.js 24 执行 `pnpm --filter @crewon/ui test:installed-plugin-task-context`。该入口复用已有唯一 SDK producer，在仓外构建独立包、删除开发源码与依赖后才启动消费者，消费者物理退出后清理自有目录。普通 UI 测试不构建包；未提供 `CREWON_TEST_KREA_PLUGIN_DIR` 时这两项不运行，显式配置空目录或坏包仍失败。专项必须实际运行两项、零跳过，不能将普通测试中的缺夹具跳过当作安装式验证通过。

完整正式 Web 入口的专业报告动作与冷恢复另见[完整 App 验收](./installed-plugin-full-app-acceptance.md)，使用实际 BFF/Control/Worker/PostgreSQL 和具名服务。它不替代 Krea2 的在线生成、原操作查询、正式 Native 或实际个人结算验收。
