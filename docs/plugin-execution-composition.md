# 原任务组合的执行装配核心

`PluginExecutionComposition` 已从原 `@crewon/plugin-host` 公开入口导出。它复用组合锁、profile Node 协调器、真实包核验及原执行工厂注册器，为一个任务根插件装配原依赖。现有单包 `PluginExecutionPackage` 保持相邻兼容；生产 Worker 的 v1 Run 拒绝路径仍保留，尚未接入真实 Run 读取、当前 PDP 与冷恢复流程。

## 身份与锁

`open` 要求严格的原完整组合锁、根插件 ID，以及从已认证 Run locator/ref 独立恢复的 `expectedScope`。tenant、space、profile、原 authority epoch 全部匹配之后才进入授权或包加载。历史 epoch 来自真实原 Run 引用，不能从待加载图自签；当前恢复权限仍由宿主另行检查，原 epoch 不等于当前授权仍有效。

完整锁保留原摘要与审计身份。装配只沿原服务边读取根插件的所有传递提供者，包括已经存在的可选提供者，不启动无关 Node 或纯 UI 模块。由这份严格原图派生的私有执行切片拥有内部摘要，仅供私有协调器使用；它不改写原锁、不保存新 head、不代替 Run 原引用。每道授权都收到原完整锁，调用者不会误把切片当作持久组合。

任务实际需要的宿主服务实现必须与原宿主服务元数据匹配。原图中无关的宿主服务不必恢复；当前新出现的服务也不能填补原图已捕获的可选缺失，不绑定或调用这些实现。执行注册器的首个内置实现明确标为 `crewon.execution-registry.v1`、修订 1；调用者必须将该身份记录进原图。它是宿主的显式版本承诺，不能当作源码哈希或签名；实现身份变化须推进修订，未保留的旧实现必须拒绝恢复，不能假冒旧身份静默替换。文件、来源、宿主发行和配置真实性仍由宿主批准与原绑定检查证明。

## 准备与授权

所有节点使用原精确包摘要、publisher、version、requires/provides 进行真实核验。首次准备授权、setup 后的异步权限刷新、同步发布栅栏均必须提供；仅凭安装状态、锁摘要或一次旧批准不能获得执行资格。

协调器新增可选 `beforePublication` 钩子，保留原调用者兼容；本执行装配入口强制要求它。钩子只能看到冻结的身份和捕获依赖，不获得 prepared commit/abort 句柄。异步刷新完成后再次检查内存当前性，发布仍由原 NodeHost 的自身栅栏检查实际依赖。任何必需节点失败都关闭此任务装配，不返回半个可运行工厂。

根插件必须实际向原执行注册器注册工厂。提供者可以只提供服务，不要求注册工具工厂；注册器按节点数量有界。工厂查找必须持有实际 NodeLease，身份对象由宿主证明，不能用同形 DTO 伪造。

## 借用与关闭

借用必须给出原完整锁摘要、明确的新执行/历史恢复用途及新的宿主授权。返回的工厂继续执行原注册器的身份、必要服务和租用校验，并额外拒绝不同 tenant/space/profile 的运行上下文及 scope getter。真实 Run、配置、输入、部署、提交/观察权与原外部回执仍是 Worker 的责任，不能因为此处返回工厂就跳过它们。

关闭先停止工厂创建，再撤权与清理依赖图。未释放的根借用保留全部捕获提供者，关闭明确失败，待所有运行器和物理调用结束、借用释放后才允许重试成功。启动清理失败通过原公开 `pluginExecutionPackageFailureOwner(actualError)` 保留真实重试所有者；同文案、同形或包装错误均不获得该所有权。

所有服务仍在明确的可信同进程模式运行，没有增加代码沙箱、替代 Node 运行时或第二套构建系统。装配不签发 HTTP 权限，不启用插件，不派发模型/Comfy 请求，也不向模型注入整图。

## 验证与剩余工作

真实安装包专项覆盖：原提供者 v1 与新图 v2 并行、旧图关闭后从原 JSON 重建、无关模块完全不加载、授权回调始终读取完整原锁、setup 后等待刷新、刷新后撤权不能开放工厂、精确摘要与 scope、实际工厂注册、在途租用退出，以及失败清理的真实所有者。测试使用临时安装根和工厂，没有外部服务请求。
