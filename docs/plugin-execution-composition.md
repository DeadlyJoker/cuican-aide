# 原任务组合的执行装配核心

`PluginExecutionComposition` 已从原 `@crewon/plugin-host` 公开入口导出。它复用组合锁、profile Node 协调器、真实包核验及原执行工厂注册器，为一个任务根插件装配原依赖。现有单包 `PluginExecutionPackage` 保持相邻兼容。真实 Run 的原组合读取、逐提供者当前 PDP、publisher 批准及跨包工厂已接入原 RuntimeResolver 和 Worker 组合函数；未显式配置组合执行时仍保留 v1 拒绝。正式桌面配置尚未启用此路径。

## 身份与锁

`open` 要求严格的原完整组合锁、根插件 ID，以及从已认证 Run locator/ref 独立恢复的 `expectedScope`。tenant、space、profile、原 authority epoch 全部匹配之后才进入授权或包加载。历史 epoch 来自真实原 Run 引用，不能从待加载图自签；当前恢复权限仍由宿主另行检查，原 epoch 不等于当前授权仍有效。

完整锁保留原摘要与审计身份。装配只沿原服务边读取根插件的所有传递提供者，包括已经存在的可选提供者，不启动无关 Node 或纯 UI 模块。由这份严格原图派生的私有执行切片拥有内部摘要，仅供私有协调器使用；它不改写原锁、不保存新 head、不代替 Run 原引用。每道授权都收到原完整锁，调用者不会误把切片当作持久组合。

任务实际需要的宿主服务实现必须与原宿主服务元数据匹配。原图中无关的宿主服务不必恢复；当前新出现的服务也不能填补原图已捕获的可选缺失，不绑定或调用这些实现。执行注册器的首个内置实现明确标为 `crewon.execution-registry.v1`、修订 1；调用者必须将该身份记录进原图。它是宿主的显式版本承诺，不能当作源码哈希或签名；实现身份变化须推进修订，未保留的旧实现必须拒绝恢复，不能假冒旧身份静默替换。文件、来源、宿主发行和配置真实性仍由宿主批准与原绑定检查证明。

## 准备与授权

所有节点使用原精确包摘要、publisher、version、requires/provides 进行真实核验。首次准备授权、setup 后的异步权限刷新、同步发布栅栏均必须提供；仅凭安装状态、锁摘要或一次旧批准不能获得执行资格。

协调器新增可选 `beforePublication` 钩子，保留原调用者兼容；本执行装配入口强制要求它。钩子只能看到冻结的身份和捕获依赖，不获得 prepared commit/abort 句柄。异步刷新完成后再次检查内存当前性，发布仍由原 NodeHost 的自身栅栏检查实际依赖。任何必需节点失败都关闭此任务装配，不返回半个可运行工厂。

根插件必须实际向原执行注册器注册工厂。提供者可以只提供服务，不要求注册工具工厂；注册器按节点数量有界。工厂查找必须持有实际 NodeLease，身份对象由宿主证明，不能用同形 DTO 伪造。

## 借用与关闭

借用必须给出原完整锁摘要、明确的新执行/历史恢复用途及新的宿主授权。返回的工厂继续执行原注册器的身份、必要服务和租用校验，并额外拒绝不同 tenant/space/profile 的运行上下文及 scope getter。真实 Run、配置、输入、部署、提交/观察权与原外部回执仍是 Worker 的责任，不能因为此处返回工厂就跳过它们。

关闭先停止工厂创建，再撤权与清理依赖图。未释放的根借用保留全部捕获提供者，关闭明确失败，待所有运行器和物理调用结束、借用释放后才允许重试成功。启动清理失败通过原公开 `pluginExecutionPackageFailureOwner(actualError)` 保留真实重试所有者；同文案、同形或包装错误均不获得该所有权。

所有服务仍在明确的可信同进程模式运行，没有增加代码沙箱、替代 Node 运行时或第二套构建系统。装配不签发 HTTP 权限，不启用插件，不派发模型/Comfy 请求，也不向模型注入整图。

## 验证与剩余工作

`InstalledPluginRunContext` 可显式接收只读组合 Store。它先验证真实持久 Run、原准入、回执、配置和根包，再按原引用读取与重新计算锁摘要；tenant/space/profile、原 epoch、修订、摘要及根包全部匹配后，仍须通过现有根任务的当前权限检查才能签发上下文快照。组合元数据只可从该读取器自己的真实快照取出，不加入插件 SDK 上下文或模型历史。普通构造不迁移、不写入、不读取当前 head；未提供只读接口时保持原 v1 拒绝。即使配置了读取接口，现有单包 RuntimeResolver 也明确拒绝此图，不能静默忽略依赖。

真实 SQLite 专项验证新 head 与 epoch、依赖停用后重开数据库仍读取原图；缺失、篡改、替换图和当前根权限拒绝均无法发布新快照；重新授权再次读取原引用。该路径只证明原数据和根权限，尚不证明提供者权限、包代码或真实跨包执行。

真实快照现在还支持 `assertCompositionNodeCurrent`：只接受原根插件及沿原边捕获的提供者，按各自原精确摘要核对同 profile 的持久包，并使用原任务 actor 对该节点独立检查 `extension:run` 或 `extension:query`。提供者没有独立业务配置时不伪造根配置或任务准入；服务包仍须经过该独立权限决定。根任务授权前后刷新，提供者选择在根权限刷新之后再次读取，防止等待期间停用继续使用旧检查。授权结果 getter 不执行，取消不能发布成功结果。

提供者与根插件复用同一选择规则：新提交要求当前 enabled；历史观察可在停用或逻辑卸载后读取原包，但仍须当前权限允许。升级不替换原依赖包；新选择修订不能倒退，原修订下必须仍匹配原 enabled 精确摘要。该接口返回的是核对后的持久包元数据，不能代替 NodeHost 文件核验、publisher 批准或同步发布栅栏，仅开启读取仍保留执行保护；执行需另外显式配置下述组合入口。

## 真实任务签发与 Worker 接入

原 `ExtensionTaskApplicationService` 可显式配置同 Store 的只读 `pluginCompositions.loadCurrent`。仅新安装插件生成任务读取 head，严格核对已认证 pin 的 scope、epoch、根 publisher/version/摘要/选择修订，然后签发原 v1 组合引用。普通任务及未配置组合的安装任务保持 v0；收据重放在读取 head 之前返回原绑定，不按新组合改写。缺失、损坏、根不匹配或存储不支持都明确失败，不静默降级；实际 Turn 提交仍由原同事务准入检查 head 和完整 enabled 向量。

`InstalledPluginExecutionConfig.compositionExecution` 和直接 RuntimeResolver 上的同名配置明确提供宿主实现版本 `hostServiceMetadata`。配置先复制、严格校验、冻结，不能在异步启动时改变版本；没有自动从原锁复制今天的服务实现身份。实际 per-owner 宿主服务必须存在对应版本，执行注册器仍使用已有公开版本常量；版本不匹配交由原协调器拒绝。基础启动不迁移组合表。

实际 Worker 组合函数从自己的原安装 Store 取得只读组合接口，仍使用原 Store、Run 读取器、kernel、工具通道和物理资源管理。装配按原依赖逐包核验持久元数据和文件；根包额外核对实际业务 manifest 与原 Agent materialization，提供者服务包不伪造业务 manifest。每个包在准备和 setup 后刷新自己的当前权限及 publisher 批准，同步发布检查实际身份、描述符和已刷新状态。工厂、后续工具执行、观察、取消与项目服务操作都经过原图全体捕获节点授权。整轮异步授权前后还比较节点选择向量，防止后检查的根插件掩盖先检查提供者的状态变化。

关闭继续先结束实际 SDK 与工具/IO 服务，再释放根借用并清理原提供者。启动失败沿用实际失败所有者和隔离槽，不能把失败清理变成成功。原任务选择停用、新 head 为空及 epoch 变更之后仍可在当前观察权限允许时重建旧图；冷恢复返回未知结果时只观察，不自动重新执行。

真实两包安装、实际 Application 付费任务、原 RuntimeWorker 模型流与持久消息已通过专项验证；模型 transport 是测试适配器，不能当作真实外部模型验收。测试还覆盖原服务调用、节点清理顺序、当前提供者停用、publisher 拒绝、setup 后拒绝、原图冷恢复、新 head 不替换旧任务，以及跨节点等待期间选择变化。没有重新启用用户插件或派发外部请求。
