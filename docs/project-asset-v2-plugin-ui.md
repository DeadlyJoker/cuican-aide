# V2 素材协议与实际插件 UI 调用

2026-10-07，接续[共享采用服务](./project-asset-media-adoption-public-v2.md)。V2 现在提供原 11 个素材动作和生成图采用动作，使用实际 `PluginUiApplicationService` 的安装、选中版本、模块和调用生命周期。当前增量不更新已安装 App 或冻结插件包；正式 Control / Worker 组合、页面、Agent 与恢复日志仍需接线。

## 可变范围与兼容

插件继续仅占用 `main.content` 模块槽位。此增量没有修改宿主主题、侧栏、账户设置或会话绑定，也没有新增独立业务插件。素材服务在插件描述符中只有一个版本声明，不能同时声明相同服务的 V1 与 V2。

V2 保留列表、内容读取、内容候选保存与选中、锁定、概念图参考保存和参考历史改选的原输入语义，新增采用已保存生成结果。公开数据明确区分概念图与生成图来源。解析器复用原版本比较、身份、分页和响应大小校验，内容请求沿用原 24 KiB 上限。旧 V1 编解码和恢复日志保持原行为，不将生成图伪装为概念图。旧 V1 调用尝试选中生成图时会在提交前拒绝，避免提交成功后才因旧响应格式无法表示来源而报错。

## 调用与提交

`PluginProjectAssetV2ActionOwner` 仅接收实际 UI 服务注册的调用对象。复制上下文、已结束调用、其他插件包或不匹配的服务版本均无法获得写权限。授权限定实际安装、包摘要、模块槽位和动作；生命周期关闭会撤回待提交工作。元数据提交不授予 Run、任务或积分权限。

原五个写动作使用明确的 `crewon.project-asset-plugin-commit.v2` 事务证明，保留真实 V2 动作 ID。生成图采用使用原共享采用服务与真实安装信息。所有写入继续交由原 SQLite / PostgreSQL Store，在原连接上校验安装和数据版本。

采用、编辑等写入完成后返回原持久化回执。已提交后发生权限撤回不把成功变成重试信号；读取仍做返回前的权限检查。同一幂等键可在新挂载重放原回执，不重复写入，也不覆盖后来选中的版本。

V1 恢复日志只接受原 V1 动作。V2 不能把自己的请求改名为 V1 或附加 V1 intent 引用。当前已验证调用方保留原请求与幂等键时的重试；跨 App 重启自动发现未确认 V2 操作仍待实现，不能把这次验证称作完整恢复验收。

## 生成图历史切换

实际操作验证暴露出原历史选择仅能验证概念图来源的问题。本增量补齐了生成图来源校验：选中或重放生成图参考时，Store 在同一提交连接读取原保存候选、生成输入、原 Run / operation 历史和输入参考锚点，重新比较完整来源。不能只凭已存参考记录就跳过证明，也不访问供应商或重新下载图片。

修改角色内容后，旧参考仍遵守原内容关联规则；恢复旧内容再改选参考也沿用原规则。来源历史不匹配、版本竞争、锁定或调用撤回均拒绝新提交。图片档案的当前可读性继续由预览与素材准备检查，元数据选择不替代文件校验。

## 宿主可用性

新增显式 V2 可用性组合器，分别询问 V1 和 V2 owner。两种组合顺序都保留原延迟服务能力，关闭一个 owner 不会错误关闭另一个版本，也不会让未知版本或无关服务获得授权。正式宿主还未绑定该组合器，因此当前不会向用户 App 自动宣告 V2 已启用。

## 验证与后续

证据目录：`output/extensions/checks/asset-v2-plugin-ui-owner-20261007/`。使用原安装处理器产生的 T10 结果、实际 UI 调用服务、SQLite / PostgreSQL、原保存候选与原资产存储。UI 包读取器、供应商响应和策略决定为具名测试端口，没有调用真实 ComfyUI。

测试覆盖 12 个 V2 动作、编辑与锁定、概念图和生成图来回切换、失去响应后的同键重试、旧回执不重选、读取时撤权、提交后撤权、SQL 中关闭 owner 的原子回滚，以及 V1 合同、原参考读取与恢复日志回归。

基础新增与回归 117 项通过；随后针对最终兼容修复重跑的 53 项也全部通过，两轮均无失败和跳过。Contracts、Application、PluginHost、RuntimeWorker、ControlAPI 类型检查，仓库边界、格式检查和 7 个桌面运行时构建通过；临时 PostgreSQL 已清理。SDK、冻结插件包与已安装 App 的原文件校验保持一致。
