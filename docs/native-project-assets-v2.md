# 桌面端 V2 素材与已采纳图片复用

2026-10-07，接续 [V2 素材恢复](./project-asset-v2-recovery.md)。此增量将 V2 素材、操作恢复和已采纳图片读取接入桌面 Control / Worker 的现有运行链路。使用同一父 Store、项目、安装版本、原生身份和私有加密归档。

## 配置与兼容

桌面 v3 bootstrap 的 `projects.assetV2` 是明确的宿主配置：

```json
{
  "version": "crewon.desktop-project-assets.v2",
  "publications": [
    {
      "pluginId": "crewon.short-drama",
      "packageDigest": "sha256:<已验证插件包摘要>",
      "contributionId": "workbench"
    }
  ]
}
```

每条发布必须同时存在于 `assetUi` 和 `mediaResults.publications`，并且结果服务包含读取用途。配置限定在短剧插件的 `main.content` 工作台；它不授予生成、网络或积分权限。未配置时仍使用旧素材路径，不推断 V2 能力。只读结果服务继续要求已有结果表，不通过读取权限创建生成记录。

原生启动先准备结果服务，再准备引用它的素材生成服务。V2 UI owner 随后在同一父数据库明确准备采用记录和 V2 恢复日志，注册 12 个素材动作及 3 个恢复动作。旧 V1 owner 和日志并行保留。配置替换、身份变化、安装权限失效和运行时关闭仍会撤销原调用权限。

共享素材运行时提供的内部 `sources` 不再整包传给桌面和 Worker 的严格接口；两处都明确返回 `materials` 和 `close`。这修复了此前内部返回值扩展后导致的桌面启动校验失败。

## 参考图复用

Control 手动输入服务和 Worker 媒体输入工具在配置 V2 时，都按当前已选择的参考版本区分概念图与已采纳生成图。后者读取原数据库中的采用记录；没有此配置时继续拒绝把生成结果当作旧概念参考。

Control / Worker 使用相同的宿主密钥派生规则重新打开原结果归档。专用读取器校验保存的结果、工作流审阅和图片内容，只提供读取与素材冻结用途，不能发布新结果或访问供应商。临时密钥及时清零；关闭或撤销原身份后，已取得的读取器也不能继续读取。
