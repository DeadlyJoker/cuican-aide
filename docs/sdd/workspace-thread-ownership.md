# 工作空间新增与会话归属

## 用户问题与范围

侧栏加号必须新增工作空间；一个会话只有一个持久归属。当前单目录偏好被覆盖、所有会话被归到当前目录、切换目录重启整个任务服务，三者必须一起修复。

本次覆盖桌面安装版：目录注册、选择、线程创建/分叉/恢复、侧栏分组、命令与 MCP 文件工具执行。复用现有 Electron 目录选择器、原子本地存储、Control 线程事件及 Store、tool-broker 与 MCP runtime。不会引入第二套运行时。

## 持久契约与兼容

- 线程增加 `workspaceId: string | null`。创建时固定，分叉继承；改名、归档、恢复、发送新消息均不得改变。原来的 `spaceId` 继续用于租户授权。
- 旧事件、快照缺失字段归一为 null，显示在未绑定工作空间；不得根据当前目录猜测归属。
- 桌面目录登记改为 `crewon.desktop-workspace-authority.v2`：revision、activeWorkspaceId、workspaces（opaque workspaceId、私有 canonical root）。v1 单目录无损迁移。目录相同去重，不以名称去重。
- renderer 状态仅传递 workspaceId、displayName，保持 root 私有。新增与选择分离；取消选择不修改状态；clear 仅取消活动选择。
- registry 限制 100 个空间和 128 KiB。使用已有 CAS 和原子写；路径失效保留记录，执行时明确失败。

## 用户行为

1. 加号打开目录选择器，新增并选中新空间，进入新任务草稿；以前的空间和会话保持原位。
2. 选择已存在空间只改变新任务的默认归属。
3. 打开历史会话时跟随其持久 workspaceId；目录操作和后续执行不得跟随全局活动目录。
4. 空间切换不重启 Control API/Worker，运行中的任务不中断。

## 执行边界

桌面 Worker 从可信 Store 的 run → thread → workspaceId 查找本机 registry，按该空间复用 MCP 与命令 runtime。不会从模型参数读取真实路径或从全局 activeWorkspaceId 猜测。无归属/未知空间的文件工具拒绝执行；普通模型对话仍可用。不同空间实例独立，流恢复和工具重试沿用同一归属。

## 验收

- 新增 A、再新增 B，重启后 A/B 都在；同路径重复选择不新增；同名不同路径各保留。
- A 中新建会话、切 B、回 A 继续会话，归属及执行目录仍为 A；分叉继承 A。
- 在 A/B 放不同内容的同名文件，跨空间并发读取与命令均返回各自内容；切换活动目录不影响执行。
- 旧事件/SQLite 数据恢复后未归属会话保留，不误归到新空间。
- 取消目录选择、CAS 冲突、目录失效、未知 workspaceId 均不丢数据或跨空间执行。
- 安装包验证登录、默认 aicuican 模型实际回复、新增空间、重启持久化。

## 安装验收发现的界面竞态

1. 新会话创建成功后不应再次依赖可被选中会话刷新替换的历史读取。首次发送直接使用刚创建的会话，既有未加载会话仍走正常恢复路径。
2. 列表摘要与详情缓存都必须保留 workspaceId，包括详情被 LRU 淘汰后的摘要；不能等到选中会话才恢复其分组。
3. 原生目录变更后的会话刷新可能被新的选择取消。过期回调不应污染当前状态；普通历史读取失败不应撤销已校验的原生目录操作能力。身份切换及真实原生权限错误仍按原有边界拒绝。

回归覆盖首次发送并发读取、摘要生成与详情淘汰、原生目录变更与会话刷新交错。安装后另行验证新增空间、两个目录读取同名文件、切换与重启后的分组和图片恢复。
