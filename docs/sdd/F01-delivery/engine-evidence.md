# F01 表格引擎支持范围与实际文件证据

2026-09-14。实现为 `packages/artifacts/src/spreadsheet-engine.ts`，遵循 `SpreadsheetEnginePort`。当前高层读取、单元格类型、样式与写入使用 ExcelJS 4.4.0；CSV 使用 csv-parse 7.0.2；公式计算使用 xlsx-calc 0.9.2。fflate 0.8.2 与 fast-xml-parser 5.3.6 用于加载前安全准入及输出验证，没有自定义 OOXML 写入器。验收输入全部为合成数据。

## 格式验收口径调整

依据成熟库复用要求，测试从“输出未修改 ZIP part 字节相等”改为“独立读取确认原数据与格式语义保持”。ExcelJS 可以重排 XML、重建共享字符串和样式索引；这些序列化差异本身不能判断损坏。用户输入原件仍由持久层保留原字节；输出文件必须保留未指定修改的值、公式、字体、填充、边框、对齐、数字格式、合并区域、行列尺寸、人工备注及已支持文档属性。

测试使用独立的 xlsx 0.18.5 读取值/公式/文档属性，并从实际输出文件解析单元格关联的样式语义；没有把新的样式索引或 XML 排版当作预期值。模板增加彩色粗体 Arial 字体、填充、边框、对齐、合并区域和 core 作者/标题/日期属性。Second/Third/Fourth 全部未触及单元格逐项对照。富文本内容与强调格式也在重序列化前后独立核对。

## 已验证的范围

- UTF-8 CSV：全部行与列，BOM、CRLF/LF、引号内逗号/换行、双引号转义、尾部空字段。非法 UTF-8 或不闭合引号拒绝。无歧义且不超过 15 位有效字符的十进制数字转换为 number，前导零和长数字标识符保持 string；空值保持 null。CSV 中公式样字符串保持普通数据。
- 普通 transitional OOXML XLSX：全部工作表和完整选择行；数字、布尔、字符串、共享字符串、内联文本；经测试的单元格样式、基本行高/列宽、合并单元格、人工备注、core 元数据。读取原件不修改字节；输出由 ExcelJS 重序列化。修改合并区域非左上角单元格拒绝。
- 汇集要求显式来源、表头行、列映射、目标 sheet/startRow。目标已有人工内容或公式拒绝覆盖；样式空白单元格可写。重复来源、缺失/重复匹配表头、重复目标列拒绝。
- 可选 rules：精确值排除、必填非空检查、异常原始值、分组汇总、逐行来源 sheet。存在 currency 列时分组必须显式包含该列。缺金额不转成 0；非数值汇总输入和缺分组值进入异常。来源 sheet 记录每条数据行的原 inputId/sheet/row/status 和输出位置，工具验证响应只给计数。`numericTotals` 是机械列合计，附警告，不作为跨币种业务总额。
- 单元格补丁支持值或有限公式，另可选数字格式 `0`、`0.0`、`0.00`。通过 ExcelJS 公开 style/numFmt API 修改；测试独立验证其它字体、边框、填充、对齐等保持。value 仍必须显式给出，不自动改业务数值。

## 明确拒绝的范围

宏/VBA、外部链接或关系、透视、图表、图片、Excel 表对象、计算链、非标准 ZIP part、strict OOXML、工作簿保护/共享编辑、自定义文档属性（docProps/custom.xml）、名称定义、未验证的 worksheet 顶级结构、单元格错误值、数组或共享公式、XML DTD/entity 声明。带这些结构的文件在 inspect 时拒绝，不先改写再提示。高层库生成的未使用 ContentType 默认声明不代表存在实际图形；实际 part/relationship 准入仍检查真实内容。

公式计算由 xlsx-calc 执行；首版准入同表 A1/绝对 A1 引用、普通十进制数字、`+ - * /`、括号和 `SUM`。科学计数法、跨 sheet 引用、命名引用、其它函数、动态数组及库行为未验证的语法拒绝。首版公式引用中的文本/布尔值也明确拒绝，以免库的类型转换与 Excel 语义不同。除零、循环依赖、非数值结果、超深或超预算失败；不采用原缓存继续。输出先计算受支持公式、由 ExcelJS 写入缓存，再重新打开对照文件中的实际缓存与预期值。

## 加载前资源边界

输入 10 MiB、ZIP 展开 64 MiB、最多 256 个工作表、单表 100000 行/256 列。ZIP 逐 entry 预检展开大小；未知或重复 part 拒绝。`spreadsheet-preflight.ts` 在 ExcelJS.load 前检查所有 worksheet 的 dimension 两端、row.r/spans、cell.r/所属 row、cols.min/max、merge 两端，防止极小 ZIP 中的超大稀疏坐标触发高层分配。

ExcelJS 会展开合并区域；即使坐标合法，A1:IV100000 仍会分配约 2560 万格。因此首版将整个工作簿合并区域的展开面积总和限制为 100000 格，并将合并范围数量限制为 1024 个以约束库的两两相交检查，超限返回 `spreadsheet_merge_expansion_exceeded`，不会省略部分区域。行为测试用 load spy 证明非法坐标和超大合并没有进入 ExcelJS；上限内的普通稀疏坐标通过预检。工作簿 sheet 清单也在加载前检查数量与名称/ID/关系唯一性；sheetId 最大 100000，防止其被高层库用作巨大稀疏数组下标。

分页最多 100 行且整个页 JSON 不超过 `DELIVERY_LIMITS.pageBytes`（9 KiB）。页满返回 nextRow，单行超预算明确失败，不裁剪行或冒充完整输入。当前公式准入上限为 128 个公式、每式 2048 字符/512 tokens/64 层括号，全工作簿 200 万引用格；循环访问额外限制由公式适配器执行。来源表同样受行数上限约束，超限失败而不省略来源。
