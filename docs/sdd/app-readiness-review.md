日期：2026-09-14。起始版本 `0638ab701`，界面修复提交 `98f3ea5ca`，独立集成分支 `codex/sdd-integration-20260914`。未合回主分支、未推送、未发布安装包。

## 结论

后续安装验收：已生成 arm64 DMG，并实际安装到 `/Applications/CrewON.app`；首次启动、退出后再启动、包内运行服务生成 XLSX 和重启恢复通过。企业登录后的整页操作、升级安装与 Apple 公证仍未验证，详见 [DMG 安装记录](dmg-installation.md)。下文保留此前界面复核的检查范围。

五项功能已有实现，支持的本地“录制 → 模型整理 → 固定 Skill → 新输入试跑 → 日程交付 XLSX”有真实执行证据。但之前的真实执行脚本替用户准备了任务文件和浏览器范围，不能据此认定普通 App 操作入口完整。本次逐一核对实际界面，发现并修复下列三个入口缺口。

当前可以按 [App 使用说明](../crewon-app-user-guide.md) 试用本地集成版；不声明所有场景无问题或达到正式发布条件。

## 本次修复

| 原问题                                           | 现在的行为                                                                                                             | 验证                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 每次 Skill 试跑直接新建空任务，无法提前放入模板  | 用户明确选择当前任务或新建任务；当前任务已有文件可供试跑使用。文件依赖从真实目录读取并冻结交付目标，日程也沿用选定任务 | 当前任务复用、目录身份错配拒绝、账号切换、不确定请求重试保持原任务；模型整理仍独立任务 |
| 限定范围授权只有后端和展示组件，普通用户无法配置 | 复用授权组件新增网站、动作、控件和值/参数表单；UI 与 Electron 共用范围校验，必须明确授权，scoped Skill 禁止降级        | 有效/无效范围、站点/动作上限、参数校验、范围变化后旧异步回调失效、宿主拒绝越权         |
| 浏览器日程重启后授权失效，无重新授权入口         | 持久日程卡和手动列表新增“浏览器授权”，绑定保存的任务、Skill 版本和审批模式，可授权/撤销/重授权                         | 普通与 scoped 日程、旧 prompt 日程不变、无隐式授权、缺少桌面桥、身份变化、快照         |

本次没有新加运行服务或表格引擎。继续复用 ExcelJS、csv-parse、xlsx-calc、Puppeteer、现有 React 组件、Control 客户端、调度器与授权宿主。

- 根 UI/Electron 类型检查与 TypeScript 入口边界检查通过。构建、格式及最终文件摘要见 [本轮机器记录](evidence/app-readiness-checks.json)。

既有真实模型证据仍单独保留：[日程 XLSX](../../artifacts/f05-real-schedule/second-period-orders.xlsx)、[实际执行结果](../../artifacts/f05-real-schedule/result.json)、[重放核验](../../artifacts/f05-real-schedule/replay-verification.json)、[根文件核验](evidence/scheduled-file-review.json)。本轮修改后的 UI 没有重新执行一次企业环境/人工桌面的全链路模型试跑，不能把旧脚本结果当成本次 UI 全流程验收。

## 尚未完成或验证的部分

1. **单条日程暂停、编辑、删除**：当前 Control API 与 UI 没有完整入口。创建时可以修改参数，交付到明确选择的任务；不能宣称已经支持已保存日程的编辑。禁用 Skill 会影响所有引用它的日程。
2. **范围配置保存**：授权本身按设计不跨重启保存；范围编辑草稿也尚未持久保存，重新配置时需要填写网站和动作。
3. **人工桌面与企业登录验收、安装/升级验收**：仍未完成。不能宣布安装包可发布。
4. **仓库已有架构债务**：此前 package architecture 检查仍有 3 项失败、23 条既有违规，较独立基线没有新增。完整仓库不是全绿。本轮入口边界与 UI 架构回归通过，不代表消除了这些历史违规。
5. **范围外能力**：任意桌面软件示教、多教学浏览器并行、Word/PPT 同等级交付、本机睡眠时执行、云托管、远程/Postgres 新交付不在本轮已验收范围内。

F04-R08 中“编辑参数/交付目标”实际对应创建前选择参数与任务。若按“编辑已保存日程”理解，该项尚未完成；本复核明确这一差别，不用测试通过掩盖产品缺口。
