# CrewON SDD 并行开发总纲

状态：2026-09-14 启动详细设计与开发。产品范围依据[交付与示教路线](../delivery-and-demonstrated-skills-roadmap.md)。当前文档是任务边界与契约基线；各 feature 的详细设计、实现和验收状态由其 spec/design/tasks/evidence 记录，未验收不标为完成。

## 目标与交付边界

让用户把重复的桌面工作教给 CrewON，得到可核对、可编辑、可再次使用的真实成果。第一条验收路径是：多份 CSV/XLSX 与模板 → XLSX 交付 → 定向修改并保存 → 浏览器示范取数生成 Skill → 用新参数试跑 → 添加到现有日程执行。

首发聚焦普通表格和一个受支持的 CrewON 内置浏览器实例。Word/PPT、任意桌面软件录制、行业专属工作台、复杂业务记忆、公共技能市场、无人值守外部发布不包含在本轮。后续格式可以沿用已定义的交付边界。

用户已经授权按 SDD 并行设计开发、创建独立任务。常规设计取舍、实现与本地验证由任务自主完成；无须将 spec 文档交回用户逐项审批。公共契约变更需要内部兼容评审与行为测试；超出本轮范围的决定交回协调任务。

每个 feature 在自己的 worktree 完成 `docs/sdd/F0N-*/spec.md`、`design.md`、`tasks.md`、`evidence.md`。spec 必须先于对应产品代码建立；设计演变先更新设计与任务追踪，再改实现。

详细设计至少包括需求编号、明确非目标、用户路径、现状源码、数据/状态模型、HTTP/事件/IPC 变化、授权来源、存储/版本兼容、失败恢复、有界资源、测试映射和发布条件。任务清单逐项关联需求、源码和证据；模型模拟、组件快照、真实模型 GUI 和跨进程恢复分别记录。

## 开源复用与必要自研

用户明确要求：开发不能纯手写通用能力，须充分利用成熟开源组件来提高稳定性。每个 feature 的 design 增补「复用与自研边界」，优先复用仓库已有可靠实现，再评估成熟开源能力。表格读写、CSV/Markdown/schema 解析、浏览器定位与动作、可访问名称、通用 UI 和时间处理不重复造完整引擎。

选型记录具体版本、许可、维护状态、适用范围与真实兼容验证；锁定依赖并保留升级路径。引用一个底层 ZIP/XML 库不自动证明高层表格引擎无需评估。已有通用自研部分也按此标准复核，需要替换时先保留行为测试，再分模块替换。

自研集中在 CrewON 的业务规则、C01–C05 适配、版本/授权/幂等和成果校验。通用能力必须自研时，先记录成熟方案不适配的具体证据及最小实现范围，由协调任务作内部评审；无需用户逐项审批。不得因此引入第二套 runtime、浏览器或调度系统。当前候选与任务责任见 [复用选型记录](reuse-decisions.md)。

## 共享契约的最小边界

以下是语义基线。具体 schema、枚举和接口由指定 owner 在首轮 design 中完善；其他任务先通过端口和本地契约夹具开发，不复制生产权威实现。首轮只冻结跨 feature 必需字段，避免预建插件平台。

### C01：RecordingExport，由 F02 负责

- 带明确 schemaVersion、recordingId、revision、内容摘要、已授权的工作空间/所有者范围。
- 有序步骤具有稳定 stepId、事件种类、应用/页面定位信息、可解释的操作对象、用户说明，以及按权限读取的证据引用。
- 导航与目标须保留经敏感过滤的可复用 URL/路由模板、角色和可访问名称；敏感值标为运行时参数。来源摘要不能替代导航信息，几何定位图不能代替真实任务关键画面。用户授权录制范围内的普通业务文字可作为任务证据，不一概丢弃。
- 文本输入在捕获源头区分普通值、可参数化值、需要运行时重新提供的敏感值。密码、令牌、Cookie 和未授权后台网络正文不进入可分享录制。
- 关键画面和原始事件分离存储，有条数、时长、单项与总字节上限；暂停、重载、页面跳转、异常关闭不产生伪造的成功记录。
- 导出是数据，不是指令权限；F03 拒绝未知版本与内容摘要不符的记录。跨源 iframe 或不可捕获的动作显式标注，不静默忽略。

### C02：SkillVersionRef / SkillInvocationSpec，由 F03 负责

- 引用的稳定语义为 `skillId + versionId + contentDigest`。`latest` 不作为已保存日程或在途运行的身份。
- 调用配置包含上述引用、声明输入 schema 校验后的参数、所需工具/应用引用和可选 DeliveryTargetRef。凭据仅在执行时按宿主既有授权解析，不嵌入 Skill 正文或日程参数。
- 可移植 SKILL.md 表达用途、方法、输入/输出、完成标准和已知异常。宿主管理所有权、不可变版本、草稿/试跑/激活状态与证据，不以文件名存在视为已验证。
- 草稿可编辑；发布/激活生成不可变快照；旧任务保留旧绑定。删除或撤权阻止新执行，历史记录仍按原版本展示。
- 单个用户 Skill 以至少一次新材料的真实试跑及实际结果核对支持确认激活；多日期和异常场景属于产品发布验收与覆盖提示，不要求用户每创建一个简单 Skill 都完成多套强制测试。
- 试跑使用真实现有 Run 路径。只能模拟依赖端口来验证边界，不能将假模型结果标为可用技能。
- F03 提供最小解析/执行准入端口供 F04 使用，沿用既有 AgentVersion、工具和上下文边界；不修改历史，不加入超过 10K tokens 的模型片段。
- 准入须绑定或校验既有 routeResolver 解析的 RunRoute/AgentVersion，避免 Skill 的工具需求与实际执行主体不匹配；有界上下文使用确定规则生成，供持久化层独立重算校验。

### C03：DeliveryTargetRef / 交付结果引用，由 F01 负责

- 交付目标以受授权工作空间与输出位置身份表达；客户端路径或模型声称的文件名不能自行获得读写权限。
- 结果至少可定位逻辑交付物、不可变版本、内容摘要、媒体类型、来源 Run 与可读取状态；供 F03/F04 引用的身份不得依赖本机 blob 绝对路径。
- 工具输出 Artifact 和用户保存交付文件的保留策略单独评审；旧 toolOutput 记录保持可读，不能因为任务输出过期而悄悄删除用户保存成果。
- 定向修改带被编辑版本的预期身份；不匹配时返回冲突，不能覆盖用户已保存的更新。校验结论不能代替真实文件。

### C04：日程兼容，由 F04 负责

- 继续使用当前 AutomationDefinition、scheduler、invocation、Run 与运行历史权威链路。
- 现有 prompt 日程无需迁移即可读取和按原语义执行；Skill 绑定采用显式可区分的版本化新增结构，不把不可验证 JSON 藏进 prompt。
- 保存和实际触发时均校验 Skill 的可用性、参数与权限；触发时固定调用快照，版本更新不会改变在途运行。
- 周期日期支持最小显式规则（运行日期、上一完整周起止），按 occurrence 时间与日程时区解析为 C02 的具体参数；同一 occurrence 重试保持相同参数。保存时固定技能版本与规则，实际调用固定已解析值，不把创建当天日期永远用于后续周期，也不新增任意表达式引擎。
- 缺少 Skill、撤权、版本摘要变化、工作空间离线、超出预算、执行结果未知有明确状态与后续动作。重试不盲目重复已成功的外部效果。
- 复用现有时区、重复触发去重、取消、恢复和通知语义。按已通过验证的宿主能力执行，不承诺本机睡眠期间仍运行。

## 并行与集成规则

1. 每个任务一个独立 worktree 和 `codex/` 分支；原始工作目录中的未提交改动全部保留。公共开发基线以协调任务记录的隔离快照 commit 为准，快照不代表原工作区已通过验收。
2. F01/F02 独立推进。F03 可用 C01 的受控样本推进；F04 可用 C02 的端口夹具推进。使用夹具只表示本任务边界测试通过，产品闭环仍须集成真实上游。
3. 跨任务契约变更先发送具体差异、兼容影响和受影响需求给协调任务及 owner。接收方无须等待用户作常规技术决定；协调任务裁决冲突并同步版本。
4. 新逻辑尽量放独立模块。`control-api.ts`、`main.ts`、UI App/shell、包 entrypoint、lockfile 等公共入口只做最小接线，记录变更，集成时按语义合并。
5. 不修改其他 feature 的实现来解除自己的测试失败。依赖尚未具备时完成独立任务与接口测试，清楚列出需要的 commit/契约；不可把未接线功能标记完成。
6. 不依赖 task 的 cwd 字符串获得跨任务权限。跨 worktree 仅只读参考或引用已提交依赖，产品代码仅写自己的 worktree。
7. 本地提交只包含自己的 feature 变更。合并/发布到远端不是本轮自动动作；协调任务负责后续集成评审和验收。

## SDD 阶段与推进条件

| 阶段              | 必须产出                                     | 如何进入下一阶段                                                 |
| ----------------- | -------------------------------------------- | ---------------------------------------------------------------- |
| S0 现状与需求     | 有源码依据的现状、编号需求、非目标和验收例子 | 不确定项有调查任务，范围无冲突                                   |
| S1 详细设计       | 状态、契约、兼容、恢复、UI 路径、测试映射    | owner 完成自检，跨任务契约由协调任务确认；无冲突独立部分可先实现 |
| S2 行为测试与实现 | 有意义的失败用例、最小完整实现、需求追踪     | 本 feature 的窄检查和相关 UI/运行时检查通过                      |
| S3 集成与验收     | 真实上游接线、GUI 流式/恢复及失败证据        | 用户路径完成，兼容通过，未知项显式保留                           |

本轮每个新任务的目标是推动自己的完整 SDD feature 至可集成状态，不仅写完设计就结束。先把 S1 文档与依赖清单报告协调任务，再继续独立实现。遇到上游依赖时回报并完成无依赖工作，不重复轮询或伪造成功。

## 全链路验收

- E01：多份表格完整读取，输出真实 XLSX，行数、汇总与排除项可独立核对；异常数据不擅自补全。
- E02：人工修改后继续定向修改，原修改保留；版本冲突可见；任务切换或刷新不串文件。
- E03：录制浏览器筛选与下载，用户能删去无关步骤；敏感输入不出现在导出与 Skill。
- E04：生成 Skill 后换日期与输入试跑，能定位正确元素并完成文件交付；未知动作明确需要人工处理。
- E05：同一 Skill 添加到现有日程，到点使用固定版本和参数执行，结果进入现有运行历史；旧 prompt 日程保持兼容。
- E06：运行中断、重启/重连、撤权、取消与未知外部结果保持一致状态，不重复写入。

每个 feature 在 evidence 中分别记录合成/模拟与真实模型运行；缺少真实环境的项目保持“待验收”。禁止用单元测试或成功编译宣称端到端可交付。依照 AGENTS.md 使用 Node 24、pnpm 10，完成相关契约、边界、类型、组件快照与 GUI 检查；文档额外检查 `docs/sdd/**/*.md`。
