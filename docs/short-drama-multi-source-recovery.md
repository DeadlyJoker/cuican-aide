# 独立短剧 10.0.0：逐条处理不同来源的原请求

日期：2026-10-04。此次增量只修改独立短剧插件及其测试，沿用冻结 SDK、Host 三类原请求上下文和已有公共动作。原 App、账户、设置、左右侧栏和共享 CSS 保持不变。

## 问题与交互

生成、查询和选用可以各自保留一条结果未知的请求。它们来自不同保存输入时，原恢复协调器禁止自动采用任何一个来源；所有重试也被互锁，用户无法解除冲突。

10.0.0 在插件内列出最多三条原请求。点击“查看原输入”只读取该请求的已保存来源；随后单独点击“重试这条原请求”，才调用原通道的重试方法。整个原请求保持不变，包括幂等键、输入修订、全部旧 CAS、原线程及版本、operation 和图片原始索引。其他未知请求保留，新编辑、项目写入与导航继续锁定。

第一次发现来源冲突后，手动处理状态保持到全部请求确认。剩余请求缩为一条也不会自动采用它的输入。Host 提示变化或 ready 撤回会撤回本次本地选择并取消来源读取；迟到回复不能替换后来的明确选择。重新挂载保留 Host 原请求，但不继承本地选择。Host 不允许重试时可以查看原输入，不能重放。

## 在途门禁

实际业务调用、来源读取、当前选用读取和元数据写入未结束时，禁止切换与重试。最后一条请求先收到 accepted 提示，也要等原调用返回后才能编辑或导航。

SDK 的取消会立即结束 UI 等待，原 Host `invoke` 可能仍未返回。插件因此在挂载内跟踪八类已有写动作的原 Host Promise：五类项目/输入元数据写入，以及生成、查询和选用。取消不清空计数；实际 Promise 完成才释放门禁。通知异常不替换原 Host 结果，卸载只断开界面通知，迟到成功或失败仍被观察。

这是单次挂载内的物理调用门禁。跨卸载、重挂或进程重启的恢复及授权仍由真实 Host journal 和原准入负责，不能把此计数当成新的持久协议或权限。
