# 可安装插件协议与实施顺序

日期：2026-10-03。状态：包描述、可分发 SDK、本地目录安装、持久安装组合及可信 Node/UI 加载基础已实现，仓外构建的独立 UI 包已通过实际浏览器加载验证；安装与 UI 的公开 HTTP/客户端/BFF 链路及本地 Node/纯 UI 选择恢复已通过实际验证。原页面现已接入同源 Web 的已安装模块目录、导航和挂载生命周期，保留改造前样式。生产已安装 UI 启动、PostgreSQL profile 拥有权及内部原 Run 的包版本/个人积分原子准入现已实现；SDK 任务调用引用、实际 Node 动作到原任务的准入桥及已提交 UI 回执语义已有行为验证。生产安装与动作桥 main 装配、安装管理页面、SDK 执行工厂、Worker 按包执行及短剧包迁移尚未交付。用户已明确插件必须可插拔，能够独立开发后安装；原 E0–E5 的随宿主发布试点继续保留，但不能作为此目标的验收。新的安装步骤优先于继续把短剧界面写进宿主。

## 交付目标

开发者在独立目录或仓库，仅依赖公开 SDK 开发业务代码、外部 API 适配器和界面，构建预编译插件包。CrewON 校验并安装该包，加载声明的贡献点；无需修改 `apps/**` 的插件分支、复制源码进宿主或重新编译 CrewON。启用、停用、升级、回滚及卸载有实际行为，原首页、聊天、团队及用户数据继续可用。

第一条分发路径是本地预构建包，支持自研可信 TypeScript/Node ESM 实现，使用现有 Node.js 24 和 pnpm。插件市场、npm 自动发布和任意不可信 Node 执行不作为本地安装前提。安装不运行包中的构建或生命周期脚本，构建由开发者在包外完成。源码包缺少构建产物时明确拒绝。

DSH 的分发对象是带配置层的 npm bundle，运行对象是记录有序 bundle 的 profile；独立包通过插件入口、服务依赖和注册生命周期参与组合。CrewON 借鉴包与组合分层及服务契约，保留已有执行和权限架构。[DSH 打包与安装](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)、[服务与依赖](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/service.md)。

## 协议层次

| 层       | 必需内容                                                                               | 责任                                             |
| -------- | -------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 分发包   | 包协议版本、插件身份与版本、宿主 API 兼容声明、预构建 Node/UI 入口、文件清单及完整摘要 | 开发者产出，安装器逐项核验；入口必须在包内       |
| 业务声明 | 输入输出 schema、配置及凭据槽、具名操作、页面/设置/结果贡献、申请能力                  | 注册与运行校验，不等于已获授权                   |
| SDK      | 类型化服务端口、插件入口、注册句柄、生命周期及 UI 动作桥                               | 独立开发只能依赖公开 API，不能导入宿主内部文件   |
| 安装组合 | 精确包版本及摘要、依赖锁、可信来源、安装状态、选定版本                                 | 宿主持久化，不能靠浏览器状态或可变目录表示已安装 |
| 执行绑定 | 实际包/依赖、业务配置、Agent 版本、权限及价格修订、任务输入身份                        | 服务端锁定；任务与积分继续原事务准入             |

包描述采用 `crewon.plugin-package.v1`，与既有 `crewon.extension-manifest.v0` 分层。现有[纯描述契约](../packages/contracts/src/plugin-package-contract.ts)通过 `@crewon/contracts/plugins` 导出，核验 Node/UI 入口、服务依赖及提供声明、贡献和产物清单，只证明元数据合法，不证明已安装、文件真实或服务已就绪。不能修改 v0 的摘要配方、配置解析或历史运行绑定来装新包；旧版本仍通过原适配层可读、可查询和可恢复。SDK 与新的加载协议通过独立入口导出，不把应用内部组件变成开发者 API。

## 入口与可变范围

服务端插件声明所需服务并注册自己的操作、业务命令、查询和工作流。宿主在依赖及配置校验后创建实例，提供已授权的窄服务；缺失依赖保持不可用，不用全局空对象伪装就绪。注册返回可清理句柄，启动失败撤销本次部分注册；停用先撤销新准入、界面和业务订阅，在旧 Run 的执行实例租用释放且原 ToolRuntimePort 可安全退休后，再清理其实例资源。插件之间通过具名版本化服务协作，不依赖安装顺序覆盖别人的实现。

SDK 的公开入口分为 Node 生命周期、UI 生命周期和不含 Node/DOM 依赖的纯契约。Node 入口声明依赖并实现实例启动和清理；UI 入口实现 `mount(root, props, services)`、投影更新和卸载。SDK 发布编译后的 JS 与 `.d.ts`，不能让仓外开发者依赖目前 private workspace 包的 TS 源码导出。调用范围由宿主签发或当前 UI 会话派生，插件不能任填 actor 获得授权，也不能在实例启动时把整个插件固定绑定某个用户。

界面插件可以独立构建复杂列表、表单、分镜编辑器或工作台，贡献到主内容区、设置页或结果视图。宿主加载实际 UI 构建产物，管理入口、导航、身份及生命周期，并提供主题 tokens、当前业务投影及窄动作桥。安装前后全局 shell 与主题不被替换。可信自研 UI 可使用公开组件/样式 API，共享宿主 React 实例；模块样式受自己的根节点限定。不能通过导入 `CommandWorkspace`、`App` 或全局 CSS 取得业务功能。

第三方 UI 使用隔离 iframe/webview 和版本化消息桥，不取得宿主 DOM、Node、原生桥或任意文件与网络能力。自研 Node 模块的可信加载与第三方隔离模式明确分开；同进程可信 Node 代码继承该进程的 Node 权限，窄 SDK 是公开 API 边界，不是安全沙箱，浏览器隔离也不能证明 Node 代码已隔离。未知模式或未实现的能力拒绝启用，不悄悄降级为更高权限的可信加载。

账号、租户、权限、原任务与 SSE、幂等与恢复、凭据管理、个人独立积分账本都属于宿主。插件可以提供业务规则和价格规则，调用者、付款人和最终结算依据仍来自当前服务端授权与已确定的产品规则。插件内的项目数据通过所属命名空间与公开存储服务操作，迁移通过宿主端口管理，不能交出整个数据库连接。

## 安装及版本生命周期

安装依次进行包解析、字节/文件数量上限、路径和链接检查、完整摘要、宿主兼容、依赖与贡献冲突校验，再把已核验产物落到宿主拥有的不可变版本目录。拒绝路径穿越、包外引用、未知协议、重复贡献和不完整构建。预检和实际加载之间再次核对身份，失败不替换原激活版本。

安装、授权、选定版本和执行健康分别记录。停用立即阻止新操作并撤下界面入口；在途任务按已锁定版本的原恢复与撤销协议收尾。被任务引用的旧包保留，卸载不会删除项目、素材或积分流水。历史缺少专用视图时保留宿主基础展示。

升级先安装及预检新版本，再切换后续任务的选定版本；旧任务不跟随最新版。回滚先核对旧包是否兼容当前业务数据 schema，不兼容时拒绝回滚，不自动逆向迁移。合法回滚只改变新任务使用的版本，不回退已发生的外部副作用。首版可以在必要时重启 Worker 激活新执行包，不承诺 Node 模块缓存的任意热替换；UI 入口与新操作资格的停用仍必须及时生效。

## 实施顺序与验收

1. **协议与 SDK**：包 schema、入口及生命周期、服务依赖、贡献点、兼容标签和错误码；提供可编译的仓外开发模板与契约测试。
2. **实际安装与加载**：本地包预检、不可变版本目录、持久安装组合、加载 Node 入口、原子注册及失败清理。坏包不得影响已有插件或激活版本。
3. **独立 UI 加载**：读取已授权目录、加载包内界面、挂在现有内容区；主题继承、卸载清理与复杂编辑器用例通过。当前静态 ReactNode 预览仅为界面参考。
4. **迁移调用试点**：将 Krea2 固定装配放进第一方插件包，通过同一公开 SDK 使用原 Tool/Run/operation 路径；短剧业务界面作为独立包接入，保留原 v0 查询与历史绑定。
5. **可插拔端到端验收**：在宿主仓外构建第二个具名插件，安装后出现实际页面与操作；停用撤入口和新操作，升级后旧任务仍恢复原包，卸载保留记录。所有步骤不修改宿主业务源码或重编译宿主。

SDK 类型、manifest 校验或安装按钮单独通过均不能称为“支持独立插件”。须完成第 5 步的实际证据。第二个安装测试包也不替代 E5 所需的第二个真实企业服务接口验收。

## 当前实现与下一步

[`@crewon/plugin-sdk`](../packages/plugin-sdk/README.md) 的 `0.1.0` 本地分发提供 `/contracts`、`/node`、`/ui` 三个明确入口；ESM JS 和声明闭包随包提供，不含私有运行时依赖、宿主源码或 React。Node 定义和 UI 定义的校验不会调用业务代码。SDK 已通过真实仓外安装、Node 专用无 DOM 类型编译和 UI 类型编译；UI 的 `mount/update/dispose` 已接到通用加载器及实际安装目录浏览器夹具，尚未迁移正式短剧页面。

私有 [`@crewon/plugin-host`](../packages/plugin-host/src/index.ts) 接收预构建目录，核验全部实际文件与 SHA-256、目录边界及限额，拒绝链接、非普通文件和未声明文件。宿主明确批准后，以独占 staging、同摘要锁和原子发布安装到 `packages/<完整摘要>`。不运行构建脚本，不从源码包自动安装依赖；开发者需将 SDK 和运行依赖构建进声明的产物。业务 `.tgz` 解包输入、正式安装页面和生产信任策略仍待接入。

Node 加载只接受安装根目录与预期身份/摘要，在授权和依赖检查之后才导入固定版本路径。实例提供服务的注册原子发布，失败清理本次注册；停用会撤销启动中或排队的激活与新借用，已有借用保留确切版本。升级失败或依赖闭包将经过待撤旧实例时，保留原选择；清理失败保留诊断和依赖借用。这证明通用实例与服务的生命周期基础，不能替代原 Worker 的 ToolRuntimePort 安全退休、持久 Run 绑定和进程重开恢复。

仓外验收夹具已实际打包 SDK、安装到独立临时项目、严格编译并 bundle 插件、安装预构建目录，然后删除全部开发目录及依赖，再由 NodeHost 加载、调用、停用和清理。该仓外证据仅覆盖 Node 包路径，随后增加的持久安装基础见下文；完整目标继续要求生产兼容治理、授权 UI 目录及动作桥、Krea2/短剧生产迁移、原任务恢复和卸载保留业务记录。

新增内部安装领域与 SQLite/PostgreSQL 账本，独立记录不可变包身份、每个 tenant/space/profile 的当前选定版本、CAS 修订与幂等回执。第一次安装保持停用；安装新版不自动替换正在使用的版本；启用、停用、切换和逻辑卸载分别提交新修订。发布者命名空间永久绑定，版本与摘要不能重绑定；回执重放返回原快照，不重新安装或激活。卸载保留包、项目、修订及积分流水。独立 schema 不改变原任务、extension v0、创作项目或积分协议。

`PluginInstallationApplicationService` 要求真实宿主 profile 与授权端口，从受控 source ID 安装，客户端不能指定文件目录、租户或摘要算法。选定版本先 prepare，再重新核对身份与权限，以 CAS 提交数据库，最后同步发布。Node `prepare/commit/abort` 暂存注册，不提前替换当前服务，撤销只清理本次候选；升级仍保留旧借用，正在被消费者依赖的提供者不支持直接替换。数据库已提交而本地发布失败时返回 `plugin_projection_pending`，不回滚已确认的选择，也不通过旧回执重放激活旧版本。

私有 `LocalPluginInstallationHost` 已将上述服务与真实安装目录和 NodeHost 接通；它只协调一个本地 profile，必须注入当前授权、数据/运行兼容检查和持久选择的同步提交核验。实际 SQLite/文件/ESM 集成验证安装不执行、删除开发源后启用、升级/回滚、旧借用、事务失败、提交后发布失败及卸载保留真实项目和个人积分。已安装选择恢复通过真实数据库重开和安装目录验证，不修改原修订、审计和回执；支持带 Node 入口及纯 UI 包，依赖和权限预检失败不导入代码。纯 UI 包不启动 Node 实例，也不允许声明 Node 服务依赖或提供项。该证据不等于生产治理或分布式协调。跨进程同步、生产启动装配、在原 Run 事务内核对选择、原 ToolRuntimePort 安全退休、正式安装页面仍需后续实现；此阶段不能宣称完整插件产品已交付。

独立 UI 基础由严格 `crewon.plugin-ui-lease.v1`、`PluginUiApplicationService`、私有 `LocalPluginUiPackageReader` 和 Renderer 通用挂载组件组合。宿主从当前身份解析 profile，以独立 UI 授权及权限 epoch 核验目录、挂载、资源和动作；挂载引用不构成授权。清单只公开宿主显式批准的文件，实际读取复查完整安装包与文件字节；安装权限不等于 UI 执行权限。异步前后检查当前作用域、修订和权限，观察到撤销后的引用不因回滚而复活。引用数量、TTL、输入输出及并发动作均有上限。

通用加载器只支持可信 `trustedModule` 的主内容模块，原生加载固定同源产物 URL，支持声明的相对 chunk。隐藏模块不执行导入或动作；退出、更新、替换和卸载分别处理自己的生命周期，清理失败保留诊断。原宿主导航与全局样式不变。可信 UI 与普通 Renderer 同权，根节点样式约束不是安全沙箱；原生导入没有逐入口 SRI，且已经开始的导入不能取消。未实现的 `isolatedWeb`、设置和结果模式保持拒绝。

[仓外 UI 浏览器夹具](../artifacts/installable-plugin-ui-preview/README.md) 实际安装两个版本并删除开发目录，验证原生入口及相对 chunk、v1/v2 Node 动作、投影更新、退出与重挂、停用及授权撤销。夹具使用固定测试身份和显式测试策略，不代表生产认证、正式可见目录或收费调用。下一步仍是将这些端口组合到原宿主生产身份、权限和安装流程，再迁移 Krea2/短剧及原任务执行绑定。

公开 `/api/v1/plugins` 与 `ControlApiClient.plugins` 现已通过 BFF 和实际 Control HTTP 集成。复用原会话、可信 BFF 与当前用户令牌，严格校验请求和脱敏回执；独立 UI 目录、挂载、资产与动作逐次核验当前 profile、选择及权限。安装使用受控 source ID，接口不接收客户端目录或身份。Web 同源资产保留实际 MIME 与有限字节，取消、期限和原始路径检查均有覆盖。原 `App` 的模块目录使用当前客户端与会话，按完整包身份挂载；目录更新保留未变模块，退出、版本撤销及账号变更清理引用。生产 main 现可显式装配 UI 读取服务，真实 HTTPS 权威及 PostgreSQL 组合有独立行为验证；安装与业务动作仍未装配。Electron 的 `file://` 原生导入也需要专门宿主资产端口，不能将 Web BFF 测试作为桌面认证加载验收。

原 Run 的内部安装包路径通过 `createTaskFromPlugin` 增量接入，独立记录 v1 包/profile/选择及调用来源，原 Turn/Run、v0 binding、个人报价预留及回执在同一事务提交。旧摘要和 HTTP DTO 不变，新路径缺真实报价或存储能力时拒绝。PostgreSQL profile owner 与提交中的选择行锁分别处理安装投影和 Run 准入，拥有权不等于当前权限。SDK `crewon.tasks` 与私有 `PluginTaskActionBridge` 现已通过实际安装 Node 包调用该路径，按真实实例绑定有界调用引用，提交前复核插件当前权限，提交后只用原账本的受理回执返回结果。首个生成包 ID 必须与 extension ID 一致，没有跨插件委托。生产 main、SDK 执行工厂、按包执行的 Worker 和 v1 历史冷恢复仍未完成，不能将准入测试作为步骤 4 的全部验收。配置与现状见[服务启动说明](./installed-plugin-service-startup.md)。
