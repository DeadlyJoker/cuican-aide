# Run 的原插件组合绑定

本页记录基础建设中已接入的协议与存储边界，配合[DSH/Cordis 分析](./dsh-plugin-foundation-review-20261009.md)、[依赖协调设计](./plugin-dependency-reconciliation-design.md)。业务插件保持卸载。本实现尚未签发生产 v1 任务，也没有将多包图交给运行器执行。

## 版本与兼容

`crewon.extension-run-binding.v0` 的字段集合和标准化摘要配方保持不变。它不带组合字段；不能通过额外字段把旧绑定升级为组合任务。解析器拒绝未知版本、缺失引用、降级后残留的组合字段、整图注入及访问器，完整绑定仍受原 8 KiB 限制。

相邻 `crewon.extension-run-binding.v1` 保留原 tenant、space、plugin、Run、会话、actor、配置、目标、输入和 source 字段，额外加入以下严格引用：

| 字段                         | 含义                                      |
| ---------------------------- | ----------------------------------------- |
| `composition.profileId`      | 原装配 profile，不能借其他 profile 的选择 |
| `composition.authorityEpoch` | 原锁记录的宿主 epoch，不是当前权限凭证    |
| `composition.revision`       | 原组合修订，正安全整数                    |
| `composition.lockDigest`     | 原完整锁摘要，不保存服务对象或代码路径    |

上述引用全部参与 Run 绑定摘要；复制冻结输入后保存，不将最多 512 KiB 的整图放进绑定或模型上下文。原配置摘要、执行目标和真实用户输入仍按原规则验证。

`ExtensionStore.compositionBindingVersion` 仅声明存储/准入接口支持，不表示服务可用、Worker 可装配或插件已获授权。组合表迁移必须显式调用安装 Store 的 `compositionStore().migrate()`；普通构造和基础启动不执行迁移。当前真实用户库尚未执行本迁移。

## 新生成任务的原子准入

SQLite 在原 `BEGIN IMMEDIATE` 事务内，PostgreSQL 在原 Turn 使用的同一连接内完成校验与保存，不借第二连接，也不事后给已派发 Run 补图：

1. 严格解析 Run 绑定及原任务/积分准入；任务 pin 的 profile 和 epoch 必须与引用一致。
2. 读取指定原锁，重算摘要，核对 tenant、space、profile、epoch、修订、摘要和根插件节点。
3. 新任务的引用必须等于当前 head；核对全部 enabled 选择的数量及每个节点的 publisher、version、packageDigest、selectionRevision。根节点版本还必须与绑定的原配置一致。
4. 继续原有激活、部署、权限、项目来源及模型选择校验；存储中的自声明身份不能替代这些权威。
5. 用户消息、历史、Run、包含引用的绑定、工作项、回执和积分预留沿原事务一起提交。任何失败均回滚；已在此前独立确认的组合锁不会因任务失败而被删除。

读取文件、核验声明真实性、来源批准、服务就绪和执行权限仍由宿主负责。此处只保证保存与选择快照的一致性，不能把元数据保存成功显示为插件已可运行。

## PostgreSQL 的快照栅栏

原 profile 所有者持有长期独占 session lease。任务读取不能去争用这一租用，否则自己的运行器会一直等待 profile 释放。因此新增不同键的事务共享/独占锁：任务先取得共享快照锁，安装选择和新组合提交先取得独占快照锁，然后取得原行锁。现有 profile lease、命名空间及 actor/tenant 隔离保持。

显式组合迁移同时安装 enabled-entry 触发器：即使旧写入方尚未调用新辅助函数，把新行或原 disabled 行变为 enabled 时，也必须等待同一快照键，防止数量检查之后出现幻影节点。原 enabled 节点的修改则受任务已取得的原精确安装行共享锁保护。数据库和调用方都用 PostgreSQL 生成的同一 JSONB 键表示，不依赖两种 JSON 序列化的空格差异。

新准入检查该触发器的表、事件、启用状态、精确函数体和原会话触发模式；只有旧 v1 元数据表、缺失/禁用或被改变的栅栏都不能授予新准入。历史记录仍可按原摘要读取。该 PostgreSQL 路径已加入真实数据库用例，当前未配置测试连接，因此尚未完成实库验收。

## 历史读取、重放与运行器

已提交的 Run 和回执读取自身引用的原锁，重新校验摘要，不看今天的 head 或选择。升级、停用、新 epoch 或新组合不能改变其绑定。原请求重放返回原消息、Run 和积分预留，不再次派发，也不重复扣留积分。历史读取成功不表示允许执行；当前宿主必须另行重新校验历史恢复权限。

现有 `PluginExecutionPackage` 仍是每包私有 NodeHost，不能提供整个历史图。因此已安装 Run 上下文、旧 Comfy 运行器和旧查询可用性宿主明确拒绝 v1 执行。旧查询准入也不能把 v1 来源降为单包 v0 查询。v0 的原执行、观察、撤权、关闭和恢复路径保持。

当前 v1 只接入新生成 Turn 的存储准入；组合查询协议、生产入口签发、精确历史依赖装配和 scope 内协调器仍待实现。这些拒绝是阶段性保护，不是最终的组合运行能力。未知 Comfy 操作仍只读取原回执，不能因插件更新而重提。

## 验证范围

真实 SQLite 的两包依赖图覆盖原子付费准入、并发重放、重新打开数据库、依赖停用、重启用后的修订不匹配、额外 enabled 节点、过期 head、伪造 epoch、根版本与配置漂移、绑定写入故障及原锁篡改。已提交的任务在 head 切换后仍读取原锁且保留一份消息和积分预留。

协议测试覆盖摘要中的全部组合引用、原 v0 字段集合、缺失/降级/额外字段及 getter 拒绝。运行器测试验证 v1 拒绝发生在私有包执行或外部 Comfy 派发之前；它们不证明跨包流式执行或恢复已经完成。PostgreSQL 对应准入用例以及实际 owner、旧 enabled-entry 写入的快照栅栏用例受测试连接条件限制，跳过不能算通过。
