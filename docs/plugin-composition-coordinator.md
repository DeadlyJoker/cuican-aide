# Profile Node 插件协调核心

`PluginCompositionCoordinator` 从原 `@crewon/plugin-host` 公开入口导出，复用真实包核验、NodeHost、prepare/commit/abort、资源归属与借用，不增加运行时或构建系统。它执行已验证的组合变更规划；生产选择监听及正式桌面批准适配尚未接入；历史 Run 装配现已由显式 RuntimeWorker 入口复用，不能把这个类视作桌面已启用自动协调。

## 归属与输入

每个协调器拥有独立 NodeHost，固定一个 tenant、space、profile、authority epoch、宿主安装根和宿主服务实现集合。来源是宿主身份与配置，不由插件选择。组合锁必须严格匹配这些值；不同账号、profile、epoch、宿主实现或过期修订拒绝进入队列。宿主服务更换需要新协调器及其新权威生命周期，原实例先撤权并等待旧借用释放，不能仅修改元数据替换服务值。

输入锁在异步排队前复制冻结。队列最多 64 个请求，原锁至多 64 个插件；旧 NodeHost 的实例、资源和服务限制保持。较新的请求使未完成的旧请求失效；`revoke(pluginId)` 同步撤权并使待发布请求失效，不会因随后提交相同锁而漏掉这次撤权。

`synchronize` 必须显式提供宿主的异步准备授权与同步发布授权。它不是插件自签接口：调用方仍须读取真实 Store、批准、选择修订和作用域，发布回调必须实施同步当前性栅栏。锁摘要与内存 generation 都不能替代持久权威。

新增相邻可选钩子 `beforePublication`，在实际 setup 后等待异步当前权限读取，然后再检查 generation 和同步发布栅栏。原无钩子调用兼容；[原任务执行装配](./plugin-execution-composition.md)强制提供该钩子。

## 实际执行顺序

1. 严格解析锁、检查身份和固定宿主服务，规划受影响集合；按旧图撤下消费者和提供者。
2. 撤下立即阻止新准入与发现，取消资源获取；旧借用保留原实例及其捕获的依赖。等待当前可执行的清理，不能把清理失败当成成功。
3. 按新图先提供者、后消费者准备真实安装包；核验实际 publisher、version、digest、完整 requires/provides，禁止自声明图伪造包身份。
4. 核对实际捕获的依赖与锁中的精确提供者、版本、摘要及可选缺失；准备后和发布回调前后都检查 generation。发布仍使用原 NodeHost 的自身依赖和实例栅栏。
5. 保留的实例也重新核验文件及两道授权；原 NodeHost 的相同包 prepare 复用实例，不再次 setup。授权拒绝撤下该实例及其消费者，不能因图没变而保留失效授权。
6. 单节点失败仅记录固定错误码，独立分支继续。清理失败中止整个协调结果；后续请求也不能跳过该失败。服务缺失的消费者保持不可用，显式重新同步且新授权通过后才重新准备。

结果区分原锁摘要、实际 active 节点与失败节点。它不发布 UI，不声称保存配置等于就绪，也不将异常消息、凭据或整图注入模型。

## 借用与退出

`acquireCurrent` 要求当前锁摘要、精确节点和新的宿主借用授权；协调中拒绝新借用，授权回调前后均检查 generation，防止回调重入更换期望图后仍签发旧租用。已取得的原租用不被新图重绑。

`close` 同步撤权、等待排队及物理工作、调用原 NodeHost 关闭。借用未释放时明确失败，释放后可以再次关闭；清理失败始终保留原失败，不能声称已卸载干净。没有提供“按今天的选择恢复旧 Run”的接口；未配置组合执行的 v1 Run 仍由原拒绝路径保护；显式 Worker 入口使用独立历史图、原任务引用和当前逐节点重新授权。

## 从安装事实发布期望图

`publishInstalledPluginComposition` 沿原 PluginHost 公开入口提供宿主装配步骤。输入包括宿主固定的 scope/epoch、actor、安装根、宿主服务身份，以及实际安装 Store/组合 Store 和宿主快照批准策略。开始异步读取前复制冻结 scope 与服务声明；不接受调用方直接传插件节点列表。

函数分页读取实际选择，只将 enabled 的精确包纳入图。每个选择与保存的包记录均重新解析并核对 tenant/space/profile、publisher、plugin、version/digest，随后用原文件核验器读取内容寻址安装目录的完整文件；requires/provides 从实际包描述符提取，不运行入口或作者构建脚本。最多扫描 1024 个选择、纳入 64 个节点，分页必须按 pluginId 严格前进，沿用原图/文件容量限制与安装根归属检查。

通过宿主快照批准后，使用原 Store 事务提交新一代组合锁。完整 enabled 向量与头修订 CAS 在实际写事务中检查；读取/批准期间的停用、升级或新启用使过期图拒绝提交。每次显式调用创建新修订，不把旧回执重放当作重新核验向量：并发同图导致 Store replay 时返回 `plugin_composition_snapshot_superseded`，不以其驱动新激活；并发异图沿用原 CAS 冲突。调用方处理冲突后必须重新读取事实，不自动重试或改写历史图。

这只是元数据发布，既不自动迁移数据库，也不改变选择或提供激活权限；宿主须在自身初始化阶段显式迁移，并用原协调器的准备、setup 后刷新和同步发布栅栏重新授权真实运行实例。文件核验是当次快照，后续激活仍须重新验证，不能当作持续文件证明。缺失必需依赖拒绝创建伪造的部分可执行图，原历史头保持以供审计；其原 Run 的准入依然由当前授权/选择检查限制。

专项采用真实 SQLite 安装账本、实际不可变 ESM 包与原 Node 协调器，覆盖精确节点/边、入口未导入、升级后新旧借用、卸载后空图及历史保留、选择竞争、同图重放、异图 CAS、必需依赖缺失、策略拒绝/取消、文件篡改、跨租户 actor 与非法分页。生产 Native 选择监听、权限适配及用户失败状态仍未接入；不能据此声称正式 App 已自动协调。
