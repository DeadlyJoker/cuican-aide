# 短剧插件加载与项目联动验收

## 用户使用路径

1. 从左侧进入 AI 短剧，点击「新建项目」。右侧提供创意和小说两个入口，中间继续使用 CrewON 的 Agent 对话组件。
2. 输入创意并确认创作需求，或选择小说入口上传原文。确认项目名称和制作参数后，显式创建项目。
3. 保存成功后，左侧切换到该项目，右侧打开项目概览及顶部制作阶段导航。项目目录不暴露到首页的普通工作空间。
4. 进入项目时左侧自动恢复或创建专属会话，中间保留同一会话；在右侧顶部选择阶段，查看和编辑产物，并同步聊天控件的当前阶段，不自动执行。切换标签不丢失其他工作台标签。
5. 项目读取失败时显示错误及「重试读取项目」，不把服务失败表现成空目录，不自动重复创建或重复生成。

## 已定位的原因

- 首页启动入口提前加载工作台及其依赖，样式资源阻塞首屏；认证完成之前还启动了工作台连接。
- 插件浏览器代码未压缩，服务端未压缩 `text/javascript`。插件导入需要等待大文件传输。
- Foundation 创建入口使用普通项目事务，插件目录使用隔离后的项目读取能力，两者空间归属不一致。
- 创建成功只更新了右侧组件的本地项目状态，没有通知宿主更新左右侧栏的项目上下文。
- 候选安装目录解压为公共读取权限，触发宿主的私有目录校验。发布准备必须在验证与注册来源前设置私有目录权限与宿主进程的文件所有者；解压使用 `--no-same-owner`，避免继承构建机器的 UID。保留校验。

## 实施边界

- 启动状态直接渲染在 HTML；认证后才加载工作台。样式失败和异步模块失败有明确的手动恢复入口。
- 浏览器插件代码压缩，Nginx 对 JavaScript 启用 gzip；保持不可变版本和安装摘要校验。
- Foundation 插件入口继承项目服务已有的 `plugin-project-v1` 隔离配置。真实 UI 调用签发内部不透明作用域，复制 JSON 不能获得权限。
- 同一套原有项目、资料、事务和授权能力继续使用。创建项目、创建资料、归属记录和幂等结果在原有同一事务中提交；不新建数据库或绕过登录。
- 普通读取仍拒绝受保护项目；插件读取校验租户、空间、账号、执行主体、配置身份、插件和发布者。
- 原始安装选择、权限和事务终态检查保留。权限在写入后失效时，整个事务回滚；已确认的提交保留其成功结果。

## 验收证据与未完成项

- SQLite 和 PostgreSQL 的创意/小说创建、插件目录读取、Foundation 读取、参数更新、幂等重试、普通目录隐藏和权限失效回滚均已有行为覆盖。
- 候选页面实测在重新进入后约 1 秒可见启动状态；这不是工作台加载完成的耗时。
- 插件 JavaScript 的线上传输量从约 1.89 MB 降到约 222 KB；这不是整个插件打开时间。
- 53 版线上候选已验证真实创意项目创建、隔离目录读取和左右栏联动。受保护项目创建会话仍返回 `plugin_project_workspace_scope_conflict`：原生产会话组合没有配置工作空间分配与原命名空间登记适配器。54 候选复用原 Host 管理实现，实际分配后经原 PostgreSQL 登记；客户端先解析明确目标，不放宽原隔离校验。
- 54 版候选把阶段放到右侧顶部，并通过宿主页面上下文同步原聊天控件；只接受与当前真实会话绑定相同的插件和项目。待确认请求保留原阶段和来源。角色阶段使用人物资产能力，美术阶段使用场景/道具能力，仍由原服务校验授权与依赖。
- 导航和聊天阶段联动已有行为覆盖，且切换阶段不产生执行写请求；右侧实际渲染已在测试数据视图检查。54 尚未安装到线上；真实 Agent 联动仍需 Web 验收。项目进入时只由左侧挂载发起恢复，右侧挂载不抢焦点；初始创建使用项目与工作空间稳定幂等 key，失败保留原请求供手动重连，不自动循环重试。归档项目仅恢复已有有效会话。
- 上游 shuohao Skills 固定到 `dd1adef5c8189b489f6b901e8ab8d7c394c81a3e`，包含六个原始 Skill 及其参考文档（35 份 Markdown）。当前阶段的审阅片段有精确来源与摘要；上游脚本未打包或执行，质量检查状态明确为 `not-run`。
- Agent 实际模型执行、方案保存、媒体生成和视频流程需要单独验收；本轮的项目目录测试不代表这些环节已经可用。

## 54 候选的读取与存储边界

- Desktop 与生产共用原工作空间 registry、allocator、journal 和原子写入实现；Desktop 原入口保留兼容重导出。生产目录持久化、0700、当前 UID、canonical 路径与 inode 校验；观察时再次检查实际登记及目录身份。不会自动删除中断锁或未确认目录。
- 项目会话的共享 composer 通过只读 context 读取当前真实 Thread 绑定、需求版本及已采纳有效的大纲目录。权限错误不退回普通项目接口；旧服务器明确缺少路由时才走兼容逻辑。绑定变化或撤销会拒绝旧结果。
- 此路径使用原 PostgreSQL 与 artifact 服务；未宣称生产项目已经支持通用本地 shell/MCP 的 CWD。
- 已验证真实 Host 分配、原 SQL 会话创建与冷重放；桌面原管理与私有工作空间调用回归通过。线上验收仍须同时验证中央消息、右侧阶段产物以及刷新后的历史与绑定。
