# 隔离桌面连续运行试验

入口为 `apps/crewon-ui/scripts/runtime-soak.ts`，使用 Node.js 24、pnpm 10、仓库已安装的 Electron、Vite 和 esbuild。当前支持 macOS/Linux 进程组清理；Windows 直接拒绝启动，不能冒充已验证的退出行为。

```bash
# 10 分钟单会话基线，不主动注入故障
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/runtime-soak.ts 600 baseline

# 单独的断流试验：每第 17 次生成，在开始流式输出后断开连接
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/runtime-soak.ts 150 recovery

# 真实 MCP 工具：每轮读取隔离文件四次，再核对完成回执
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/runtime-soak.ts 150 tools

# 显式堆诊断：预热 30 轮后与结束时收集 GC 后指标和对象快照
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/runtime-soak.ts 600 tools --renderer-heap

# 独立的 HTTP 桥接原生回归：停读、取消、配额及 Control Client 游标恢复
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/desktop-http-regression.ts

# 显式无损归档已完成诊断的两份快照（传入具体目录的绝对路径）
pnpm --filter @crewon/ui exec node --experimental-strip-types scripts/archive-renderer-heaps.ts /absolute/path/to/.crewon/soak-runs/run-example
```

时长参数允许 30–604800 秒。达到时长只产生 `durationReached`，`acceptance` 仍为 `notEvaluated`，需要检查覆盖范围、资源趋势和正确性证据。提供 24 小时或 7 天参数不等于已完成对应验收。

HTTP 原生回归是独立的小型 fixture，Electron 负载子进程设 30 秒期限，构建/检查和结束回收另计，不执行完整 Agent Run。使用产品 preload/桥接和实际 Control Client，loopback 模拟服务器只提供流及回显端点；独立 profile、最小环境、64 KiB 子进程诊断日志转发上限、64 MiB 既有产物准入门槛，另输出固定结果 JSON，最后记录退出码和专用进程组回收。它与完整 App soak 的覆盖范围分别审计。

## 隔离和负载

- 每次在 `.crewon/soak-runs/run-*` 创建独立 profile、SQLite、产物目录和工作空间。启动使用最小环境变量集及明确的假密钥；不复制用户数据库、`.env`、账号会话或工作目录。构建也禁止读取产品目录的 `.env`。
- 冻结 UI 资源、Electron 主进程/preload 和 Runtime 入口依赖图，并记录大小与 SHA-256。`electron-updater` 的已安装外部依赖仍共享，manifest 明确记录；这不是完全独立的安装包。
- 模型与账号服务均为本次进程内的 loopback 模拟器；账号登录通过实际表单。旧 App Server 地址指向同一个私有模拟器的禁用路径。测试不能评估真实登录服务、真实模型推理、价格或缓存收益。
- 通过真实 React composer 表单提交 `SOAK-N`，单会话、单活动 Run；一轮核对完成后间隔最多 5 秒再提交。普通回复约 4 KiB，每第 10 次约 16 KiB；均低于当前 32 KiB 单次输出预算。尚无多会话并发。
- `tools` 使用 `SOAK-tool-N`，每轮通过实际 Worker、Tool Broker 和 stdio MCP 读取约 3 KiB 的隔离 `fixture.txt` 四次。模拟模型逐步核对工具名、调用 ID、结果绑定及完整文件内容，完成后再检查同一 Run 的四份成功持久化回执和不同执行 ID。模型响应里出现四次工具调用本身不能通过。
- 重复读取是用于覆盖执行、回执和压缩续接的压力负载，不是建议生产 Agent 重复读取同一文件。
- 工具任务中途压缩时，模拟器从收到的历史生成带 HMAC 的紧凑进度摘要；后续调用只依据投影中的摘要及工具结果继续执行，不在内存中保存独立的任务进度表。摘要被改动、绑定其他任务、缺少工具结果或提前完成均失败。这只校验固定读取任务的语义，不证明通用模型摘要完整；HMAC 密钥仅本次模拟器持有，当前不支持重启模拟器后恢复该摘要。
- 每轮须同时出现助手专属 ACK、已持久化的用户/助手消息、同一 Run 的双向绑定，以及 `completed` 终态。用户回显、服务器收到了请求、部分流、错误 Run 的回复均不能算完成。关联读取使用最新 8 条 transcript window，单次读取期限 5 秒。
- 窗口启动后隐藏，记录 Electron 的可见状态和页面 `document.hidden` 两种观测。macOS 试跑中两者并不相同，不能据“窗口已隐藏”宣称浏览器后台节流、系统休眠或恢复已经覆盖。

## 资源与证据

| 文件                                 | 内容与边界                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `manifest.json`                      | 构建指纹、机器条件、请求时长、负载范围和保护阈值                                                  |
| `status.json`                        | 覆盖写入的当前阶段、累计计数及最近一次资源样本                                                    |
| `observations.jsonl`                 | 约每 30 秒记录 UI 探针、Electron 进程工作集、Node RSS/heap/external、事件循环、资源计数和目录大小 |
| `trend.jsonl` / `trend-current.json` | 每 5 分钟聚合的完整区间及当前区间；保留全程起点和区间极值，不轮转                                 |
| `turns.jsonl`                        | 每轮耗时及 Run/消息身份，不复制回复正文                                                           |
| `metrics/process-*.json`             | 各进程每 30 秒原子替换的最近样本；UI 轮询只读缓存，不清空直方图                                   |
| `desktop.log` / `build.log`          | 桌面日志上限 1 MiB、构建诊断保留末尾 16 KiB                                                       |
| `screen.png`                         | 失败时尝试保存的隔离窗口截图                                                                      |
| `cleanup.json`                       | 桌面退出状态及其专用进程组是否确认消失                                                            |
| `lifecycle.json`                     | 最近 64 个窗口/退出及控制端生命周期事件、固定计数；最多 32 KiB，临时文件另计                      |

两种 JSONL 各最多保留两个 8 MiB 分段，单条 128 KiB；发生轮转时较早时间序列已丢弃，必须结合 `rotations` 解释。默认时长与采样频率下通常不会轮转观测文件，但不能假设永久保存全量曲线。模型模拟器最多保留 128 份响应、32 条请求摘要、8 个 WebSocket 客户端、4 个生成中的请求；它的资源也不能无限积累。

上述轮转策略只适用于 `observations` 和 `turns`。新增的 `trend` 单独按 5 分钟区间聚合，每个固定指标仅保存有效样本数、首值、末值、最小值和最大值；缺失仍为 null。最多 32 个指标、2018 个区间，单条 8 KiB，包括当前区间和临时写入在内小于 16 MiB。7 天之外留一个区间供在途任务结束，超过预算会失败，不能静默删除最初区间。没有保留全部历史样本的内存数组，也没有新增采样计时器。

区间按进程单调时钟分桶，同时记录真实时间戳、单调采样间隔及挂钟采样间隔；跳过的区间不补造数据。读取趋势时合并完整区间和当前区间。进程在追加完整区间后、替换当前区间前退出，可能留下同一 index 的相同记录，应按 index 核对去重；冲突或损坏必须显式报告。该记录没有事务或断电落盘保证，不能据文件存在声称崩溃恢复已验收。原始日志轮转后的细节仍会丢失，区间极值保留的是采样峰值，也不能覆盖采样之间的瞬时峰值。

磁盘扫描不跟随符号链接，逐项读取目录；最多 20000 个目录项、协作式 2 秒扫描预算，超限直接失败。大小区分逻辑字节与已分配块，SQLite/WAL 单列。扫描期间产品仍在写入，因此是并发观测，不是事务一致磁盘快照。开始新试验前，既有试验历史超过 1 GiB 时拒绝新增；不会自动删除旧证据。

单次目录超过 8 GiB、可用磁盘不足 5 GiB，或观测到的工作集/RSS 汇总超过 `min(4 GiB, 物理内存 / 4)` 时停止。RSS 汇总包含 Electron 报告的进程、Control/Worker 和测试进程，可能重复计算共享内存，也未覆盖所有短暂后代；不是整机唯一物理页统计。这些是测试保护阈值，不是产品发布验收阈值或硬实时限额；采样之间允许存在峰值和增长。保存最大采样间隔，系统休眠不能当作连续活动运行。

同一 checkout 用 `.crewon/soak-runs/active.json` 排他准入。正常结束释放；如果收到 SIGKILL、宿主退出或进程组清理未确认，保留该文件并拒绝继续。恢复前须核对文件中的 PID、目录及进程树，确认旧试验已经退出；脚本不会猜测所有权并自动清除。SIGTERM/SIGINT 走失败记录与退出流程；构建阶段仍可能等待已启动的构建完成或 120 秒子进程期限。没有自动重启策略，失败不会被重启隐藏。

## 缓存和费用口径

请求摘要只检验单会话输入数组原有前缀、model/instructions/tools 配置以及是否使用 `previous_response_id`。它不检验供应商全部缓存键、TTL、实际账单或服务端内部操作；请求前缀匹配率不是缓存 token 命中率。模拟用量固定为合成值，`syntheticUsage: true`、`realCacheHitRate: null`，不能计算真实节费金额。

## 显式渲染堆诊断

`--renderer-heap` 是单独的诊断选项，只允许 300–3600 秒，必须完成至少 31 轮。默认运行仍不附加调试器或触发 GC；开启后 manifest 标明 `explicitGc: true`、`naturalGcEndurance: false`，其资源曲线不能作为自然 GC 条件下的长期验收。

诊断在第 30 轮已核对持久化完成之后，以及负载结束后，通过 Electron 的进程内 Debugger 接口依次读取 `Runtime.getHeapUsage`、执行 `HeapProfiler.collectGarbage`、再次读取堆和 DOM 计数，最后采集堆快照。当前页面读取 50 条消息，因此先完成 30 轮以覆盖初始窗口填充；首次校准试验的第 10 轮快照不能当作同等工作集的稳定基线。没有开放远程调试端口，也不为业务页面注入 `gc()`；只有隔离入口明确设置诊断开关时才接受这一控制动作。原 `performance.memory` 在一小时试验中约 20 分钟才改变观测值，仍只作为粗粒度指标，不能用于认定保留堆增长。[Electron Debugger](https://www.electronjs.org/docs/latest/api/debugger)、[CDP HeapProfiler](https://chromedevtools.github.io/devtools-protocol/tot/HeapProfiler/)

结果写入 `renderer-heap.json`，包括 GC 前后 JS 堆、可用时的 embedder/backing storage、DOM 文档/节点/监听器计数、诊断耗时及快照大小。两份文件固定为 `renderer-warm.heapsnapshot` 和 `renderer-final.heapsnapshot`，每份最多 64 MiB，单块最多 1 Mi 个字符，直接分块写入专有临时文件，不在 JS 中拼接完整快照。命令共享 10 秒协作式期限；超限、错误或调试器被断开会使试验失败，并清理本次未完成文件与监听器。既有文件和已经附加的调试器不会被覆盖或接管。正常完成也释放调试连接，不保留远程对象句柄。

64 MiB 是写入文件的边界，不能约束 Chromium 在构建快照时的全部临时内存；10 秒计时器也不是可抢占的内核硬期限。外层试验仍负责超时后的专用进程组回收。快照会扰动 GC，可能包含隔离任务正文、合成凭据和文件路径，只保留在本地试验目录；没有采集用户正在使用的 App 或真实账号。没有生产后台定期快照或定期 GC。

历史接近 1 GiB 准入门槛时，可显式运行归档命令；它只接受已达时长、桌面退出码 0、旧进程组已消失且不是活动租约的两快照诊断目录。按流 gzip、解压核对原始 SHA-256 和字节数，并同步 `.gz` 及 `renderer-heap-archive.json` 后才移除原件。单快照及解压上限 64 MiB，共享协作式期限 20 秒，不覆盖冲突文件或归档失败试验，不删除数据库。支持有效归档的重复执行；硬终止可能留下排他锁或临时文件，需要先核对，不能自动假定旧写入者已停止。`run-PYbhS9`、`run-zad6E8` 的原始快照现以 `.heapsnapshot.gz` 保存，四份合计从 178,893,084 缩至 32,834,531 字节，原始字节哈希与分析结果核对一致。

实际统计仍使用产品调用台账和用量表。断流请求没有 usage 时保持未知；重试生成与取回已有响应分别记录，同一响应的用量只计一次。桌面当前默认 `storeResponses: false`，本次没有更改该配置或自动开启远端响应存储。
