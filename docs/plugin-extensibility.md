# CrewON 插件化能力分析与演进建议

状态：目标架构仍是建议方案；2026-09-09 已落地内置任务模板试点，未实施插件安装器或第三方代码执行。首次审查日期：2026-09-08。

## 结论

建议建设“声明式能力包 + 受控执行适配器”，不是让插件直接操作整个 App。优先支持技能、业务模板、设置表单和产物展示；需要外部操作时复用 Tool Broker / MCP / Device 边界。继续使用现有 TypeScript、Node.js 和 pnpm，不新增 Agent 执行引擎，不修改 PIM。

高度可扩展不等于无限权限。真正值得稳定的是能力契约、权限、版本和任务事件；展示样式、业务流程、模型适配可以独立迭代。不要先做一个只有安装按钮、却不能证明任务使用了哪个版本的市场。

## 建议的最小架构

```text
签名/可信来源的能力包
  -> 安装验证（摘要、兼容性、依赖、权限申请）
  -> Control 插件注册与租户/工作空间授权
  -> 发布快照（插件锁文件 + 设置版本 + AgentVersion）
  -> Worker 按快照装配 ToolRuntime / 有界上下文
  -> 既有执行、审批、回执与事件链路
  -> UI 声明式设置 / 任务产物 / 右栏展示
```

安装状态、授权状态、激活版本、运行健康必须分开。`installed` 不意味着 `enabled`，`enabled` 不意味着当前任务能执行；“未知”不能显示为 0 或健康。

### 能力贡献点

1. `skills`：业务方法、输入输出约束、受众范围、上下文预算。默认视为第三方数据，不直接提升为系统或开发者指令；可信业务包须经发布审查后编译进入版本。
2. `workflowTemplates`：生成现有 agent / humanGate / verification 节点。新节点种类属于契约变更，不通过任意脚本偷渡第二套流程引擎。
3. `tools`：声明工具契约、需要的能力、风险级别、超时与恢复语义；实现走现有适配器。安装声明不是授权证据。
4. `settings`：宿主根据 schema 渲染字段，明确生效范围、保存时机、默认值、敏感项和错误；插件不能自行伪造“已保存”。
5. `artifactViews`：按业务 schema / media type 注册只读展示。v0 用宿主卡片、表格、Markdown；以后确有需求再增加隔离的自定义视图。
6. `modelProfiles`：按已验证的模型身份与版本匹配提示词片段、输出约束和预算。选择确定性规则，禁止运行到一半更换整段历史或静默降级模型。

以下只是候选清单示例，不是当前可安装格式：

```json
{
  "schemaVersion": "crewon.plugin-manifest.v0",
  "id": "crewon.meeting-notes",
  "version": "0.1.0",
  "hostApi": "^0.1.0",
  "contributes": {
    "skills": ["meeting-notes"],
    "workflowTemplates": ["review-before-send"],
    "settings": ["output-language", "date-format"],
    "artifactViews": ["crewon.meeting-notes.v1"]
  },
  "requestedCapabilities": [],
  "activation": ["task:meeting-notes", "artifact:crewon.meeting-notes.v1"]
}
```

内容摘要与发布者签名由外层包索引绑定，避免自引用摘要。插件 ID、版本、贡献点 ID 和工具名必须命名空间化；未知 schema、重复 ID、依赖环、越权字段与不兼容版本直接拒绝。声明用 JSON Schema 校验；先复用现有 MCP SDK、schema 工具和成熟 semver 实现，不自制通用插件虚拟机。VS Code 的贡献点和按需激活机制可作为设计参考，而不是引入其整个运行时。[贡献点参考](https://code.visualstudio.com/api/references/contribution-points)、[激活机制](https://code.visualstudio.com/api/references/activation-events)。

### 权限与隔离

- 生效权限是组织策略、工作空间授权、任务授权与插件需求的交集，不是相加；插件升级新增权限必须重新授权。
- 凭据只传引用，由现有受控凭据租约注入目标调用。禁止把企业登录凭据、模型密钥或整个环境变量交给插件。
- 任意 npm 包、子进程或 `node:vm` 都不能被当作安全沙箱。v0 不在 Electron 主进程或 UI 中导入第三方执行代码；需要不可信代码时，先完成真实进程/容器隔离、出口和文件系统限制。
- 自定义网页视图必须隔离，消息使用版本化 schema 和源/实例身份校验；仅提供绑定当前任务的窄能力，不传 App store、原生桥或任意文件路径。
- MCP 的只读、幂等注解只是提示，不能作为授予权限或安全重试的依据；通用写工具缺持久化回执时保持关闭。官方规范也要求不能依据不可信服务器的注解决定工具使用。[MCP ToolAnnotations](https://modelcontextprotocol.io/specification/2025-11-25/schema#toolannotations)。
- 插件失败只影响对应能力；设置超时、并发、输入输出字节、文件数、事件速率和进程资源上限。卸载/禁用不应删掉用户产物；权限紧急撤销必须阻止所有新调用，包括旧任务，再按现有机制取消或核验在途操作。

### 版本、保存和恢复

- 将 `pluginId + version + contentDigest + dependencies + configurationRevision + policySnapshot` 纳入任务物化身份。秘密值不进入摘要材料，只记录凭据绑定身份。
- 设置区分用户界面、工作空间业务、组织策略、单次任务覆盖。界面外观无需 Agent 发布；会改变模型可见上下文或执行能力的设置必须生成新执行快照。
- 更新先 staging 校验和冒烟，再原子激活新版本；新任务用新版本，旧任务保持已锁定实现与 schema。保留仍有任务引用的旧适配器，不能仅留下旧名字并偷偷换实现。
- 回滚只影响后续激活，不自动撤销已发生的外部副作用。迁移需版本化、可重试且不能在回滚时破坏旧版本读取；有不可逆迁移时禁止自动回滚并要求人工决策。
- 继续使用现有 SSE、事件序号和重连游标。新增插件进度事件必须有 schema 与事件兼容测试；事件记录按 tenant / workspace / thread / run 分区，不能从网页文本推导“已经执行”。

## 运行时、harness 与提示词怎么分工

| 放在哪里    | 适合解决                                                    | 不应承担                                       |
| ----------- | ----------------------------------------------------------- | ---------------------------------------------- |
| 运行时/宿主 | 权限、预算、工具选择、取消、去重、错误恢复、版本与产物身份  | 靠提示词说服模型“别越权”                       |
| Harness     | 同场景质量门槛、反例、模型分组比较、流式/重连证据、升级回归 | 用一次成功或只看耗时证明效果更好               |
| 提示词/技能 | 业务语义、例子、输出结构、何时澄清                          | 代替可执行校验、持久化、权限控制或无限追加补丁 |

降低轮次先减少无效上下文、重复工具与缺失的结构化输入，再考虑合并角色。不能把复杂任务硬压成一轮：结果核验和必要的人类审批仍应独立。不同模型采用独立已测 profile，先过正确性门槛再比较轮次、成本、首字延迟；不可见的 PIM 内部轮次保持 unknown。9 月 8 日的设置修复未改 PIM、模型策略或提示词；9 月 9 日仅新增用户主动选择的业务模板，不改变全局 Agent 提示词。

## 分阶段落地及验收

### 第一阶段：一个真实业务包贯穿全链路

选“会议纪要与行动项”：输入现有会议材料，输出结构化纪要、负责人、日期、未确认事项和来源。先只生成草稿，不连接日历发送。

交付最小 manifest/schema、注册与版本锁、宿主设置表单、只读右栏产物、GUI 案例。包的配置只允许语言/日期格式等业务偏好；不开放任意执行代码。需要业务 Artifact 类型时，单独评审公共契约，不能把任意结构藏进未声明的事件字段。

建议新增的模块边界（均为提案）：`packages/plugin-contracts` 管 schema；`packages/application` 管安装/授权/激活用例；`packages/store` 管版本与授权记录；Worker 管受控适配器装配；UI 管贡献点渲染。优先做第一个包所需的最小接口，不预建全套 SDK。

验收至少包括：

- 简单：完整时间、负责人、目标，逐项无遗漏；不创造会议链接。
- 复杂：互相矛盾的日期、未确认负责人、资料链接与入会链接混杂，必须标注冲突与未知；用户修改后不残留旧值。
- 隔离：任务 A 的产物不进入 B，其他租户无权读取，网页材料中的恶意指令不能扩权。
- 生命周期：刷新/重连保留任务；升级不改变旧任务；坏包拒绝激活；回滚后新任务恢复旧版本；禁用后不能再调用。
- 效果：基础正确性必须全过，同模型同场景对比启用前后；记录质量、轮次、失败率、tokens、首字及总耗时，缺失值明确标为未知。至少重复多次，避免把随机波动当优化。

### 第二阶段：接入可复用工具与独立配置

加入一个只读知识库检索插件，通过现有 MCP/工具适配器提供可核验来源；按工作空间授权，按需注册/加载。建立权限 diff、受信来源校验、安装失败恢复、设置迁移和每插件诊断。

### 第三阶段：受控外部写入与丰富展示

只有在 receipt/reconcile、审批及取消恢复通过故障注入后，才加入日历/工单写操作。自定义交互视图、模型适配包、插件市场随后按实际需要扩展；不把这些高风险能力一次性纳入 v0。

## 2026-09-08 已实施范围

只修正设置页：区分 Control 与旧设置来源，真实读取当前模型/策略；将未知设备、工具和隔离状态明确说明；取消当前链路无效控制；补快捷键入口、外观持久化与生效范围提示。插件部分只有本分析，未安装任何第三方插件，未新增插件执行权限。

## 2026-09-09 内置任务模板试点

新增私有包 `@crewon/capability-packs`，先验证“会议纪要与行动项”的最小闭环，而不是把上述完整目标架构宣称为已实现。

| 已实现                                                                 | 明确边界                                                              |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 精确 schema / host 标签、命名空间 ID、数字版本、不可变注册表、内容摘要 | 仅随宿主发布的可信定义；摘要不是签名，内存版本测试不是持久化升级/回滚 |
| 设置页按声明渲染语言、详略选项，显式保存                               | 按本机浏览器来源、账号、包与版本隔离；不是组织策略，也不保存会议材料  |
| 将模板、已保存选项和编号材料准备为新草稿                               | 必须由用户检查并发送；不覆盖已有草稿/附件/执行中任务，不授予权限      |
| 复用现有 Agent 执行、会话保存与右栏只读预览                            | 不是新的结构化业务 Artifact，不伪称已保存文件或已对外发送             |
| 输入字节/行数上限、未知字段与越权声明拒绝、契约及界面测试              | 提示词中的“不调用工具”不是宿主权限撤销；安全仍由已有执行边界保证      |

当前 `crewon.task-pack.v0` 是严格受限的**任务模板**格式，不是上文候选 `crewon.plugin-manifest.v0` 的实现。它不解析 semver 范围、不加载第三方代码，不暴露安装/授权 API，因此没有改变公共 HTTP、事件或业务持久化结构。旧设置与未选择能力包的任务路径保持不变。

实施源码和增加新包的约束见 [capability-packs README](../packages/capability-packs/README.md)。下一步只有在至少两个不同业务包验证贡献点确实可复用后，再决定通用输入表单与结构化 Artifact 契约；组织授权、远程安装和外部写入必须独立评审。不要把模板做成隐式执行引擎。
