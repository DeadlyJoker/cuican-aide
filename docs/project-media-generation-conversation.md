# 原项目对话中的媒体生成

2026-10-07。接续[共享请求恢复](./project-media-generation-http-recovery.md)，将已保存的 T10 / D18 输入接入原项目对话。短剧完整包仍为 Short28；本次增加宿主对话侧入口，没有改写完整包或冻结 SDK。

## 用户流程

只有实际绑定项目、且当前宿主独立开放媒体生成的会话，才显示“生成已保存画面”。入口位于现有项目创作控件内，默认折叠。

1. Agent 的“准备生成输入”阶段或工作台先保存画面描述与采用的参考素材。
2. 用户展开生成区，选择已保存输入。列表每页最多 16 项，支持翻页；选择后读取确切版本，并展示实际保存的描述。
3. “生成画面”使用该版本及当前原会话修订。聊天草稿保留，不把聊天文字静默改作工作流参数。
4. 受理回执交给原 `ControlThreadRuntime.adoptExtensionTask`，沿用原 Run 查询、会话投影、流式订阅与续传。再次生成有独立的明确按钮文案。

准备或恢复展示期间，项目阶段控件不能切换，普通聊天发送会保留草稿并提示等待。这里仍是用户明确执行；尚未把媒体生成串入 Agent 的自动阶段计划。普通聊天、文字阶段和现有 Agent 输入准备路径保留。

## 请求与生命周期

生成前重新读取原会话绑定、媒体恢复记录和实际会话快照。绑定的项目、会话、工作空间、安装来源或修订变化会阻止发送。已保存输入必须是最新输入版本，并匹配当前需求和执行配置；供应商、素材权限及最终版本检查仍由共享后端负责。

控制器保留完整八字段命令。派发失败后，页面只能读取服务端 journal；明确重试继续使用原执行 ID、幂等键、输入及会话修订。读取、挂载、切换主题和恢复已受理回执不会自动 POST。已有受理回执但展示失败时，只重试原任务的读取和接管。当前实例中的未知命令不会因一次空恢复响应被清除。

首次准备失败只有在服务端证明“未调用 TaskCore”后才解锁。取消等待、结果未知、并发及 TaskCore 异常继续遵循上一版恢复限制。其他项目或会话的未决请求会阻止新生成，不能在当前会话重试或展示外来回执。页面关闭、身份或绑定切换会中止本实例的请求并忽略晚到展示；持久恢复仍使用服务端记录。

停止等待不等于取消已经受理的任务；真实任务取消继续使用原会话的任务操作。组件没有创建另一个任务系统或绕过审批。

## 增量 HTTP 接口

原媒体输入运行时新增只读列表：

```text
GET /api/v1/creative-projects/:projectId/media-inputs?limit=16&afterMediaInputId=...
```

省略 `limit` 时为 16，范围 1–16；游标可省略，原输入 ID 按 URL 编码传输。多值、未知字段、空游标和无效数字均拒绝。响应使用既有 `ListMediaInputsResponse`，最大 24 KiB。`ControlApiClient.projectMediaInputs.listInputs` 使用原身份和请求来源，不要求生成许可或 CSRF，不跟随重定向，不自动重试。

列表调用实际 `ProjectMediaInputApplicationService`，保留租户、项目、profile 和读取用途边界。读取不会创建 Run、冻结材料、上传参考图或唤醒执行。新 GET 根路由不改变原保存 POST、带输入 ID 的 GET、UI list action、数据库形状或已有 SDK。

## UI 范围

新控件仅使用既有项目 Composer 插槽、宿主 Button 和主题令牌。局部布局允许换行，并限制展开区及描述预览高度；没有修改全局 CSS、侧栏、账户、设置或工作空间布局，也没有增加全局弹层。主题/语言更新保留选择、草稿和请求状态。

完整插件工作台仍受[插件主题范围](./plugin-variability-boundary.md#ui-主题接入约定)约束。这个宿主对话扩展不授予插件改变全局主题的权限。
