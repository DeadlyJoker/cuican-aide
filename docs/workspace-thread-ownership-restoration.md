# 桌面工作空间与会话归属恢复

2026-10-05 用户发现插件分支重打包后，工作空间与实际会话的绑定回退。历史修复 `0d073c3dc`、`98c51b79f` 位于 `codex/sdd-integration-20260914`，没有合入当前插件分支或 main。仅比较样式与账号文件无法验证这条行为链。

当前恢复提取两次提交的工作空间相关语义，接入现有插件执行链，不整体覆盖含图片与分页改动的大提交。基础约束为：

- `workspaceId` 在创建时固定，分叉继承，发送、重命名、归档和恢复不改变归属。
- 旧事件和记录没有该字段时归一为 null，不按当前活动目录推测。
- v2 私有 registry 保留多个 canonical root，Renderer 仅获取 ID 和显示名称；v1 单目录保留兼容迁移。
- 新增目录与选择已有目录分离，取消不写入，选择不重启 Control / Worker。
- 侧栏按会话实际空间 ID 分组，打开历史会话跟随其持久归属。
- Worker 从可信 Run → Thread → workspaceId 查找目录；模型参数和全局活动目录不授予路径权限。未知归属的文件工具拒绝执行，普通模型对话仍可使用。
- 首次发送使用实际刚创建的会话，详情缓存保留空间 ID，过期刷新不撤销已核验的本机权限。

实际用户文件已在正常退出旧 App 前备份。覆盖为 v1 的目录本来就在更新前完整备份的 v2 registry 中；恢复保留四个原 ID、原目录和当时选择。新 v2 reader 已核验，旧进程物理退场、原文件摘要未变化后，以原子写入提交到实际 profile。现有六个绑定会话全部可找到原空间，不按目录或当前选择推断归属。
