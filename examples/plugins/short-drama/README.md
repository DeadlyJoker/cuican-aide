# AI 短剧插件：工作台与生成执行

将整个目录复制到 CrewON 仓库外开发。公开依赖为 `@crewon/plugin-sdk/ui`、`@crewon/plugin-sdk/node`、`@crewon/plugin-sdk/contracts`、React、ReactDOM 和 lucide-react；浏览器产物包含插件自己的 React 和全部依赖，不借用宿主源码、组件、React 实例或工作区样式表。

保留原 `lucide-react 0.468.0` 图标。React 19 类型移除了其声明引用的 `ReactSVG`，包内仅以无运行时代码的声明补回 SVG 标签名映射；`strict` 与 `skipLibCheck: false` 保持启用，不更换图标或降低类型检查。

包标识为 `crewon.short-drama`，模块标识为 `workbench`，默认版本为 14.0.0。一个安装包同时提供原 `trustedModule/main.content` 工作台、Node 执行入口和业务清单，内部集成 Krea2 概念生图与角色三视图；不需要再安装单独的 Krea2 预设插件。发布者继续为 `example.publisher`。

UI 声明原项目、恢复、生成、查询、选用服务，并新增独立 `crewon.project-texts@1`；Node 声明 `crewon.tasks@2`、`crewon.execution@1` 和独立 `crewon.project-tools@1`。这些服务都是可选依赖，让不同宿主可以单独加载 UI 或 Node。声明不授予能力，UI 调用仍须经过原来源批准、挂载和服务授权；缺少项目或恢复服务时如实显示不可用。Node 缺少任务服务时拒绝动作，缺少执行服务时不注册执行工厂。同一个包内的生成与查询仍各自核验权限。

执行配置只有 `baseUrl` 和 `preset`：地址为 HTTPS 根地址，预设为 `krea2-portrait` 或 `krea2-character-three-view`，没有隐式默认。T01 沿用已确认的 1MP 图；T04 保留原 16 节点及随机种子哨兵 `-1`，不能据此承诺人物跨图一致性或确定性重生成。只有提示词及输出文件前缀可变，构建检查模板 hash、完整节点和连接；任务的配置修订与整图请求摘要保护原任务恢复。已有提交或未知受理只查询原 history/queue，不能重新 POST；不使用供应商全局取消。

旧 Short 11.0.0 与 Krea 1.0.0 的安装、回执和任务绑定保持原版本。新工作台生成映射到自身 `workbench`；旧 Krea 历史按旧身份读取，主动查询仍需原 Krea 目标批准，不会改用 Short12 的配置。原未知请求需要原包恢复。

8.0.0 通过宿主的恢复协议保留生成、查询和选用三类原请求：宿主在模块 ready 前读取恢复提示，写入前先持久 stage 并收到 ACK，再调用原业务动作。重新挂载仅恢复原输入与回执提示，不自动重发；结果未知时须明确重试原请求和原键。恢复仍要求同一 Control 数据库与 realm、实际账号及原包命名空间，并重新核验当前挂载与权限。声明本身不授予能力；当前需要显式组装恢复服务的 Production Host，尚未接入该服务的 Standalone/Native Host 不能启用此版本。旧 5.0.0、6.0.0、7.0.0 不声明该协议，其同进程恢复行为保留。创建会话的准备请求不属于这三类恢复动作。

9.0.0 保留相同恢复协议，仅修正同一输入的原请求重试互锁：可重试的 UNKNOWN 不阻挡用户明确重放另一原请求，实际在途请求、来源冲突和元数据写入仍阻挡；新写操作继续锁定。重试保留原键及全部旧版本字段，不自动发送。8.0.0 的已发布安装目录保持独立。

2026-10-04 已使用实际 SDK tarball 在仓外离线安装、严格编译并自持构建 8.0.0，发布 ESM 67/67 通过。产物位于仓库 `output/extensions/installable-plugins/recovery-ui-short-drama-20261004/short-drama/8.0.0`，实际 Host 校验完整文件，原文件安装器验证安装与重复安装；该安装仅为已清理的隔离文件夹具，没有创建用户 profile 的安装选择。原完整 App 中的此包挂载、实际在线生成/查询及进程重启联合验收仍待完成，不能把 ESM 和文件安装验证扩大为这些结论。

## 仓外构建

使用 Node.js 24、pnpm 10.33.0。SDK 尚未发布到 registry，先由宿主的统一 SDK 分发步骤提供 `crewon-plugin-sdk-0.1.0.tgz`。在复制后的独立项目中，将 `package.json` 的 `dependencies["@crewon/plugin-sdk"]` 写为 `file:/absolute/sdk-output/crewon-plugin-sdk-0.1.0.tgz`，再执行以下命令；不能用示例版本占位值查询私有 SDK 的 registry 包：

```sh
pnpm install --ignore-scripts
pnpm build
pnpm test
```

默认构建生成完整预构建安装目录 `dist/14.0.0/`，并拒绝构建 11 及更早主版本，避免覆盖已冻结的 UI 包。`crewon.plugin.json` 清单包含 UI/Node ESM、业务清单、工作流溯源、演示使用的已有 Krea2 示意 PNG 与依赖许可文件的实际字节数和 SHA256。构建拒绝仓外源码依赖与未打包的浏览器依赖；安装器无需执行脚本。可以设置 `CREWON_EXAMPLE_PLUGIN_VERSION=14.0.0 pnpm build` 构建升级版本，测试时设置相同变量。既有 1.0.0 至 13.0.0 已发布安装包保持冻结。新清单须按实际字节重新核验 packageDigest，并同步宿主批准配置；不能沿用旧版本的 digest。

## 页面与生命周期

默认模式在实际 Host ready 后，通过公开 SDK 读取当前用户的项目，提供创建、归档/恢复、需求保存和版本历史。未就绪不发送动作；服务不可用时明确提示，不用示例项目冒充保存结果。写入使用真实项目 revision 和独立幂等键，保留文本原文；版本冲突保留草稿并要求确认，响应未知只重试同一输入/原键。概念区域支持新建、编辑和读取输入历史：稳定资产 ID、输入修订号与资产元数据版本分别处理，描述只引用已保存的需求；来自旧版需求时须明确确认。列表和历史有界分页，归档禁止新输入，冲突保留草稿并显式刷新，未知响应保留原输入及原键重试。主题更新与取消读取不会丢失草稿。

打开已保存概念修订后，通过独立读取服务恢复该修订的原任务状态、执行记录与经过校验的图片。请求只有项目、资产和输入修订三个定位字段；原 Run、执行插件与调用身份均由 Host 派生。任务取消后，原执行记录中的成功图片仍可展示；图片 `resultIndex` 保留原始结果位置，响应裁剪不重新编号。编辑草稿时隐藏历史生成记录，切换输入、停用和卸载撤回迟到读取。11.0.0 在当前可见的保存输入上自动跟进原任务记录：每次读取结束后等待两秒，最多六十次自动读取、两分钟；错误或十秒读取超时停止，保留手动刷新。后台读取保留已显示的图片，失败后明确清空旧显示。隐藏文档、离开输入、停用或卸载撤回读取与定时器，重见不会延长原观察期限。原 Run 完成且全部已展示操作均为终态、没有截断时才能提前停止；查询回执属于独立 Run，使用有限观察窗口，不冒称查询已完成。自动跟进与“刷新任务记录”均只读取已保存记录，不调用生成、查询、选用或供应商动作。没有生成关联时显示空状态；读取拒绝或服务不可用显示可重试的失败状态。分镜、视频等后续媒体阶段尚未接入。生成入口只对已保存版本开放：先读取原任务记录，确认该版本没有生成关联，再向宿主读取当前准备状态。准备状态是提示，实际提交仍核验身份、两端插件、输入版本和原积分准入。线程由宿主显式准备，模块不自动创建线程，也不声明普通任务服务权限。

提交只传五字段已保存输入引用、原线程及版本、独立幂等键；提示词、执行插件和付款身份均由宿主派生。等待或结果未知时锁定编辑、归档和切源，任意发送后异常都保留原请求；重试只使用宿主明确允许的同一请求和原键。主题或临时上下文失败不会清除未知请求，模块重新挂载可从同会话宿主日志恢复原输入；宿主明确确认已受理的回执不会因后续读取失败或晚到错误回退。读取原记录必须与原回执 Run、线程和配置一致。已占用的输入版本不能再次生成，需保存新修订。宿主明确确认尚未发送时，须显式重新读取输入与准备状态后才能使用新键。同会话日志不等于跨浏览器/登录会话持久恢复，关闭模块只撤回 UI 等待，不能撤销已经提交的原任务。

多个来自不同保存输入的未确认请求不会自动切换当前输入。10.0.0 在模块内列出最多三条原生成、原查询和原选用请求；用户先点击“查看原输入”，只读取已保存来源，再单独点击“重试这条原请求”。每条保留原输入、幂等键和全部旧 CAS，其他未确认请求继续锁定新写操作。实际请求或读取在途时禁止切换和重试；Host 提示变化、撤权或模块未就绪会撤回本次本地选择，重新挂载也须重新明确选择。此交互不授予执行或积分权限，原普通页面与 CSS 不变。

SDK 取消界面等待后，插件仍在本次挂载内跟踪原 Host 写调用，直到其实际完成；最后一条 accepted 提示也不能提前解锁编辑或导航。卸载仅撤回通知，不把此计数当作跨挂载持久协议。跨重挂和重启的恢复、准入仍由真实 Host journal 负责，详见[逐条恢复说明](../../../docs/short-drama-multi-source-recovery.md)。

“查询原任务”只对已读取的原生成执行记录开放。提交只传项目、资产、输入修订三个定位字段、选中的执行 ID、宿主准备的会话及版本与独立幂等键；原 Run、目标执行插件、配置、提示词和身份均由宿主校验派生。查询是独立任务，回执与生成回执分别保留；查询确认后刷新仍恢复原生成记录，不把查询 Run 当作生成 Run。项目改名、增加新输入或归档后，历史修订仍可查询。宿主查询上下文缺失、线程未准备或执行记录读取失败时不提交。

查询等待或结果未知时保留整个原请求并锁定切源与编辑。主题、重新挂载和准备状态恢复只读取原输入，不自动提交；只有点击“重试原查询”才重用同一执行、键和原会话版本。宿主明确确认尚未发送后，须显式恢复原输入才能建立新请求。已受理回执不会被迟到异常或旧投影覆盖；成功后再次点击同一执行记录可使用新的键和当前宿主会话版本。关闭模块仅停止 UI 等待，宿主晚到回执仍可在同会话重新挂载时恢复。模块不自行创建线程，不调用供应商 API，不读取或修改积分。

“设为选用”绑定一张已核验的原结果，提交确切输入、operation ID/修订、原图片索引、当前项目和素材元数据 CAS、独立选用 CAS 及幂等键，不提交 URL、Run 或付款身份。当前图片必须通过独立 GET 读取；旧请求重放回执只证明原选择已确认，不能覆盖或冒充后来选中的图片。当前读取失败显示失败，不伪造空指针或版本 0。输入或需求改变后保留旧图片，并显示服务端的“需重新确认”；历史输入可在当前有效项目中明确选用。

选用等待或回复未知时保留整个请求并锁定新写操作，不因刷新、换主题、重开或新元数据自动换键提交。只有宿主明确允许时，点击“重试原选用”才发送原请求与原键。相同包停用后重新启用，可以在当前真实挂载及权限重新核验后恢复；包、发布者、版本或贡献改变时禁止用新包替代原未知请求。宿主独立账户 journal 与 `projectGenerationSelectionContext` 只提供有界恢复提示，不授权操作或宣称当前选用；当前指针仍由插件通过 SDK 单独读取。7.0.0 的此恢复保留于同一运行中的账户会话，不代表应用进程重启后的持久恢复。选用不创建任务、会话、积分预留或供应商请求。

只有可信预览显式传入 `props.data.shortDramaPreview=true` 才进入原演示模式：示例项目、概念图、模拟提交/查询和服务弹窗继续只改变内存演示状态。PNG 是已有测试样例；演示不调用生图或视频服务，不冻结或扣除积分。

每次挂载创建独立 React 根和局部样式节点，主题更新仅修改该模块拥有的元素与 CSS 变量，保持现有表单和项目状态。样式选择器与原页面一样限定在 `.drama-workbench`；字体、色彩、间距、圆角与阴影沿用宿主原主题。当前 CrewON 宿主通过公开 `theme.tokens` 投影提供原页面使用的全部 32 个变量，包含原 control、spacing、radius、shadow 和 code-font 变量；插件将它们写在本模块自己的节点上。较旧的宿主缺少部分投影时仍继承可信共享 DOM 的原变量。此包仅声明共享 DOM 模式，不承诺独立 WebView 的主题或隔离兼容。

离开页面或停用时撤回迟到响应、卸载 React、关闭仍打开的原生 dialog，并删除本次挂载拥有的节点。重复卸载不会删除后续挂载或宿主其他内容。默认模式重新挂载会从项目服务读取已保存数据，未保存草稿不写入浏览器存储。显式演示模式重开会重置示例数据。插件不读取账号凭据或用户积分，不从页面传入 owner、付款方或执行身份。

`pnpm test` 对实际构建 ESM 运行持久模式和显式演示模式的行为与生命周期检查；新增观察器专项另对当前源码及实际 SDK 运行计时、取消、冷恢复和后台图片更新检查。包内使用公开 happy-dom 与严格 metadata fixture，不能据此宣称生产保存或浏览器原生 dialog 已验证。宿主另有真实安装字节、Host HTTP 与 SQLite 冷恢复集成，验证需求与概念来源冻结、不可变输入历史及稳定资产 ID；该集成的分页通过真实 SDK/HTTP 发送有界游标，发行包 DOM 另测分页控件。元数据公共服务的 PostgreSQL 验证保持独立。正式 Main/full App/packaged 生图与积分验收仍待完成。原工作区、左右栏和账号设置入口属于宿主，插件只修改自己的模块节点。

## 14.0.0 的手动文字工作台

“大纲”和“剧本”页接入与 Agent 项目工具相同的共享成果：编辑结构化正文、保存候选、查看分页历史、打开原版本、明确采用和锁定/解锁。保存候选不自动改变采用版本，锁定后仍可保存探索候选；版本冲突保留草稿，先读取当前状态再决定下一步。页面读取实际当前需求与已采用大纲；旧稿保留原来源与服务端过期提示，明确使用新来源时才保存新的候选。剧本可以引用确切大纲版本，也可以保留 `outline: null` 的手动导入来源。

新 UI 服务为 `crewon.project-texts@1`，通过冻结 SDK 的原 `services.invoke` 传输，十个动作严格限定为 `crewon.project-texts.v1.*`。独立公共入口为 `@crewon/contracts/project-texts-ui`；包内 `src/project-texts-ui-service.ts` 是无 import portable 协议的字节一致副本，`src/project-texts-ui-codec.mjs` 与 `.d.mts` 是公开严格 codec 的预构建文件。`build.mjs` 固定 portable/codec SHA-256；升级时重新核验公开源、生成 codec 和更新摘要，不导入私有宿主实现、不重建 SDK0.1.0。方法、预算与真实挂载/事务资格见[UI 文本协议](../../../docs/plugin-project-texts-ui-protocol.md)。

宿主须显式批准实际模块并启用 `textArtifacts`/`textUi`。四类写入使用真实 UI invocation 的独立 textUi 资格，保留完整主体、包/安装选择、原请求/键和当前项目权限；旧六类项目动作不扩权，也不借 Node 或 Run 身份。新文本请求/响应最多60 KiB，旧动作预算仍24 KiB。手动页面不创建生成任务、积分记录或供应商请求，原概念图片/查询/选用与 Krea 恢复身份保持独立。

结果未知时，本次挂载保留原输入与原幂等键，只由用户明确重试；成功回执后的读取失败不把已保存候选改成未知。冷重开可重新读取已确认候选、采用与锁定历史，显式同键重放由宿主重新核权并返回原回执。当前未确认文本请求和草稿不具备跨应用重启的持久 journal，不能称冷 pending 恢复已完成。

独立发行包全套 **166/166、零跳过**，包括原155项、新8项 DOM 与3项 controller 专项，覆盖来源、草稿、历史、采用/锁定、冲突、未知重试及主题/卸载。仓外依赖冻结 SDK tarball 的严格 UI/Node 编译与构建已通过。四视口实际 Chrome 截图采用明确公共 DTO fixture；真实身份/安装/原 HTTP 与 SQLite/PG 验证由宿主专项单独承担，均不代表用户实际 `.app` 已升级。原宿主导航、账户与左右栏 CSS 未改，新页面只在插件模块内增量扩展。

持久项目对话与绑定、真正的阶段 Agent 启动、冷未完成文本 journal、其他媒体工作流和实际桌面交付仍待继续；13.0.0 的真实 Agent 工具保持可复用，普通聊天仍不因插件 UI 声明而自动获得执行资格。

## 13.0.0 的 Agent 文字阶段（历史）

新增12个真实项目工具，在同一个包内读取/创建需求、保存大纲和分集剧本候选、读取历史、采用及锁定。正文通过确切修订的有界分页读取，保存不自动选用。文字由现有Agent模型创作；宿主复核当前项目权限、真实Run/Tool租约和安装身份，工具参数不接受actor或幂等键。公开单文件协议副本位于 `src/project-tools-service.ts`，独立构建固定其摘要，不依赖私有宿主源码，也不修改SDK0.1.0。

宿主须显式启用 `projectTools` 并提供独立项目权限端口。首期为真实已准入的插件任务Run接通，原普通聊天的能力发现/项目启动入口和工作台文字编辑器仍待接入；当前UI源码保持原12工作台样式。Krea2仍使用原两个模板和原受控I/O，文字阶段不要求先开启媒体网络。新包不会替换旧操作的恢复身份。详见[项目工具协议](../../../docs/plugin-project-tools-protocol.md)。

## 构建思路

参考 [shuohao-skills](https://github.com/eternityspring/shuohao-skills) 与关联的 [Reelbench](https://reelbench.79px.com/)，按大纲、剧本、角色/美术、分镜逐步组织项目成果；Agent 负责阶段编排，ComfyUI 负责明确的媒体任务。14.0.0 已有共享文字工具与手动编辑，媒体仍保留原文本生图与文本角色三视图；参考图派生、分镜、视频、配音及成片导出按实际 API 逐阶段接入。详见[参考与接入顺序](../../../docs/short-drama-workbench-reference.md)。

12.0.0 历史验收（2026-10-05）：实际 SDK tarball 在仓外离线安装、UI/Node 严格类型编译及自持构建成功；152 项插件检查与 52 项宿主审批/身份检查通过。真实文件安装器将最终包写入隔离不可变目录，删除开发副本后以 execution-only 和 tasks2-only Host 分别加载，验证两预设的完整图和未知提交冷恢复只读、不重复 POST。这些端口是明确的内存 I/O 夹具，不代表供应商已生图或用户桌面已升级。产物位于 `output/extensions/installable-plugins/short-drama-unified-20261005/short-drama/12.0.0`。
