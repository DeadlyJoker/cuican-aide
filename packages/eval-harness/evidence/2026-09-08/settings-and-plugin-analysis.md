# 设置页完善与插件化分析验收

日期：2026-09-08。范围：CrewON 设置页及插件架构建议。未修改 PIM，未改变模型策略、团队提示词或工具授权，未安装第三方插件。

## 问题与修复

1. 当前界面使用 Control，但常规、账号、工具、浏览器、设备和安全等设置仍依赖旧 app-server。缺失连接被投影成空清单或默认策略，容易误导用户。现在相关页面由 Control 设置组件负责，旧读取不再触发；常规/连接真实读取激活目录，其余明确当前管理边界，未知不显示为零或健康。
2. 外观修改能改变当时的页面，但多数偏好在无旧服务时不会持久化。新增仅保存 UI 偏好的本地存储，沿用现有序列化和取值约束；保存失败不伪装成功。旧主题在首次修改时迁移，系统主题仍响应系统变化。
3. 字号输入逐字符保存会干扰多位数编辑。改为失焦/Enter 提交，保存后显示规范化值。
4. 助理偏好保存后没有清晰反馈。增加保存成功通知，说明后续助理消息与团队成员职责的区别；长期记忆偏好不代表已有记忆能力。
5. 模型来源登记与实际执行模型混淆，网页只读空态还提示不存在的新增入口。已区分两者，保留来源变更会重启服务、活动任务约束及连接检测不等于业务验收的说明。
6. 补出已有快捷键页面，Control 文案对照实际处理器；支持以“插件/MCP/skill”等词搜索工具与扩展。
7. 已编写的能力说明被旧单行截断样式隐藏。只对新的 authored 面板允许换行、收紧嵌套卡片内边距，保留现有明暗主题。
8. GUI 发现 760px 窗口的固定账号浮层覆盖保存通知。通知关闭按钮中心实际命中“退出”，导致一次误退出。修复为 ≤840px 时通知顶部 52px，避开账号浮层 y=12..42。已重新登录并回归，未更改凭据或账号设置。

## GUI 验收

通过现有浏览器页面 `http://127.0.0.1:5185/` 操作，不以直接 API 提交替代界面测试。目录读取由产品自身触发；自动化只做可见控件操作与只读 DOM 几何检查。

| 模型来源               | 网页只读空态无新增/密钥输入/切换按钮；标题与状态改为模型来源；可跳转当前执行配置                                                              |

| 明暗与布局             | 960×640 下检查浅色工具扩展页、深色安全页；说明完整可见，卡片无横向溢出                                                                        |

## 插件方案与未验证范围

分析见 [插件化能力分析](../../../../docs/plugin-extensibility.md)：建议声明式能力包与受控适配器，复用现有执行引擎，按需贡献技能、业务模板、工具、设置和右栏产物。权限取交集，执行绑定不可变版本；安装、授权、激活、健康分开，升级回滚不能悄悄替换旧任务实现或逆转外部副作用。

第一阶段建议用“会议纪要与行动项”只生成草稿，验证业务正确性、冲突标注、任务隔离和生命周期；随后只读检索，再在审批/回执/恢复通过后开放外部写入。这是建议，不是已实现的插件宿主。

桌面 runtime stage/host build 成功，`pnpm ui:desktop` 已启动 Electron。但 Mac 锁屏，原生 GUI 无法继续；不能把网页通过等同于桌面来源管理、设备权限或操作系统交互通过。本轮未做插件执行、多模型业务效果或新任务 SSE/resume 验收，因为没有实现这些能力或更改执行链路。
