# 任务工作台联动验收 · 2026-09-08

## 范围与问题

只修改 CrewON UI 与现有运行投影的消费方式；本轮没有修改 PIM、模型提示词或执行协议。测试任务、审批与网页打开均从 Web/桌面 GUI 发起，没有通过直接 API 调用提交测试任务。

原右栏仅提供独立的浏览器/文件启动器，无法从当前会话、办公室或协作流进入对应产出。实测还发现：再次提交协作流时，第一次新运行投影到达前，旧运行的 PASS、成稿与取消目标短暂留在新输入下。

## 实现

- 当前任务工作台：普通会话、助理、办公室及协作流可见页面发布当前来源；隐藏页面不能抢占来源。
- 产物：真实会话输出、计划及协作流节点文本的只读预览；正文/节点可一键打开、复制及定位原消息。阶段草稿、未完成内容与核验结论分别标注，不把 PASS 当成通知正文，不创建虚构文件，不显示私有推理。
- 网页：点击会话或预览中的 HTTP(S) 链接打开任务关联标签。Web 使用隔离 iframe，桌面使用已有原生浏览器视图；不自动访问输出中的链接，不共享或重放 Agent 浏览会话。拒绝脚本、文件、携带用户名密码的 URL。
- 浏览记录：消费已有 Web Search、浏览器/MCP 工具记录，只提取已知 URL 字段和状态，不展示任意输入值、Cookie 或参数正文。真实运行事件的进行中、失败、重复回放有离线集成覆盖。
- 隔离与边界：任务关联标签在切换来源时移除，手动工具标签保留；切回旧任务不会自动重开旧网页。新协作流提交立即排除旧 execution 的结果与取消目标。
- 有界预览：最近 24 份产出、每份最多 40,000 字符、64 条浏览记录、16 个任务关联标签。超长文本明确提示返回源消息核对。

## GUI 交互证据

- 审批前：右栏出现提取节点的真实草稿；点击复制显示“已复制”；定位返回 `workflow-node:18965fe3-8fe5-4d12-a7f3-978f81f551b1:node-01`。
- 审批暂停时整页刷新：重新进入协作流后仍为待确认，草稿恢复，可继续审批；不是刷新后自动保持在原房间。
- Web 端预览链接：`https://example.com/` 在右栏 iframe 实际展示 Example Domain，审批 UI 保留在主区。
- 桌面端预览链接：同一公开示例页面在原生浏览器实际展示，不是占位截图。
- 桌面退出办公室：产物标签、关联浏览器标签与原生网页一并消失，右栏产出计数归零；重新进入办公室恢复该办公室 3 份输出，不重开旧网页。
- 深色 Web 与浅色桌面均实看。修复了旧 Markdown 样式导致右栏深色正文黑字的问题；最终正文计算颜色为 `rgb(237, 237, 237)`。
- Web 960×640、全屏工作台均可阅读和滚动；恢复普通视口，并用键盘宽度控件恢复原 480px 右栏。截图见本任务的 GUI 记录。

## 自动检查

- 新增 25 项覆盖：真实文本/状态投影、边界截断、危险 URL、隐藏房间隔离、迟到来源清理、标签去重和上限、新旧执行隔离、Control 事件流及重复回放、浏览器隔离预览和 UI 快照。
- 最终 UI 全量测试：354 个文件、2327 项全部通过；lint（含桌面宿主类型检查）、build、仓库边界、`pnpm format` 与 `git diff --check` 均通过。构建仍有现有大 chunk 提示，未调整阈值掩盖。
- 保留原有行为/视觉断言。抽出的工作台工具渲染模块仍受原浏览器遮挡与交互隔离断言约束，没有弱化架构检查。

## 效果判断与下一步

已经解决“审批前不知道去哪看草稿”“PASS 覆盖成稿的查找成本”“资料链接打开后与任务脱离”“旧运行结果混在新任务下”等具体问题。侧栏是读取真实产出的入口，不是额外让模型重写一次结果；本轮不增加模型轮次。

尚未完成的边界：

1. 浏览器目前是实际工具记录的展示与独立网页预览，不是与 Agent 共享的浏览会话。本轮新业务案例明确不要求 Agent 浏览，故实际浏览工具记录只有离线事件集成覆盖，不能宣称完整远程浏览操作已实测。
2. 不读取专家内部私有分支或推理；文件、图片、下载产物仍使用现有文件能力，并未在本轮统一成结构化 artifact 协议。只读文本预览不等同于文件落盘。
3. 沿用现有运行恢复机制；没有在本轮解决前端协调器刷新/崩溃时的通用持久恢复问题。右栏打开的标签不做跨刷新持久化，源产出可重新打开。
4. 不宣称减少模型轮次或适配不同模型的效果已经改善。三个新场景都通过仍属于小样本；后续应复用同样验收材料做对照。

建议优先建设 CrewON 侧受控浏览会话与产物事件的关联：以明确的 run / source / session 标识连接真实导航、页面状态、文件及可授权的接管动作，再做事件重放与断线恢复测试。不要仅靠提示词要求模型描述“已操作”，也不要为接 UI 联动修改 PIM。
